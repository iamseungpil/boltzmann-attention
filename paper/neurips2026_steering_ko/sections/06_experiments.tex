\section{평가}\label{sec:experiments}

본 절은 두 중심 주장 — 성능(\S\ref{sec:exp:main}, \S\ref{sec:exp:sign}, \S\ref{sec:exp:mechanism})과 효율성(\S\ref{sec:exp:efficiency}) — 을 동일 프로토콜 아래 Qwen2.5-7B-Instruct로 통일해 검증한다. 비교 방법은 \texttt{no\_steer}, 우리 정지 K \texttt{ocq\_bias\_a0.3}, 외부 canonical SEKA, canonical AdaSEKA, Q-회전 두 부호 \texttt{ocq\_qbias\_b$\pm$}, 그리고 레이어 적응형 K+Q \texttt{ocq\_ladapt\_k0.05\_q-0.03}이다.

\paragraph{관찰의 함의.}
표~\ref{tab:main}는 ``$\beta<0$ 하나로 통일''이라는 단순 레시피를 반박한다. 네 도메인 중 하나(Telecom)에서는 정반대 부호가 약 10배 이상 큰 이득을 내므로, 실용적 시스템은 반드시 부호를 \emph{선택}해야 한다. 이 선택을 hyperparameter grid search로 맡기면 배포 비용이 선형으로 증가하고 OOD 도메인에 일반화되지 않는다. 다음 서브섹션이 정리~\ref{thm:beta-star}의 예측기로 이 문제를 푼다.

\subsection{Adaptive Sign Routing}\label{sec:exp:sign}

정리~\ref{thm:beta-star}의 $\operatorname{sign}(\bar r_{\mathcal{G}} - \bar r)$는 baseline forward pass 한 번에서 계산 가능하다. 알고리즘~\ref{alg:asr}이 per-domain(또는 per-query) 부호 결정을 구현한다.

\begin{algorithm}[h]
\caption{Adaptive Sign Routing}\label{alg:asr}
\begin{algorithmic}[1]
\REQUIRE 질의 $q$, 온톨로지 사영 $P_{\mathrm{ont}} = BB^\top$, proxy GT 집합 $\mathcal{G}$, 강도 $|\beta|$
\STATE baseline forward로 $p_0(t) = \mathrm{softmax}(qK^\top/\sqrt d)_t$와 $r_t = \tfrac{1}{\sqrt d}\langle BB^\top q, k_t\rangle$ 계산
\STATE $\bar r \leftarrow \sum_t p_0(t) r_t$,\quad $\bar r_{\mathcal{G}} \leftarrow \frac{1}{\sum_{t\in\mathcal{G}} p_0(t)}\sum_{t\in\mathcal{G}} p_0(t) r_t$
\STATE $\beta \leftarrow |\beta| \cdot \operatorname{sign}(\bar r_{\mathcal{G}} - \bar r)$
\STATE $q' \leftarrow q + \beta q P_{\mathrm{ont}}$로 두 번째 forward pass 실행, 결과 반환
\end{algorithmic}
\end{algorithm}

추가 비용은 $O(Tdr H)$의 내적 연산 한 번으로, 총 추론 시간의 1\% 미만이다. $\mathcal{G}$는 per-domain proxy로 (MetaTool의 경우) 도구 이름 토큰 집합을 쓰고, $\tau^2$에서는 \texttt{evaluation\_criteria.actions}의 도구 이름을 활용한다.

표~\ref{tab:sign-routing} (§\ref{sec:theory})의 부호 예측 결과는 4개 도메인 중 3개에서 완전 일치하고, Airline에서만 mixed signal을 보인다. Airline은 baseline F1 0.329로 Telecom(0.251)과 Retail(0.468) 사이의 경계 구간이며, $\bar r_{\mathcal{G}} - \bar r$의 절댓값이 다른 도메인 대비 작아 예측기 신뢰도가 낮음을 시사한다. Adaptive Sign Routing은 이 경계 구간에서 layered K+Q로 fall back하는 규칙을 둘 수 있다(부록~\ref{app:asr-fallback}).

\subsection{효율성 비교}\label{sec:exp:efficiency}

성능 이득을 얻으려면 얼마의 비용이 드는가? 표~\ref{tab:e-efficiency}가 본 방법을 tool-aware 파인튜닝, 프롬프트 스캐폴딩, KV-cache 최적화, 정지 활성 스티어링과 네 축에서 비교한다. 본 방법은 추론 시 hook으로 작동하여 학습 비용과 토큰 오버헤드가 모두 0이며, 저장은 per-head 기저 $(L, H_{\mathrm{kv}}, d, r)$만 추가한다. Qwen2.5-7B ($L{=}28$, $H_{\mathrm{kv}}{=}8$, $d{=}128$, $r{=}24$) 기준 약 $2.6$ MB. Adaptive Sign Routing은 per-query baseline forward 한 번을 추가하므로 지연이 대략 $2\times$로 늘지만, domain-level routing(도메인별로 한 번만 $\bar r_{\mathcal{G}} - \bar r$ 측정)은 지연 거의 0이다.

성능 측면(\S\ref{sec:exp:main})에서 Telecom에 $+24.78$pp, MetaTool ST4에 $+2.28$pp, Retail에 $+5.11$pp를 파인튜닝 없이 얻는다는 사실과 결합하면, 본 방법은 ``도메인별 부호 한 번 측정 + 저랭크 hook 1개''의 예산으로 부분 파인튜닝에 상응하는 이득을 낸다. 특기할 점은 KV-cache 최적화와 \emph{직교 결합 가능}하다는 점이다 — KIVI 등이 캐시를 압축하는 동안 본 방법은 같은 캐시 위에서 과제 수준의 선택을 개선한다.
