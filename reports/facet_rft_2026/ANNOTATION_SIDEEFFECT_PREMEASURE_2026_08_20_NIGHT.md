# 주석을 한 칸 더 주면 무엇을 파나 — 배포된 유사물로 재는 오프라인 선계량

> 2026-08-20 밤 · 사용자 지시 *"2부터 하라"*(부작용 계량 먼저) · 계기 `x442_annotation_sideeffects.py`
> 산출 `x442_annotation_sideeffects.json` · **유료 런 0 · LLM 0** · fit 호출이 있는 **326 sim** 전수

## 0. 왜 이걸 먼저 하나

C562 가 *"후보별 값을 주면 0.38 → 0.98"* 을 냈다. 그러나 **같은 자리**에서 `present` 는 pass 를 사고
**미조회 날조 5.6% → 10.4% · 조회 2.62 → 0.48** 을 팔았다(C31/C34/C43). 배선 전에 부작용을 재야 하는데
([[70]]·등대 §1.3 Δspurious ≤ 0), 유료 런 없이 재는 길은 하나다 — **이미 배포된 가장 가까운 유사물**.

```
유사물 = check_card_application_fit 의 rate_for('<범주>') 주석(C204/D6)
        → 모델이 **선택적 인자 `spend_category` 를 줄 때만** 붙는다
        ⇒ 같은 코퍼스 안에 주석이 붙은 sim(130) 과 안 붙은 sim(196) 이 공존한다 = 자연실험
```

## 1. 세는 법 (전부 정본 재사용 · 새 술어 0)

| | |
|---|---|
| 날조 | 엔진 `t2_gate_patch._first_fab_call` **그대로**(ctx = user+tool 텍스트만·[[03b]] 새 기준 금지) |
| 조회 | write 가 아닌 도구 호출 수(write 집합 = `t2_forensic.write_tools` = gold 채점표에서 도출) |
| 쓰기 | write 도구 호출 수 |
| 성적 | sim 단위 `reward`([[69]]) |

전부 **fit 호출 이후**만 센다 — 주석은 그 뒤에만 영향을 줄 수 있다.

## 3. 읽기

1. ★**`present` 의 두 손상이 이 유사물에서는 재현되지 않는다.** present 는 조회를 **5.5× 죽였는데**
   (2.62 → 0.48) 여기서는 조회가 **같거나 오히려 높다**(전체 4.50 ↔ 3.89 · 태그 6개 중 5개에서 주석 쪽이
   높다). 날조도 **1.9×** 같은 급증이 없다(0.89 ↔ 0.87 · 태스크별 부호 +2/−1).
   ⇒ 기전이 다르다는 §4 의 예상(present 는 **새 레코드·id 를 주입**하고, 주석은 **이미 있는 수를 가공**한다)과
   정합한다. 다만 이것은 **정합**이지 증명이 아니다.
2. ⚠**pass 는 주석 팔이 낮다** — 전체 0.32 ↔ 0.43, 태스크별 부호 **+0/−2**. 이것을 주석의 해악으로 읽으면
   안 된다: `spend_category` 를 줄지는 **모델이 고르고**, 범주를 말한 손님이 있는 태스크(003·024·055·063)는
   거의 전부 실패 태스크다. **선택 효과와 구분 불가**다.
3. 따라서 이 계량이 **허가하는 것**: *"present-형 손상이 자동으로 따라오지는 않는다"*.
   **허가하지 않는 것**: 안전성·이득. 그건 라이브 `reward` 짝 A/B 만이 준다([[69]]).
