## 0. 요약 (8줄)

ax32p1 실패 11건(005 제외 10건 기전 확정) 중 6건에서 처방이 갱신됐다. **⑴010: write-dedup 가설은
dbdiff가 기각** — env에 이미 idempotence 거부가 있고, DB를 죽인 것은 **여분 give의 GIVEN 등록**(유일
diff 1건). 레버는 give-인용(닫힌 실재성 검사). **⑵012: env가 무득점을 말해주고 있었지만 그 신호는 LLM
산문**이라 산문-매칭은 금지선 — 검색층의 **구조 신호 확보가 선결**. **⑶001: FIT_DIFF의 유저-속성
사각**(신규 변종·flip이라 pass2 재현 대기). **⑷023+019: 보조 계산-도구가 gold와 다른 판정을 명령형으로
지시** — rebate는 과소(미달 오판), discrepancy는 과다(6건 지시 vs gold 4건) = **같은 계열·방향만 반대**
→ 정합 조사로 통합. **⑸018: user-tool을 외부 포털로 오설명 → 사용자 거부 → 미이행**(C212④ 계보의
재발). **⑹C212④·⑤가 둘 다 백로그 사각에서 소실**돼 있었다 — **처방 백로그 원장 신설**(구조 처방).

## 2. 처방 설계

### P1. give-인용 표면화 (010 직격) — `T2_GIVE_QUOTE`

- **관찰**: give = DB-write(GIVEN 등록). 무요청·미사용 give 1건이 db_match를 죽임.
- **닫힘 판정**: "사용자가 이 도구 기능을 요청했는가"의 *의미*는 열림([[22]]) → **강제 금지**.
  그러나 "인용한 사용자 발화가 실재하는가"는 **닫힘**(대화록 내 토큰-연속 부분열 검사·C276 규율·C289 동형).
- **레버(근거-우선 formalize 계약·[[22]] 따름정리 그대로)**: give 호출 선언에 `user_request_quote`
  필드(사용자 발화 축자 인용)를 요구. 엔진 검사는 **실재성만**(quote ∈ user-turns·정규화 토큰-연속) —
  의미 판정 없음. 불성립 시 **표면화+재질의 1회**(deny 아님·fail-open). 인용 실재 시 통과-비용 0.
- **기각 명시(재제안 방지)**: ~~write-dedup 가드~~ — ①env idempotence 실재(응답 축자) ②선차단 시 env의
  "already exist" 신호를 모델이 못 봄 ③편익=턴 1~2. **비채택.**
- **Δspurious**: gold가 give를 기대하는 태스크(015류)에서 give 드롭·재질의 루프 계수. 과차단 0 목표.
- **replay-위생**: 개입은 생성-레벨(선언 검사)·도구 출력 무변형 → 해당 없음. 단 재질의 경로가 스텁을
  만들면 `_dedup_cache_safe` 통과 필수(§6-4).

### P2. KB-무득점 → 이관-후보 표면화 (012) — `T2_KB_NOHIT_SURFACE` (⚠구조 신호 선결)

- **관찰**: env가 무득점을 6회 말했지만 신호가 **LLM 산문**(변이 있음).
- **금지선 준수**: 산문 패턴("does not contain") 매칭 = 자유-NL 프록시 = **열림 → 레버 금지**
  (STACK_PREDICATE_AUDIT·C216 — 산문 프록시 전면 실격의 재적용).
- **선결 조사(무료·구현 전)**: KB_search 파이프라인(bm25 검색→POLICY_QA 응답기)에서 **구조적 무득점
  신호**가 존재하는가 — ⑴검색층 hit 수/스코어 ⑵응답기 반환 구조 필드. **없으면 응답기(우리 소유층)에
  구조 플래그 `no_answer: true` 추가**가 1단계 구현이다(응답기 계약 변경 = 엔진-측·도메인-일반).
- **레버(구조 신호 확보 후)**: 무득점 플래그 **k=2회 연속** + 미해결 상태에서 노트 1회(NOTECAP 예산 내):
  "KB 무득점 k회 — transfer 후보를 검토하라(reason=kb_search_unsuccessful…). **KB 밖 일반 지식으로 절차를
  작성하지 말라**." — 강제 아님·검토 지시만.
- **축1ⓒ 번복 재정**: FAILURE_AXES §2e "비채택(표적 2/24·계측만)"은 ⑴+1 재발 ⑵구조 신호 존재 가능성
  ⑶날조-없는 발현(출처-선언 그물 밖 확인)으로 **재판정 대상**. 채택 여부는 ax32 완주 판정과 함께.
- **Δspurious**: gold가 transfer가 아닌데 무득점인 사례에서 과잉-이관 유발 계수(문구가 "검토"인 이유).
- **replay-위생**: KB_search는 non-mutating(replay 스킵·C149)이라 출력-부착 안전. 채널은 현행 마커
  관행 유지(버스 교체는 별도 게이트).

### P3. FIT diff 유저-속성 행 (001) — `T2_FIT_DIFF` 확장 (조건부: pass2 재현 시)

- **관찰**: FIT_DIFF는 카드-축 diff만 설계(qp32p1 "판별 0" 처방) — 유저-속성 축 사각.
- **닫힘 판정**: "apply 스키마가 요구하는 유저-속성 인자 목록"=도구 스키마(닫힘) · "그 필드의 유저
  레코드 조회 여부"=궤적 관측(닫힘). **값을 대신 읽어주는 것은 금지**(present/autofetch 계보·C31/C34
  제거 — "DB를 대신 읽지 않는다"가 특허 D 차별점이기도 함).
- **레버**: fit-diff 표에 행 추가 — "apply 인자 중 유저-속성: `rho_bank_subscription` … **현재 미조회**"
  (조회 유도 표기만·값 미제공). 필드 목록은 env 도구 스키마에서 런타임 도출(도메인 리터럴 0).
- **조건**: 001은 flip(n=1·qp32p1 통과·발화-변동 31%·C272) — **pass2 재현 확인 후에만 착수**.
- **Δspurious**: diff 표 팽창(노트 부하)·NOTECAP 예산 내.

### P4. 보조 계산-도구 ↔ gold 정합 조사 (023+019 통합·r2 확장) — 조사 항목(레버 아님·무료)

두 도구가 **같은 계열 결함의 양방향**을 보인다: `check_rebate_qualification` = 과소(자격 미달 오판·023) /
`get_reward_discrepancies` = 과다(6건 지시 vs gold 4건·019). 둘 다 **명령형 지시문**을 출력하고
에이전트는 그것을 축자로 따랐다 — 결함이면 **C290 "env 1종" 지시-결함 계열**(에이전트-측 아님).

1. **소유 확인**: 두 도구의 구현 위치(banking_knowledge 도메인 확장부=우리 저작 추정).
2. **재계산 대조**(무료·로컬):
   ⓐ 023 — Yuki(224959b99e) 거래 월별 합계 vs threshold·gold "Diamond QUALIFIES"와 diff·C212 "$94
   undercount [S]"와 동일 결함인지.
   ⓑ 019 — 여분 2건(Delta $287.50·Hilton $356.21·Gold Rewards·Travel)의 **정책 요율 KB 대조**: 도구의
   "correct"가 10×/$ 일괄 계산 흔적 — 진짜 요율이 2.5×면 도구 결함(recorded가 옳음)·요율이 맞으면
   gold-범위 필터(사용자 문의 범위) 문제로 갈림. gold 4건의 카드 종류도 함께 확인.
3. 결함 확정 시: **수정 설계는 별도 문서**(env/채점 인접이라 단독 리뷰) + 그 전까지 두 도구 출력의
   신뢰 표기 강등(포렌식 시 주의 표식). 범위-필터로 판명 시 → 열린 판단(대화 범위)이므로 레버는
   표면화(도구 출력에 "대화 범위와 대조하라" 노트)까지만 검토.

### P5. user-tool 안내 표준문 (018 직격·C212④ 늦은 구현) — A2 문구·표면화만

- **관찰**: 에이전트가 대화-내 user-tool 실행을 "portal/app 제출"로 서술 → 사용자 공포·거부 →
  gold 흐름(사용자 실행 6건) 붕괴. C212④ "regen-본문 괴리(017 '수동 포털' 서사)"와 동일 계보 —
  당시 구현 목록(A1~B3)에 ④ 부재 = **백로그 사각 2호**.
- **닫힘 판정**: "give 직후 안내문에 표준 문구 포함"은 닫힌 개입(문구 주입·의미 판정 없음).
  사용자 거부의 *설득*은 열림 — 하지 않는다. [[21]]: 거부 페르소나는 면책이 아니라 흡수 대상이고,
  흡수 지점은 오설명 제거다.
- **레버**: give 실행 시 엔진이 A2 문구 `user_tool_channel_note`를 안내에 부착: "이 도구는 **지금 이
  대화에서 바로 실행**됩니다(외부 포털·앱 아님). 실행을 원하시면 말씀만 하시면 됩니다." — 표면화만·
  강제 없음·give당 1회(NOTECAP 예산 밖·give 자체에 부착).
- **Δspurious**: 문구 추가로 인한 대화 팽창(미미)·기존 통과 태스크의 give 흐름 회귀 관측.
- **replay-위생**: give는 mutating — **도구 출력 변형 금지**(§6-4·C208②의 원사고 지점). 부착은
  도구 출력이 아니라 **에이전트 안내 생성 직전의 프롬프트-측 노트**(생성-레벨)로만. 구현 시 이 경계
  준수가 리뷰 필수 확인 항목.
