## 0. 왜 클래스가 단위인가

user-sim이 매 런 시나리오를 다시 쓴다. 그래서 **같은 태스크가 런마다 다른 원인으로 분류**되고,
레버가 듣지 않으면 원인이 태스크 사이를 옮겨 다니며 총계만 유지된다(실측: A/B4 구성 11·11 / 11·10 /
10·8 인데 명단은 바뀌고 flip 16/64). ⇒ **레버의 성패는 표적 클래스의 계수 감소로만 잰다.**

## 1. per-step 포렌식이 갈라낸 것

`user 실행·인자 불일치` 11건은 **한 클래스가 아니었다.** 결정 스텝 *이전* 문맥 기준:

| 하위 원인 | sim | 결정 스텝 이전에 정답 값 보유 |
|---|---|---|
| **C1 범주 세탁**(`card_type`) | 6 | **있음 (True)** — 후보표가 이미 손에 |
| **C2 인자 미접지**(dispute `arguments`) | 5 | **없음 (False)** — 값이 아직 안 나옴 |

같은 관찰(손님이 틀린 인자로 실행)이 **정반대 원인**이었다. 클래스별 레버가 필요한 이유가 이것이다.

## 2. ★C1 범주 세탁 — 근본 원인 (024/t0 축자 확인)

### 2b. ★rev2 정정 — C1은 레버 표적이 아니라 경계다 (사용자 반론 2026-08-04)

초판은 이것을 *"스캐폴드가 만든 오정박"* 이라 불렀다. **틀렸다.** 인과를 단계로 끊으면:

| 단계 | 주체 | 옳았나 |
|---|---|---|
| 트럭 = operations 판정 | **모델** | **틀림 ← 원인** |
| 그 범주의 요율 조회 | A2/엔진 | 맞음 — `category_rates:{"operations":2.5}`는 `doc business_gold_rewards_card_*` 축자 전사 |
| argmax 계산 | 엔진 | 맞음(입력이 주어지면) |
| Gold 추천 | 모델 | 잘못된 전제의 충실한 귀결 |

엔진은 **참인 사실을 참되게 보고**했다. 오류를 *만든* 게 아니라 *못 잡은* 것이고, [[13]] 기준으로
못 잡은 것은 결함이 아니다.

**초판 L1은 자신을 정당화한 사례에서 발화하지 않는다.** L1의 검사("범주가 그 카드 qualifying 목록에
축자 존재하는가")는 operations/Gold에서 **통과**한다 — Gold 문서는 실제로 operations를 문서화한다.
⇒ L1 **폐기**.

**여기엔 닫힌 술어가 없다.** 필요한 판정은 *"$40,000 작업 트럭이 공과금·통신 / 클라우드·SW / 배송·물류 /
사무용품·유지보수 / 전문서비스 목록에 속하는가"* — 의미 소속 판정이고 변이 불변이 아니다.
[[22]]대로 **LLM 몫**이며 §1.4의 **F3(semantic operand) = 경계**다.

검토했다가 기각한 대안:
- *"후보 2개 이상이면 비교 수치를 반드시 제시"*(닫힘·발화에서 계수 가능) — **이 건을 못 뒤집는다**:
  잘못된 전제 위에서 비교를 보여줘도 Gold 2.5% > Bronze 1.0%로 여전히 Gold가 이긴다.
- *"원문서 확인 요구를 표면화"* — **이미 하고 있고 무시됐다**(fit note 축자 *"before the final choice,
  verify the cited source docs"*). [[42]] 및 Recuse Signal 2606.06460(비강제 신호는 작업 중 0/40 정지).

### 2c. ★rev3 — 기각 철회: 근거-핀 계약 L1′ (사용자 제안 2026-08-04)

§2b는 *"표면화는 이미 했고 무시됐다"* 를 근거로 이 클래스를 통째로 닫았다. **그 일반화가 과했다.**
무시된 것은 **산문 note**이고, 제안된 것은 **채워야 통과하는 검증 필드**다 — 둘은 다른 물건이다.
같은 구분 위에서 우리가 이미 성공시킨 레버가 있다: **C45 출처 선언 + provenance 검증**
(32B 날조 67→0% · over-block 0 · Δspurious 0). L1′은 그 계열의 재적용이다.

**입증 단위를 내린다.** `spend_category="operations"` 는 뭉뚱그린 주장이라 자기정당화가 싸다.
그런데 요율의 근거 문서(`doc_..._gold_rewards_card_003`)의 qualifying 목록은 **유한 열거**다 —
공과금·통신 / 클라우드·SW 구독 / 배송·우편·물류 / 사무용품·시설 유지보수 / 운영 지원 전문서비스.

**계약**: 범주로 파생 요율을 받으려면 `spend_category`에 **핀**을 함께 낸다 —
`(근거 문서 id, 그 문서에 축자 존재하는 목록 항목)`. 엔진 검증은 셋 다 닫힘:
(a) 핀이 있는가 (b) 인용 span이 그 문서에 **축자** 존재하는가 (c) 그 문서가 그 요율의 출처 문서인가.
미충족이면 `rate_for(X)`를 수치로 내지 않고 `all_purchases_rate`만 낸다.
*"트럭이 그 항목에 속하는가"* 는 **여전히 LLM 몫**이다 ⇒ [[22]] 준수(엔진은 근거만 검증).

⚠**정직한 한계**: 024/t0을 뒤집는다는 보장이 없다. 모델이 *"shipping, postage, and logistics
providers"* 를 집어 자기정당화할 수 있다. **그러므로 주장하지 말고 잰다.**

**선결 = 무료 격리 프로브(§7)**. 프로브가 실패하면 C1은 §2b대로 경계로 되돌린다.

⇒ **12/14 = 결정 시점에 손님 앞에 정답이 없었다.** 보고도 다른 걸 고른 건 **1건**.

`card_type: Business Gold Rewards Card · customer_name: [Your Full Name]`(024). 카드 이름이 **답변이 아니라

`invited` null 7 / **false 18** / true 0 · `business` false 20 / true 9 / null 0 ·
반면 숫자는 모르면 비운다(`credit_score` null 17 · `min_cashback` null 28).

(note에 이미 `[checks] applied / not applied` 기계가 있다),

공표해야 한다.** 엔진 검정 = (마지막 assistant 발화의 카드 이름 집합) ⊇ (fit이 반환한 eligible)
∨ (누락 공표 문구 존재). 발화와 도구 출력만 보므로 완전히 닫혀 있다.

**표적 = 12/14**(마지막 안내 축약 8 + 필터 배제 1 + fit 미호출 3 — 셋 다 *"결정 시점에 정답이
손님 앞에 없었다"* 의 다른 표면). **잔여 = 2**(보고도 다른 선택 1 · 미신청 1)는 레버 밖으로 남긴다.

넘기는 대상이 **사람 상담원**(NEVER 9·말로 바꿈 4·ARG 3)이거나 **손님**(카드 12·user 미실행 7)일 뿐이다.
40건 중 **≈29건**이 이 형태다.

★그리고 이것이 **①이 통행료를 싸게 만들었는데 pass가 안 움직인 이유**를 설명한다 —
이관은 지배적 탈출구이고, 통행료를 낮추면 **더 싸게 탈출한다**. 실측 정합: 이관 호출률 37.5% → **42.2%**.
§1.3 제1원리(레버는 하나를 사면 하나를 판다)의 이번 아크 실증이다.

### L2 — 인자 생산자 선행

### L3 — 노드 완결성 계수

⚠**선택 보조용이 아니다** — 결정론 선택기는 top-3 6~12%로 실패하고, 모델 자신의 검색은 이미 77% 정답
노드에 닿는다. 값은 **분모 제공**에 있다.
**부작용**: 후보 밀도↑ = ADB·[[49]] ⇒ Δspurious 필수.

### L5 — 이관 전제의 접지 (2g에서 파생·신규)

이관이 지배적 탈출구이므로 통행료를 *싸게* 하는 방향(①)은 잔여를 늘린다. 대신 **통행료를 참이면서
검증 가능하게** 만든다(rev4.5 §5 폴백 F1이 이미 지목한 방향):

| 검정 | 술어 | 대상 |
|---|---|---|
| a | 이관 호출 전 **KB_search ≥ 1**(궤적 사실) | 033형 2건(검색 0회 즉시 이관) |
| b | 이관 전 **해금됐으나 미호출인 discoverable 도구 0**(레지스트리 대조) | 032/033/035형 — 일반 이관이 문서화된 도구를 대체한 경우 |
| c | `summary`가 **시도한 것을 인용**(궤적의 실제 호출명 부분열) | ARG 3건(`reason`·`summary` 불일치) |

셋 다 궤적·레지스트리 사실만 본다 ⇒ 닫힘. **무엇을 할지 정하지 않는다 — 하지 않은 것을 했다고
말하며 넘기는 것만 막는다.** ⚠[[06]]: write 강제 금지선 준수(이관을 *막지* 않고 전제만 요구).

### L4 — 미실행 완료-주장 차단
에이전트 발화가 완료를 주장(`has been submitted/filed/...`)하는데 그 도구의 호출이 **궤적에 없으면**
차단하고 사실을 표면화한다(*"이 도구는 아직 호출되지 않았다"*). 궤적 사실만 보므로 완전 결정론.
표적 = `user 미실행` 7 중 거짓주장 4 + `말로 바꿈` 4.
⚠[[06]]: 차단이 **행동을 강제하지 않는다** — 주장만 막는다(write 강제 금지선 준수).

## 4. [[05]] 3질문 ([[17]] 상설 의무)

**Q1. 도메인 어휘가 순증하는가?**
- L1: 아니오. 규칙은 *"미검증 입력으로 계산된 파생값은 수치로 제시하지 않는다"* — 도메인 명사 0.
  카드별 qualifying 목록은 **KB 문서에서 읽는다**(A2 리터럴 아님).
- L2: 아니오(기존 선언 재사용). L4: 아니오(완료-주장 어휘는 영어 시제 패턴·도메인 무관).
- L3: A2에 노드 라벨·변별어가 들어가나 **전량 파일명·코퍼스에서 기계 도출** = env 도출 ⇒ [[23]] opex 0.
  **gold 참조 0**(어느 노드가 정답인지 보지 않고 만든다).

**Q2. 유동 판단을 동결하는가?**
- L1: 아니오 — 범주 판정을 **엔진이 대신하지 않는다**. 판정은 LLM이 하고 엔진은 *축자 존재*만 검증한다.
- L3: 아니오 — 노드 선택은 여전히 모델 몫이고 엔진은 계수만 낸다.
- L4: 아니오 — 무엇을 할지는 모델이 정하고 엔진은 *하지 않은 것을 했다고 말하는 것*만 막는다.

**Q3. 도메인 전이 시 무엇을 다시 써야 하나?**
- L1: A2 0 (qualifying 목록은 KB에서 읽음). 엔진 규칙 그대로.
- L2: 기존 `arg_producers`(도메인당 선언 있음·이미 계상).
- L3: **A2 노드 선언은 도메인마다 재생성** — 단 스크립트가 파일명에서 기계 생성하므로 **저작 0·자동**.
- L4: 0.
