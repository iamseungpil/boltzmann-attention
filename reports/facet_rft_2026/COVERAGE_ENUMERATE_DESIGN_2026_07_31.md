# 022형 coverage 결손 설계 — 열거-후-판단 (2026-07-31)

> 표적 = C270. **긴 목록의 꼬리 한 건을 놓치고 완결을 주장**하는 결손. 두 런에서 출력이 동일한
> **결정론적 재현 실패**라 개입 효과를 잡음 없이 잴 수 있다.

## 1. 무엇이 문제인가 (실측)

- 77-레코드 목록에서 gold 10건 위치 `3·4·10·13·15·22·32·41·45·**52**` → **마지막 것만 누락**.
- 누락 건은 실행한 건과 **카드·범주·배수(5.0×)가 동일** ⇒ 기준이 달라서가 아니다.
- 에이전트는 9건을 *"We have identified the following discrepancies"*로 제시하고 10번째는 **한 번도 언급 안 함**.
- 기존 EPLAN coverage(`discovery_L2`)가 못 잡는 이유: 트리거가 **사용자가 말한 수량 N**인데
  (`n < 2면 침묵`), 이 태스크군의 필요 건수는 **기준에서 파생**된다(사용자는 "다 확인해줘"라고만 한다).

## 2. ❌기각한 설계 — "미언급 목록 되묻기" (정밀도 부족)

가장 먼저 떠오르는 게이트 = *"목록엔 있는데 한 번도 언급 안 한 id"를 열거해 되묻기*. **모집단부터
재보니 만들면 안 된다**(C255 전례 — 처방이 모집단에서 죽는다):

| | |
|---|---|
| 자격 sim(목록서 2건 이상 행동) | **24** |
| 놓친 gold가 미언급에 있는 sim | **4** (022 ×3런 · 026 ×1) = 실질 **2 태스크** |
| 미언급 개수 | 중앙값 **0** · **최대 68** |

⇒ 022에서 **68건을 되묻는** 피드백이 되고, 018·029는 미언급 41건인데 **놓친 gold 0**이라 전량 오탐이다.
표적 2개를 잡으려고 매 런 수십 건의 잡음을 만든다. **기각.**

## 3. ✅설계 — 열거-후-판단 (per-record 값 표)

되묻지 않는다. 대신 **행동 전에 목록 전체에 대해 자기 기준을 균일하게 적용**시킨다.

```
트리거(닫힌 술어): 한 목록에서 파생된 entity로 write를 하려 함 ∧ 그 목록 크기 ≥ K(기본 10)
   ↓
1회 서브콜: "네가 쓰는 기준을 각 레코드에 적용해 값 하나씩 내라 — {id: 값} JSON, 산문 금지"
   ↓
결정론 검사 = **arity만**: 목록의 모든 id가 표에 정확히 1회 등장하는가
   (내용은 검사하지 않는다 — 무엇이 불일치인지는 열린 술어·LLM 몫 [[10]]·[[22]])
   ↓
누락 id가 있으면 그 id들만 짚어 1회 재요청(cap 1) → 이후 통과
```

**왜 이게 §2보다 나은가**: 68건의 *제외 사유*를 캐묻지 않는다. 한 줄짜리 값을 요구할 뿐이고,
그 표를 만드는 순간 **꼬리 누락이 모델 자신에게 보인다**. 오탐 개념이 없다(모든 레코드가 대상).

**비용**: 77행 × ~15토큰 ≈ **1.2k 토큰/발화**, 결정점당 서브콜 1회. `max_tokens` 미설정(C269)이라
프롬프트 창은 충분하다.

## 4. 선결 조건 (무료·미실행)

**모델이 레코드별 값을 실제로 낼 수 있는지 먼저 확인한다** — `x25_criterion_probe.py`(이미 구현).
①기준을 필드명으로 대는가 ②레코드별 파생값을 내는가(우리가 **산술로 재계산해 채점**·gold 불필요).
**②가 실패하면 이 설계는 무효다**(표를 만들어도 값이 틀리면 누락이 안 보인다) — 그때는 F2 계산
자체가 표적이 되고 처방이 `결정론 계산 주입`으로 바뀐다(C266 ④).

## 6. [[05]] 3질문 ([[17]] 상설 의무)

1. **도메인-특화를 순증시키나?** — **아니다.** 트리거는 기존 A2 `eplan.entity_key`(이미 존재)만 쓰고
   새 키 0. 판정은 **id 집합 연산**뿐이라 도메인 어휘가 없다. 기준·값은 전부 모델이 만든다.
2. **유동 판단을 결정론에 동결하나?** — **아니다.** 무엇이 불일치인지, 어떤 값이 옳은지는 **검사하지
   않는다**. 결정론은 *모든 행이 채워졌는가*(arity)만 본다 = [[22]] 닫힌 술어.
3. **모델 대신 도메인 행동을 수행하나?** — **아니다.** 도구를 부르지 않고, 표를 대신 만들지도 않는다.
