## §1 데드락의 정확한 형태 [M]

```
cap = T2_ACTION_DENY_CAP=3 (sim당)
발화 = 모델이 표적을 밀 때(push) 1회 과금
환급 = "요건 큐의 머리가 바뀌면" — 그런데 그 판정이 **발화 블록 안에** 있다
```

101 실측 타임라인: 발화 3회가 **turn 4·6·8에 전부 소진**된다. 그런데 `log_verification`이 성공하는 건
**turn 11 전후**다. 즉 **예산이 바닥날 때까지 첫 요건은 한 번도 충족되지 않았고**, 머리는 계속
`GB1`이었다. 머리가 안 바뀌었으니 환급 0. 예산이 0이니 이후 발화 0. 발화가 0이니 **환급 판정 자체가
다시는 실행되지 않는다.**

> 환급이 발화 안에 있어서, 예산이 바닥나면 환급도 못 받는다. **되돌아올 수 없는 상태다.**

(확인해 둔 것: `_executed_tool_names`는 집합이라 성공이 한 번 들어가면 이후 중복 실패
(`Failed to log verification: Record may already exist.`)로 **취소되지 않는다**. 즉 `failure_markers`가
GB1을 미충족으로 되돌린 것은 아니다. 원인은 위 타이밍 하나다.)

**구조적 진단**: 지금 게이트는 **반응형 거부기**다 — 모델이 밀 때만 깨어나, 한 걸음을 인쇄하고,
예산을 쓰고, 잠든다. 절차를 **끝까지 끌고 가는 주체가 없다.**

## §2 설계 — 프런티어 스케줄러

절차의 주체를 엔진으로 옮긴다. 그래프도 상태도 **이미 있다**; 없는 것은 *루프*다.

### 2.1 이미 있는 자산 (신규 코드 아님)

| 자산 | 위치 | 하는 일 |
|---|---|---|
| `prereq_map(a2)` | `t2_dominance.py:131` | 흩어진 3선언(`satisfier_requires`·`require_tool_before`·`requires_reads`)을 **하나의 그래프**로 |
| `first_step(...)` | `t2_dominance.py:161` | 뿌리까지 전이적으로 내려가 **지금 가능한 한 걸음** (순환 차단 포함) |
| `_executed_tool_names(...)` | `t2_gate_patch.py:2118` | **성공한** 호출 집합(실패 표지 반영) = 그래프의 상태 |
| `requirements_for(...)` | `t2_dominance.py` | 표적을 덮는 **미충족 요건 전부** |
| `t2_compute.apply_op` | `t2_compute.py` | `count_where`·`days_between`·`diff`·`lookup_table` … |

### 2.2 프런티어 (사용자 지시의 형식화)

표적 `T`에 대해, 매 assistant 턴마다:

```
done      = _executed_tool_names(messages)            # 상태
needed    = ancestors(T, prereq_map) \ done           # 아직 남은 조상 전부
frontier  = { n ∈ needed : preds(n) ⊆ done }          # 지금 바로 실행 가능한 노드
```

- `frontier`가 비면 → `T`의 선행이 전부 충족 → **T를 열어 준다**(게이트 해제).
- 비지 않으면 → `frontier`에서 **하나**를 명령한다(명령은 하나, 사실은 합집합 — 기존 C3 유지).
- `done`이 커지면 `frontier`는 **자동으로 다음 층으로 올라간다.** 이것이 지시하신
  *"처음이 만족되면 역순으로 올라오면서 실행"* 이다. 지금은 이 재계산이 **발화할 때만** 일어나고,
  발화는 예산으로 막혀 있다.

### 2.3 예산 폐지 (2026-08-07·사용자 지시 — 구현 완료 `0de1e98c`)

초안은 "진행에는 과금하지 않는다"였다. 사용자 판정은 더 단순하고, **근거는 그쪽에 있다**([[56]]):

> *"예산 없애라. 예산이 주는 이익이 없다."*

- cap의 **해악은 측정됐다**: turn 6 이후 영구 침묵 · 원장 조회 명령 0회 · 실제 조회 2/20.
- cap의 **이익은 측정된 적이 없다**. 거부가 재생성을 유발한다는 것은 *비용*의 관측이지,
  cap이 그 비용을 막았다는 관측이 아니다.
- 실제로 일어난 over-action 사고(023: 게이트 스택 regen 누적 → vLLM 컨텍스트 초과 → sim 무효)를
  막는 층은 **전역 `T2_REGEN_BUDGET`**이지 게이트별 발화 수가 아니다. 상한이 필요하면 거기 둔다.

구현: `T2_ACTION_DENY_CAP` **미설정 = 무제한**(종전 기본 1 폐지). 정수를 주면 종전 거동으로 되돌아온다.
`go_stack.sh`에서 `T2_ACTION_DENY_CAP=3` 제거.

⇒ §1의 되돌아올 수 없는 상태가 **원리적으로 사라진다**(환급이라는 개념 자체가 불필요해진다).
남는 억제는 두 가지뿐이고 둘 다 셈이 아니다: (a) 요건이 충족되면 발화할 것이 없어져 자연히 멈춘다
(b) 전역 regen 상한(현재 미설정).

⚠**측정 의무**: 개입 빈도가 오르므로 Δspurious(gold 밖 호출·거부 후 재시도·컨텍스트 초과 sim 수)를
같이 잰다. 등대 제1원리 — 부작용 없는 레버는 없다.

### 2.4 노드 두 종류 — `read`(모델이 실행) / `compute`(**엔진이 실행**)

지시의 후반부 *"선순위 조건 모두 만족하면 그다음 실행하는 엔진"* 이 여기다.

| 종류 | 선행 충족 시 | 결과 |
|---|---|---|
| `read` | 모델에게 **명령**(도구 호출) | `done`에 추가 |
| `compute` | **엔진이 즉시 계산**하고 결과를 표면화 | `done`에 추가 · 값이 ctx에 들어감 |

`compute` 노드는 모델에게 시키지 않는다. 선행 read가 끝나는 순간 엔진이 스스로 돌린다.
101/102에 필요한 두 노드:

```
referral_window_remaining  = diff(2, count_where(원장, days_between(row.date, today) ≤ 9))
referral_type_remaining(T) = diff(cap(T), count_where(원장, row.referred_account_type == T))
```

둘 다 선행 = `get_referrals_by_user`. 즉 **원장 조회가 성공하는 순간 두 수가 자동으로 나온다.**
지금은 원장 29행이 문맥에 들어와도 아무도 세지 않는다(창_잔여는 19/22에서 미언급).

`cap(T)`의 조달은 §3의 근거-우선 계약을 따른다 — **엔진이 문서를 파싱하지 않는다**([[03b]]).

### 2.5 산문 바인딩 (2단계 · L3)

측정된 사실: 제출 유형은 직전 에이전트 답변에 **101 87/87 · 102 61/63**로 들어 있다.
**산문이 곧 write다.** 그러므로 `compute`가 낸 가용집합은 **답변이 나열할 수 있는 이름의 집합**을
제약해야 한다. 우리 문구는 이미
*"Telling them to run it earlier is the same as doing it early yourself"* 라고 말한다 — 없는 것은
**그 문장을 집행하는 술어**뿐이다.

술어(도메인-일반): *"정책이 유계를 정하는 열거형 값을 답변이 나열할 때, 그 집합이 계산된 가용집합에
포함되는가."* A2는 어느 열거형인지와 어느 compute 노드가 가용집합을 내는지만 선언한다.

⚠**1단계와 분리해서 켠다.** 2026-08-07 규율: 막 확인된 이득 위에 검증 안 된 레버를 둘 이상 얹지 않는다.

## §7 위험·되돌리기

| 위험 | 관측 | 대응 |
|---|---|---|
| **over-action** — 게이트가 매 턴 말해 대화를 밀어낸다 | Δspurious(=gold 밖 도구 호출·거부 후 재시도) | 진행-기반 과금이 상한. 악화 시 플래그 OFF |
| `compute` 결과를 모델이 무시 | 창_잔여 발화율 | 3단계(L3 바인딩)로 넘어간다 |
| 인용 검증이 fail-closed로 굳어 진행이 멈춤 | compute 미실행률 | `[SOURCE]`는 지적만 하고 **막지 않는다**(현행 유지) |

## §8 이 설계가 하지 않는 것

- 102의 **NL 축**을 열지 않는다. Ember 설립일은 db·문서·도구 어디에도 없다(부검 §6). 별도 레버.
- 상한표를 A2에 박지 않는다.
- `gates[]` 선언을 바꾸지 않는다 — 이미 `GB3`가 `submit_referral`을 덮고 있고 매 발화의 `reqs`에
  실려 있다. **문제는 선언이 아니라 루프였다.**
