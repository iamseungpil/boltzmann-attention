## §0. 한 문단

`DECLARATION_FIRST §1c`가 정한 순서는 **①봉투+검증기 배선 → ②프로브로 준수율 확인 → ③구 트리거
OFF → ④라이브 검증**인데, 지금까지 있는 건 **②의 프로브뿐**이다. 이 설계가 ①을 채운다. 어젯밤
세 개의 실측이 배선의 형태를 **좁혔다**: 문법을 도구 호출과 같은 요청에 걸면 **행동이 0**이 되고,
hermes 파서는 **호출 뒤 텍스트를 버리며**, 프롬프트만으로는 행동 턴 봉투가 **32%**에 그치는 반면
**two-pass는 96%**다. 따라서 배선의 기본형은 **선언과 행동의 분리(two-pass)**이고, 선언은 반드시
**호출 앞** 또는 **별도 호출**로 간다. 1차 마일스톤은 **검출 전용**(모순을 재기만 하고 막지 않음)
으로 잡아 Δspurious를 통제한다 — 집행은 별 플래그다.

## §1. 어젯밤 실측이 배선을 어떻게 좁혔나

|---|---|

| 비용: 호출/런 10.5→6.1 · multi-act 45→3 · D는 모델 호출 2배 | **선언을 사면 행동량을 판다** — Y2 판정에 이 상쇄를 반드시 병기 |
| Y1 임계 28%(C249) | arm 간 차이가 **9태스크 미만이면 노이즈** — 검출력 제약을 설계 단계에서 인정 |

## §2. 배선 (4개 단위)

### W-A. 봉투 스키마·가이드 = **A2 base-layer**에서 로드

- A2 키 `declaration = {schema, guide}`(도메인-불변 base-layer·§0c LOCK).
- 엔진은 **읽어서 시스템 프롬프트 말미에 보간**한다. 미선언 도메인이면 **레버 전체 skip**(U2′ 원칙).
- 가이드 문구에는 **"봉투를 호출 앞에 쓸 것"**을 포함한다(C248이 강제하는 조건).

### W-B. 2패스 형식화 (`T2_DECLFIRST=1`)

- 1패스 = 평소대로 도구 제공·문법 없음 → 모델이 행동한다.
- 2패스 = **도구 미제공 + `guided_json`(A2 스키마)** 으로 "방금 그 턴"을 봉투로 형식화.
- 2패스 프롬프트는 **호출 이름 목록을 주고 축자 복사를 요구**한다(X13에서 키 이름을 베끼는
  누출을 겪었다 — C250 ⑥).
- **비커밋**: 2패스 요청·응답은 `state.messages`에 넣지 않는다(C208 replay 위생). 기록은 사이드카.

### W-C. 검증기 (§1d R1~R13 중 **닫힌 것만**)

| 규칙 | 술어 |
|---|---|
| R1 | `ACT` 선언인데 호출 0 |
| R2 | 호출했는데 `ASK/INFORM/DONE` 선언 |
| R4 | `next_action` ∉ 실제 호출 이름 집합 |
| R5 | `done_report`의 주장이 **실제 write에 없다**(거짓 완료 주장) ← **이 배선의 본체 가치** |
| R13 | `ASK`인데 `ask.slot` 없음 |

R5가 핵심이다 — 산문을 파싱하지 않고 **완료 주장을 write 원장과 대조**한다(P2-b 폐기의 대안).

### W-D. 1차 마일스톤 = **검출 전용** (`T2_DECLFIRST_ENFORCE=0`)

- 위반을 **세고 기록만** 한다(사이드카 + 행). deny·regen **없음**.
- 이유: 집행은 Δspurious를 만들고([[19]]·C212 실측), 그러면 Y2에서 "선언-우선의 효과"와
  "개입의 부작용"이 섞인다. **먼저 재고 나서 켠다.**

## §6. 리스크 · 미결

1. **비용이 2배다.** 2패스는 턴마다 추가 호출이다. Y2 GPU 시간이 arm③에서 늘어난다(§5-Z6로 계량).
2. **행동량 감소가 pass를 깎을 수 있다** — X13에서 호출/런이 10.5→6.1이었다. 이건 부작용일 수도,
   과행동 억제라는 순기능일 수도 있다. **Δspurious와 over-action 지표를 함께** 봐야 갈린다.
3. **R4 판정 미확정** — X13의 107건이 내 프롬프트 누출이었고 **D arm 재측정 중**(36런). 그 결과가
   나오기 전에는 "two-pass의 선언 충실도"를 수치로 쓰지 않는다.
4. **검출력** — Y1 임계 28%는 크다. arm③이 pass를 5태스크 올려도 **판정 불가**다. 그래서 §4가
   기전 지표를 1차로 둔다. nt를 3 이상으로 올리면 임계가 내려가지만 비용이 선형으로 는다.
5. **스택 전이 가정** — Y1(임계)은 pre-U 스택, Y2는 post-U + 사이드카 + (선택)살리기 스택이다.
   C249에 기록한 가정이 여기서도 유효하다.
