## 1. ⛔0 — 레버 전에 결손을 격리로 쟀다 ([[62]])

| 물음 | 측정 | 결과 |
|---|---|---|
| 결손이 재현되는가 | x256 `A_LIVE` n=8 | **0/8** (8/8 전부 `Light Blue Account`) |
| 문맥 부하 문제인가 | x256 `E_FREE`(우리 문장 0) | **0/8** ⇒ **아니다.** x241 형이 아니다 |
| **결론만 전달하면 되는가** | x256 `B_VALUE` | **6/8** |
| 호출 형식이 필요한가 | x256 `C_FORM` | **0/8** (+`BADTOP` 3) |
| 값+형식은 | x256 `D_BOTH` | **4/8** — `B_VALUE` 와 **구분 불가**(p=0.608) (+`BADTOP` 4) |

**세 가지가 확정됐다** (v1.4a 리뷰 반영 — 셋째를 **낮췄다**).
1. 결손은 **정보 부재**다 — 문맥 어디에도 `Sky Blue` 가 없다(우리 문장을 다 지워도 0/8).
2. **결론 한 줄이 0/8 → 6/8 을 산다** (Fisher **p=0.0070**). 이것이 이 설계의 유일한 근거다.
3. **형식은 값을 대체하지 못하고, 형식 문구는 인자를 깨뜨린다.**
   - `C_FORM` 0/8 = `A_LIVE` 0/8 ⇒ **p=1.000 · 중립이지 해로움이 아니다.**
   - `D_BOTH` 4/8 ↔ `B_VALUE` 6/8 ⇒ **p=0.608 · n=8 에서 구분 불가.** 열위를 주장하지 않는다.
   - **해로움의 유일한 실측 = `BADTOP`**(최상위 인자를 문자열로 뭉갬): 형식 문구가 있는 두 팔
     **7/16** ↔ 없는 두 팔 **0/16**, **p=0.0068**.
   ⇒ 쓸 수 있는 진술: *실어야 할 것은 값이고, 형식 문구는 중첩 인자 구성을 깨뜨린다.*
   ⚠**철회**: 초판의 *"§1.3(하나를 사면 하나를 판다)을 우리 레버로 실측한 첫 사례"* 는 지금
     근거로 **못 쓴다**. 쓰려면 `D_BOTH`/`B_VALUE` 를 n≥24 로 다시 재야 한다.

⚠**N1 — `B_VALUE` 의 값 출처는 gold 다**(`x256:145` — `value_txt` 가 `gold.get("account_class")`).
  따라서 6/8 은 **상한 측정**이지 라이브 가용 성능이 아니다. §7-4 의 `B_ENGINE`(출시본 *문자열*)
  도 여전히 gold 를 주입하므로 §4.2 의 위험선을 검증하지 못한다. ⇒ 팔 하나를 더 둔다:
  **`B_SUB` = 값이 이 턴 문맥에서 검색 서브가 실제로 낸 것.** `B_SUB ≈ B_VALUE` 가 확인되어야
  6/8 이 진짜 상한이다(C417 의 8/8 은 **격리 문맥**이지 이 턴 문맥이 아니다).

**격리에서 되므로 레버는 전달(부하 축소/재료 배달)뿐이다** — 계산·선택을 대신하면 무효다([[03b]]).

## 2. 무엇이 빠져 있었나 — 컴포넌트가 셋이 아니라 **넷**이다

v1.3 의 3컴포넌트는 **coverage(무엇을 빠뜨렸나)** 축이다. 오늘 드러난 결손은 다른 축이다 —
**decision-carry(정한 값이 실행에 닿는가)**.

```
[CP0 PLAN-SEED]        무엇을 해야 하나        ── v1.3 · 스텁
[DISCOVERY L1/L2]      무엇을 아직 안 봤나      ── v1.3 · 라이브 발화 중(유일 가동분)
[CP2 DECISION-CARRY]   ★정한 값이 실행에 닿나  ── **신설(이 문서)**
[CP5 COVERAGE-WALK]    무엇을 아직 안 했나      ── v1.3 · 스텁
```

CP2 가 없어서 생긴 것이 오늘의 네 칸 중 셋이다. 그리고 같은 부재가 **다섯 전문 에이전트 전부**에
있다(§3).

## 3. 진짜 병 — 전문가는 다섯인데 **배달 계약이 없다**

| 전문가 | 오프라인 | 결론이 메인에 닿는 경로 | 라이브 도달 |
|---|---|---|---|
| 호출형식 (x249·C419) | 32/32 | `_ufb` 문자열 치환 | **3/6** (억제 + **rank 11위** — §3.1) |
| 액션 (x228·C406) | 6/6 | 재생성 문구 | 넘김 발화 **2/6** |
| 진단 (C397) | 100% | 사이드카 | 닿지만 무효 |
| **검색/결정 (C417)** | **8/8** | **경로 없음** | **0/6** |
| 빈인자 (x250·C420) | 8/8 | tool deny | 닿음·재시도 **0/2** |

**전부 맞히고 전부 죽는다.**

### 3.1 ★기전은 임시 배선이 아니라 **배타 체인**이다 (리뷰 B1 · 코드로 확인 · rank 는 C429)

`t2_gate_patch.py:7568-7600` 이 **같은 `tool_call` 객체**에 대해 `elif` 로 **하나만** 내보낸다:

```
do_gate → main_prov → ep_fb → dd_fb → cons_fb → ra_fb → te_fb → wev_fb
        → tr_fb → proc_fb → rw_fb → tl_fb → sig_fb → un_fb → pc_fb → dr_fb → pr_fb
```

**우선순위 = 소스 줄 순서**이고, 그것을 **정한 사람이 없다.**

**확정 rank**(C429·`x257_route_rank_audit.py` 가 코드에서 뽑는다 — 사람이 옮기지 않는다):
총 **17 분기** = `do_gate` 1 · `main_prov` 2 · `elif` 15. 그중 **`wev`(`T2_ARG_EMPTY`) = 8** ·
**`resolve_write`(`T2_CALL_FORM`) = 11** · `prov` = 17.

그리고 추적해 보니 초판이 놓친 것이 있다 — **`T2_CALL_FORM` 이 이 체인 안에 있다**:
`_ufb`(CALL_FORM 이 치환하는 그 문자열) → `rw_fb`(:6806) → **:7594 = 11번째 분기**.
앞에 열이 있고 **그중 `wev_fb` 가 `T2_ARG_EMPTY` 다.**

⇒ **`cf` 런에서 내 두 레버가 서로를 밀어냈다.** 같은 호출에 ARG_EMPTY(또는 WEV/WAG/REF_VERIFY)가
걸린 턴에서는 CALL_FORM 문장이 **통째로 버려진다**. 초판 §3 이 배달 3/6 을 억제(59회) 하나로 돌린
것은 **부분 귀속**이었다 — 원인이 둘이고, 둘째가 더 구조적이다.

⇒ **CP2 는 이 표의 16번째 경쟁자가 된다.** 우선순위 칸 없이 얹으면 오늘의 0/6 이 그대로 재생된다.

교차 증거 셋:
- **x241**: 궤적만 8/8 ↔ 우리 문장 되돌리면 1/8 — 메인은 조각들이 경쟁하는 자리다.
- **[[65]]**: 메인으로 나가던 **여덟 조각 중 답은 하나**. 그중 `ineligible_text` 는 x231 이
  **8/8 → 0/8** 로 해롭다고 이미 잰 문자열인데 기본으로 나가고 있었다.
- **오늘 CALL_FORM 배달 3/6**: 원인 **둘** — `identical demand suppressed` **59회** **와** §3.1 의 배타 체인 11위. unlock 은 상태
  변화인데 억제 지문이 그것을 보지 않아, **하필 무언가 바뀐 그 턴에** 입을 닫는다.

⇒ 이 설계의 절반은 CP2 이고, 나머지 절반은 **라우팅 계약 표**(§5)다.

## 4. CP2 DECISION-CARRY — 명세

### 4.1 무엇을 언제 싣는가

```
트리거   결정점(既存 `_limit_reduce_text`/`T2_DECIDE_ANY` 자리)에서 전문가가 **결론을 냈고**
         그 결론이 **아직 메인 뷰에 없을 때**  (있으면 재발화 0 — [[57]])
내용     결론 **값** 하나. 축(무엇에 대한 결정인지) + 값 + 출처 표지.
         호출 형식·도구 이름·인자 구성은 **넣지 않는다** — 근거는 §1-3 대로 *"형식이 값을
         대체하지 못한다(`C_FORM` 0/8)"* + *"형식 문구가 `BADTOP` 을 만든다(7/16↔0/16·p=0.0068)"*
         이지 `D_BOTH`<`B_VALUE`(p=0.608·구분 불가)가 아니다.
채널     생성-레벨 작업버퍼만. **히스토리 커밋 절대 금지**(v1.3 §2 채널 절대규칙·
         `t2_gate_patch.py:997-1004` — 커밋하면 `set_state` replay 파손 = infra_error).
상한     축당 1회. 값이 바뀌면 재발화(횟수가 아니라 **인자 변화** 기준·[[57]]).
```

문구는 A2 슬롯(`decision_carry.text`)이고 기본형은 x256 이 **실제로 이긴 문자열**을 쓴다
(측정한 문구 = 출시할 문구·[[03b]]). 프로브에 `B_ENGINE` 팔을 두어 등가를 매 개정마다 재확인한다.

### 4.2 값의 출처 — 여기가 유일한 위험선

- ✅ **격리 결정 LLM**(C417 `t2_search.material_for` → 결정 서브)이 고른 값을 **엔진이 나르기만** 한다.
- ⛔ 엔진이 표에서 고르거나 최댓값을 계산하면 **gold 프로그램 재작성**이고 실험 무효다([[62]] ④).
  `account_class` 는 **채점 칸 그 자체**이므로 이 선을 넘는 순간 070/071 실험이 죽는다.

검정으로 강제한다: `test_decision_carry.py` 가 엔진 경로에 정렬·최댓값·`argmax`·`sorted(...)[0]`
류가 없음을 확인하고, 값이 **서브 응답 문자열에서만** 오는지 본다(hook `scaffold_guard` 와 동렬).

### 4.3 왜 "제자리 치환"이 아닌가

후보였다(코드에 선례 있음 — `disamb_mode == "subcall"` *"격리 서브콜 판정 + 제자리 치환"*).
**기각**: ①x256 `B_VALUE` 6/8 이 이미 나오므로 치환 없이 산다 ②치환은 v1.3 §4 절대선

`B_VALUE` 가 라이브에서 안 사는 것이 실측되면 그때 재검토한다.

## 5. 라우팅 계약 표 — 다섯 전문가를 한 규약으로

각 전문가마다 **여섯 칸**을 선언한다(초판은 넷이었다 — 리뷰 2판이 `rank`·`acted` 를 더했다).
지금은 이 표가 없어서 §3 의 절반이 안 닿는다.

| 칸 | 뜻 |
|---|---|
| `when` | 어느 결정점에서 부르는가 (닫힌 술어) |
| `answer` | 서브가 돌려주는 **하나**의 것 (값 · 발화 · 판정) |
| `lands` | 그 답이 놓이는 자리 (생성-뷰 · tool-deny · 어시스턴트 발화) |
| **`rank`** | **같은 `tool_call` 을 두고 경합할 때의 순위** (§3.1 배타 체인) |
| `arrived` | **도달** — 그 답이 그 턴 **모델 입력 메시지**에 실제로 있었는가 |
| **`acted`** | **효과** — 그 답이 놓인 **다음 턴에 모델이 다르게 행동했는가** |

**`rank` (리뷰 B1)**: 지금은 소스 줄 순서가 곧 정책이다. **현행 15행의 rank 를 먼저 명시적으로
적고**(코드에서 기계 추출·`_fbtag` 가 이미 태그를 갖고 있다), CP2 의 자리를 그 표 위에서 정한다.
잠정 제안 = **CP2 를 `rw_fb` 바로 앞**(값이 없으면 그 뒤 문장들이 전부 헛것이므로) — 다만 이것은
[D]이고, `route()`/`audit()` 계기(:7654 에 이미 있다)로 *현행 체인이 실제로 무엇을 말했나* 를
먼저 센 뒤에 정한다.

**`acted` (리뷰 L5·C425)**: `arrived` 만으로는 C425 형 실패가 **성공으로 찍힌다** — `ARG_EMPTY`
deny 는 닿았는데 모델이 끝내 다시 쓰지 않았다. `acted`=0 인 경로는 전부 **[[64]] 로 보낸다**
(*무엇을 하면 풀리는지*를 안 대는 거부이고, C413·C414 가 6/6 실패로 이미 잰 기전이다).

**구현 범위 (리뷰 B2 — 초판을 좁힌다)**: `_emit` 은 **계측만 통일**한다(사이드카 `agent`·`axis`·
`rank`·`arrived`·`acted`). **전달 경로는 둘로 남긴다** — tool-result deny 채널과 생성-뷰 채널은
도달 조건도 replay 성질도 다르다. 초판 §7-1 의 *"기존 5경로 무회귀"* 는 한 함수로 묶으면 지킬 수
없는 약속이었다. ([[65]] 의 `T2_MAIN_ANSWERS_ONLY` 와 같은 함수를 쓰라는 조항은 **계측에만** 적용.)
⚠리뷰 B2 의 전제 하나는 정정한다: CALL_FORM 은 생성-뷰가 아니라 **tool-result 채널**이다
(§3.1 — `_ufb → rw_fb → ToolMessage`). 채널이 둘이라는 결론은 맞지만, 둘로 갈리는 자리는
*CALL_FORM ↔ ARG_EMPTY* 가 아니라 *현행 15경로 전부 ↔ CP2 가 쓰려는 생성-버퍼* 다.

**`arrived` 계산 (리뷰 N3)**: **호출부에서 세지 않는다.** `_emit` 이 불렸는가가 아니라 **그 턴
모델 입력 메시지에 그 문자열이 있었는가**로 센다. `proc_fb` 死배선(:7404)이 정확히 이 실수였고,
그것이 deny 11회를 인쇄로 만들었다([[55]]).

### 5.1 억제 수리 — **보류**. 다음 런의 `lost_to` 로 먼저 가른다 (C429)

`identical demand suppressed` 는 **바이트 동일**만 본다. 초판은 여기에 **진행 상태 해시**를 넣는
것을 §7-2 의 작업으로 잡았다. 재 보니 **판정을 미뤄야 한다**:

- **억제는 실재하는 손실 채널이다**: `CALL_FORM` 이 문장을 지은 턴의 **6~7할**에서 억제가 운다
  (t1 7/10 · t0 6/7 · t5 6/8). `_ufb` 가 만들어진 뒤 `_sig` 일치 → `_ufb=""` → `rw_fb=None`.
- **그러나 unlock 턴에서는 울 수 없다**(x257 6/6 — `unlock` 이 `_executed_tool_names` 에 잡혀
  `len` 6→7 로 지문이 변한다). ⇒ 억제 하나로 배달 3/6 을 설명할 수 없다.
- **축자 연결이 없다**: `trace.turn` 과 사이드카 `turn` 의 기준이 다르고, 한 턴에 재생성이 여러
  번 돌아 억제와 배달이 같은 턴에 함께 찍힌다.

⇒ **지금 고치면 다음 런에서 귀속이 안 된다.** `T2_ROUTE_TRACE`(오늘 배선·기본 ON)가 같은
레코드에 `agent`·`rank`·`arrived`·`lost_to` 를 찍으므로 **다음 런 한 번**이면 *억제 ↔ 체인 ↔
미생성* 셋이 직접 갈린다. 그 결과를 보고 **한 번에** 고친다.

⚠**[[64]] 동반 조건은 그대로 유효**: 억제를 풀면 `_FB_GENERIC`(:7556)이 더 자주 나가고, 그
문자열은 C413·C414 가 **6/6 실패**로 잰 이름 없는 거부다. 억제 수리와 [[64]] 교정은 **한 작업**.

⚠**이 절은 한 번 지웠다가 되살렸다**(C429⒞): 좁은 프로브(x257·unlock 턴 하나)가 *"지문 수리는
값을 못 산다"* 로 닫을 뻔했다. **프로브의 관측 창이 표적의 창과 같은지**를 먼저 봐야 한다.

## 5b. 메인 뷰 계약 — **호출과 결과만** (사용자 지시 2026-08-11)

> **지시 축자**: *"중간과정은 모두 필요없고, 메인뷰에서는 어떤 서브에이전트를 불렀는지와
> 결과만 표시되어야 한다."*

### 5b.1 무엇이 남고 무엇이 사라지나

메인 뷰(`work` = 메인 에이전트 LLM 입력)는 다음만 담는다:

| 남는다 | 왜 |
|---|---|
| 손님 발화 · 어시스턴트 발화 | 대화 자체다. 지우면 답할 수 없다 |
| **무엇을 불렀는가**(도구·서브 이름) | 진행 상태. C411⒟ 가 이것을 자르면 **2/8** 로 떨어짐을 실측 |
| **그 호출이 무엇을 돌려줬는가**(결과 = 서브의 구조화된 답) | 판단 재료 |

| 사라진다 | 왜 |
|---|---|
| 도구 출력 **원문 덩어리**(문서 전문·레코드 목록) | 서브가 읽고 구조화한 것으로 대체 |
| 서브의 **중간 과정**(추론·후보·기각 사유) | 서브 문맥 안에서 끝난다 |

⚠**메시지를 지우지 않는다.** 채팅 API 는 `tool_calls` ↔ 같은 id 의 결과 **쌍**을 요구하고,
tau2 평가기도 같은 보행을 한다(`_paircheck` · `environment.py:334`). 그래서 결과 메시지는
**자리에 두고 content 만 갈아 끼운다** — 지금 `_compact_view` 가 쓰는 그 방식이다.

⚠**커밋 히스토리(`state.messages`)는 원문 그대로.** 평가·replay·**우리 게이트 술어**가 그것을
읽는다. 뷰는 그 순수 함수로 남는다 — 그래야 프로브가 모델 입력을 재구성할 수 있고(오늘 측정
전부가 그 성질 위에 섰다), 누적 버퍼로 바꾸면 그 재구성이 불가능해진다.

### 5b.2 서브의 반환은 **JSON 스키마 고정** (사용자 지시)

자유 텍스트를 받으면 엔진이 검산할 수 없다. 형식이 고정돼야 검증기가 붙는다([[10]]:
생성기=LLM · 선택기·검증기=결정론 / C417 규약: *LLM 형식화 · 엔진은 인용 실재만 검산*).

```json
{ "kept":  [ {"line": "<원문 축자>", "why": "<요청의 어느 부분에 걸리는가>"} ],
  "dropped": 37 }
```

- 엔진은 **`line` 이 원문에 substring 으로 실재하는지만** 본다. 없으면 그 줄을 버리고
  `invented` 로 계수한다 ⇒ **서브가 지어내면 자동으로 걸린다.**
- 엔진은 **`why` 를 읽지 않는다**(도메인 텍스트 해석 금지·[[59]]). 모델에게 그대로 넘어간다.
- ⛔**스키마에 답의 모양을 담지 않는다**: `{"best_account_class": …}` 는 채점 칸 그 자체라
  떠먹이기다([[62]]). 도메인 일반 스키마(`kept`/`why`/`dropped`)만 허용.

### 5b.3 ★근거의 범위 — 무엇이 이 계약을 지지하고 무엇이 **지지하지 않나**

**지지하는 것**
- 배관이 이미 있다: `_compact_view` 가 뷰 전용 교체를 하고 커밋을 안 건드린다.
- 서브는 커밋 통로(`_append`)에 접근할 수 없다 — 구조적으로 replay 를 못 깬다.
- 우리 문장은 이미 한 턴만 산다(`work = list(state.messages)`) — 누적 오염 걱정은 근거 없음.

**지지하지 않는 것 (기록해 둔다·C431)**
- **070_4 를 사지 못한다.** x259 (n=8·같은 궤적·결손 재현 0/8):
  `A_FULL` **0/8** · `B_TRUNC`(기계절단) **0/8** · `C_SUB`(서브 요약) **0/8** · `D_VALUE` **8/8**.
  **뷰의 모양은 아무것도 안 바꿨다.** 오답의 출처가 도구 출력이 아니라 **손님 발화**였다 —
  그 턴 손님 축자가 *"start the application for the **Light Blue Account**"* 이고 gold 는
  `Sky Blue` 다(문서는 `Sky Blue` 를 지지·C417 격리 8/8).
- ⇒ 이 계약은 **효과 주장 없이** 넣는다. 겨누는 결손(서브의 값 왜곡·날조, 원문 덩어리의 잡음)은
  **아직 실측되지 않았다.** 라이브에 켤 때 `invented` 계수와 Δspurious 를 사전 등록한다.

## 8. 사전 등록 · Δspurious (제1원리 · 반드시 성적보다 먼저 읽는다)

**★대조 팔을 같은 런 안에 둔다** (리뷰 L7). 기준선을 nt=1 스냅샷에서 가져오면 분모가 어긋난다 —

같이 돌리고, 게이트는 **칸 통과율**로 쓴다.

| 계기 | 어떻게 잰다 | GO |
|---|---|---|
| **P0 도달** | 결정값 `arrived` (모델 입력 대조·§5) | **≥ 5/6** · CP2 OFF 팔에서 0 |
| **P0b 효과** | 결정값 `acted` (다음 턴 행동 변화) | `arrived` 대비 손실 ≤ 1 |

| P2 성적 | 태스크 pass | **참고만** (nt=4 로도 총점은 약하다) |
| **P3 부정통제** | `B_NULL` 라이브 판본 = 같은 자리·같은 길이·**값 없는** 한 줄 | **P1 을 못 산다**(사면 프로브 무효) |

| P5 부작용 | `BADTOP`(중첩 인자 파손) | **0 유지** (x256: 형식 문구 팔 7/16 ↔ 없는 팔 0/16·p=0.0068) |

⚠**nt≥4.** 3 sim 은 총점을 못 가른다(C403·C406·C408·C415 가 네 번 적었다).
⚠**010 은 이 유료 scope 에서 뺀다** (리뷰 N4): §9 R-a 가 010 을 CP2 밖(`lands`=발화 경로)으로

뒤에 합류시킨다.
⚠**동결 SHA 를 런 태그와 함께 적는다 — 기록만으로는 부족하다**(§7-0·C423⒞). 결과 파일의

에 17커밋·내 런 도중에도 3커밋). ⇒ **판정 조건**: 런 시작 SHA = 종료 SHA ∧ 추적 파일 dirty 0.
어기면 그 런은 **성적을 읽지 않는다**(읽으면 오늘의 실패를 그대로 반복한다).

## 9. 미해결 · 기각 기록

- **R-a 010_1(손님 미실행)은 CP2 가 아니다.** 010 은 넘김 발화 = 손님 실행 = pass 가 4런 내내

- **R-b 별도 프로세스 멀티에이전트 — 지금 기각.** 사는 것: 병렬성(071 은 sim 당 38분)·턴 간
  서브 상태. 파는 것: **replay-safety** — 서브가 무상태 LLM 호출이라 궤적 위에서 재생되고,
  오늘 무료 측정 여섯 건이 전부 그 성질 덕이다. 그리고 **마지막 홉을 없애지 못한다**: tau2 는
  메인 어시스턴트 메시지의 `tool_calls` 만 집행하므로 위상을 바꿔도 전문가의 결론은 메인의 그
  턴에 놓여야 한다 — 실패 넷이 전부 그 자리다. *턴을 가로질러 서브가 상태를 쌓아야 하는 결손*이
  실측되면 그때 간다.

  후에도 그 판정이 유지되는지는 미측정 — CP5 배선 전에 격리로 다시 잰다.
