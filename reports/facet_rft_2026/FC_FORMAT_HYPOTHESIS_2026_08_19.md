## 1. 가설 H 와 우리 실측

### 1-1. 사용자 H (2026-08-19 축자)

> "function-calling 을 학습한 **모든 모델**이 같은 학습데이터 문제를 가질 것이다. 도구 호출을 학습시키려면
> **정량화된 양식의 입력**이 필요했을 것이고, 그래서 산문 대화에서는 텍스트 응답이 나온다."

이 진술은 **세 개의 분리 가능한 주장**을 담고 있다. 섞어서 판정하면 [[03b]] 위반이므로 쪼갠다.

| | 진술 | 논리 형태 |
|---|---|---|
| **H-necessity** | 도구 호출을 가르치려면 정량화된 양식 입력이 **필요했다** | 필요조건 주장 |
| **H-descriptive** | 공개 FC 코퍼스는 실제로 *구조화/명세형 입력 → 도구호출*, *산문 → 텍스트* 로 **편향돼 있다** | 분포 서술 |
| **H-causal** | 그 편향 때문에 **우리 32B 가** 산문 대화에서 텍스트를 낸다 | 인과 귀속 |

**H-universal**("모든 모델")은 H-causal 의 전칭 확장이므로 별도로 세지 않고 §4 E1 에서 검정한다.

## 3. 판정

### 3-A. H-necessity — **기각** [S]

산문 입력(median 228단어)으로 도구 호출을 가르치는 코퍼스가 **실재하고 잘 작동한다**:
`hermes/func_calling` (a)→tool_call **1.000 (n=300)**, ToolACE first 121+단어 **0.935**.
"정량화된 양식이 **필요했다**"는 반례로 죽는다. 살아남는 건 *"실제로는 그렇게 안 한 코퍼스가 많다"* 는 서술뿐이며, 그 원인은 필요성이 아니라 **파이프라인 편의 + 검증기 생존편향 + BFCL Goodhart**(§2-6)다.

### 3-B. H-descriptive — **부분 지지 · 단 축이 바뀐다** [S]

- **형식 축(구조화 vs 산문)으로는 지지되지 않는다.** glaive 계열에서 (b) 구조화 입력의 tool_call 은 **정확히 0.000** (n=31, n=8) — 구조화는 오히려 텍스트를 100% 예측한다(실체 = "엑셀 표 만들어줘" 류 일반 채팅). ToolACE·ToolBench 는 형식과 무관.
- **지지되는 축은 세 개다** [S]:
  ① **인수 축자 노출** 0.63–0.89 — 코퍼스는 *대화에서 인수를 추론해 호출하기*를 거의 안 가르친다.
  ② **위치·직전턴** — 산문 assistant 턴이 2회 이상 쌓인 뒤의 호출은 glaive/hermes 에서 ≈2% 이하, `func_calling` 0%.
  ③ **채널 종결** — 도구 결과 뒤 최종 응답이 text 인 비율 0.88–1.00, `tool_call→결과→tool_call` 연쇄 0.000.
- ⚠ **xLAM 의 "산문 멀티턴 → 호출 0/1000"은 확률이 아니다** — `messages` 필드가 없어 **분모가 0**이다. 조건부확률 0 으로 인쇄하면 안 된다(§2-2 에서 "분모 0"으로 표기했다).

### 3-C. H-causal — **불충분. 상관조차 아직 확립되지 않았다** [S/D]

세 가지가 동시에 막는다:

1. **노출 미확인**: Qwen2.5-32B 의 FC 학습데이터는 **비공개**. 우리가 잰 건 Qwen 의 노출이 아니라 공개 코퍼스 모집단이다 — 생태학적 상관(ecological correlation).
2. **혼합 가중치 미상 (Simpson)**: 코퍼스별로 (a)→tool_call 이 0.070 ↔ 1.000 으로 **부호가 반대**다. 어떤 평균도 의미가 없다.
3. **우리 팔 자체가 교락**: A_min 은 우리가 쓴 요약이라 **정보량·인수 축자율이 다를 수 있다**(우리가 xLAM 을 비판한 바로 그 자). 그리고 A_min↔B_full 대비는 **유의하지 않다**(§1-3).

**현 시점 최대 허용 진술**:
> *"공개 FC 코퍼스 6종에서 위치·인수축자·채널종결 편향을 직접 계수했다[S]. 그 편향이 Qwen2.5-32B 의 팔별 채널 선택을 설명한다는 주장은 아직 상관도 확립되지 않았다 — 노출 미확인·팔 정보량 교락·주 대비 무의미."*

### 3-D. 판정이 §4 설계에 주는 제약

- 형식 축이 아니라 **위치/직전턴/인수축자** 축으로 팔을 다시 짜야 한다 → **E3**.
- 인과는 **노출이 알려진 모델로 옮기거나(E1)**, **코퍼스만 바꾼 동일 튜닝(E6, 유료)** 으로만 산다.
- [[62]] ② 적용: 격리(A_min)에서 되면 레버는 **전달(부하 축소)뿐**이지 결정론기가 아니다. 단 그 전제인 "격리에서 된다"가 0.58 이라 **아직 격리에서도 안 된다** — 결정론기 설계는 **금지**다.

### E2 — base vs instruct (H-causal 의 최종 심판: 사전학습 prior 인가 FC SFT 인가)

가장 강력한 대안 설명: **사전학습 코퍼스에 이미 "명세 뒤엔 코드/JSON, 잡담 뒤엔 잡담"이 있다.** GitHub·API 문서는 시그니처 다음에 호출이 오고, 포럼은 산문 다음에 산문이 온다. 참이면 채널 사전확률은 FC SFT 가 설치한 게 아니고, **데이터 재조성으로 못 고친다**.

**ⓐ 팔**: {Qwen2.5-7B **base**, Qwen2.5-7B-**Instruct**} × {A_min, B_full, B_tail4, C_neg} × {템플릿 적용, 원시 텍스트(양 모델 바이트 동일)}
**ⓑ 표본**: 2 모델 × 4 팔 × 2 조건 × 32 문항 = 512 프롬프트 × 후보 2종 = **2,048 teacher-forced 스코어링**(생성 없음)

**ⓒ 사전 고정 종점**
- **채점으로 재고 생성하지 않는다**(base 는 `<tool_call>` 포맷을 모르므로 생성으로 재면 전 팔 0 = **계기 실패**이지 H 반증이 아니다).
- 두 후보 연속열 — (ㄱ) gold 도구 호출 문자열, (ㄴ) 동등 의미의 텍스트 응답 문자열 — 의 **logP 비교**.
- 종점 = `S = logP(ㄱ) − logP(ㄴ)`. **원값 · 토큰당 정규화값 · PMI 보정값(C_neg 접두사 하 동일 후보 점수를 뺌) 셋 다 보고**.
- 부수: `logP(151657 | 빈 문맥)` 무조건 사전확률을 사전 측정해 보고(base 의 미학습 특수토큰 로짓은 임의값일 수 있음 — base 종점에 특수토큰 단독 사용 금지).

**ⓓ H 가 죽는 조건**
- **F7**: H(=FC SFT 원인) ⇒ `Δ_base ≈ 0`, `Δ_instruct > 0.3`(정규화 단위, 사전 고정). **관측이 `Δ_base ≥ 0.6 · Δ_instruct` 이면 H 의 귀속 사망** — 원인은 사전학습 prior 로 이동.
- **레벨 비교 금지**: instruct = 일반 SFT + RLHF + FC 가 한꺼번에라 레벨차를 FC 에 귀속할 수 없다. **Δ(팔 효과)만** 비교한다.
- 템플릿/원시 두 조건에서 Δ 부호가 다르면 결론은 **템플릿 조건부로만** 진술.

**ⓔ 비용**: 스코어링만 → 7B 1장 · 2,048 forward ≈ 5분 + 로드. **≈ 0.3 GPU-h, 벽시계 30분.** vLLM 아닌 HF transformers(`prompt_logprobs`) 사용. **GPU 1장 필요.**

### E3 — 형식 통제 절편 (내용 고정 · 형식 5종) ★정보량 교락 제거

**이 실험이 H-descriptive→H-causal 다리의 유일한 청소도구다.** 현행 A_min/B_full/B_tail4 는 형식과 **정보량이 함께** 변한다.

**ⓐ 팔 — 2×2 기계적 전치 + 형식 5종**

정보집합 I ∈ {I_min(A_min 이 담은 것), I_full(대화 전문이 담은 것)} 를 고정하고 형식만 바꾼다.
전치는 **결정론 규칙만 사용 · LLM 저작 금지**([[59]]). 전치 전후 **인수 substring 노출률이 동일함을 검증**한 뒤에만 사용.

| 형식 | 렌더 |
|---|---|
| F1 명세형 | 절차문장 + 필드 나열 (= 현행 A_min) |
| F2 대화형 래핑 | 같은 내용을 `User:/Assistant:` 턴으로 **기계적** 분할 |
| F3 원문 대화 | 그대로 (= 현행 B_full) |
| F4 결정론 추출 | 원문 대화에서 규칙으로 필드 추출·나열 |
| F5 꼬리 4메시지 | (= 현행 B_tail4) |

**ⓒ 사전 고정 종점**
- EP1/EP2/EP3 4분류 + 팔별 **인수 축자 노출률**(스칼라/샘플 단위) 동반 보고 — 우리 팔에 우리 자를 댄다(P2).

**ⓓ H 가 죽는 조건**
- **K6**: 효과가 **내용(I_min vs I_full)을 따라가면 H 사망** — 정보량/프롬프트 공학 설명. 형식을 따라가면 H. 대각선이면 상호작용.
- **K7 (도구 수 스윕, 동시 실행)**: |tools| ∈ {1, 5, 50}. **|tools|=1 에서 팔 효과 소멸(Δ ≤ 0.1)이면 H 는 우리 실측에 대해 사망** — 원인은 채널 사전확률이 아니라 **후보 선택 부하**([[45]]).
- **K10 (문형 최소쌍)**: 마지막 문장 서법만 명령/의문/평서로 교체, 나머지 **바이트 동일**. 여기서 전 효과가 재현되면 원인은 형식이 아니라 **문형 프라이밍**이다.

### E4 — role/템플릿 절편 (같은 내용을 system/user/tool 역할에)

**근거 (템플릿 축자 조사 완료)** [S]: Qwen2.5 템플릿은 `role=="tool"` 을 **`<|im_start|>user`** 로 렌더한다.
```jinja
{%- elif message.role == "tool" %}
    {%- if (loop.index0 == 0) or (messages[loop.index0 - 1].role != "tool") %}
        {{- '<|im_start|>user' }}
    {{- '\n<tool_response>\n' }}
```
⇒ **Qwen 토큰열에 `tool` 역할은 존재하지 않는다.** R2(user)와 R3(tool)의 차이는 `<tool_response>…</tool_response>` **래퍼 문자열 하나뿐**이다 — 완벽한 최소쌍.

**ⓐ 팔**: 동일 payload P 를 4 위치 × 형식 2종 = 8셀
- R1 system(도구 블록 뒤) · R2 user 마지막 턴(= 현행 A_min) · R3 `role:"tool"` · R4 assistant 선행턴 + 최소 user `"Proceed."`
- 교차 모델: Hermes-3 `tool_use`(**진짜 `<|im_start|>tool` 역할 존재** ⇒ R3 가 실제 role 조작이 됨) · Mistral-7B-v0.3(system 채널 없음·도구가 항상 마지막 user 직전 = 거리 0) · Llama-3.3(`tools_in_user_message` 플래그를 템플릿이 노출 ⇒ **도구목록 위치만 바꾸는 순수 조작** — 단일 모델 내 거리 실험으로 최고)

**ⓑ 표본**: 8셀 × 32 문항 × 8 디코드 = 2,048 (Qwen) + 교차모델 3종 × 4셀 × 256 = 3,072 → **총 5,120 생성**

**ⓒ 사전 고정 종점**: 셀별 EP1. 주 대비 = **R3 − R2**(래퍼 단독 효과) · **R4 − R2**(미학습 슬롯 효과) · Llama `tools_in_user_message` on/off(거리 단독 효과).

**ⓓ H 가 죽는 조건**
- **K8**: `R3 − R2 ≤ 0.05` 이면 **"템플릿 구조" 다리 사망** — H 의 잔여는 순수 내용/register 축으로 축소.
- Llama 거리 조작에서 Δ ≥ R3−R2 이면 원인은 형식이 아니라 **도구목록 거리**다(단, Qwen 은 도구가 system 맨 앞 고정이라 B_tail4 가 거리 최단인데 최악 — 거리 가설과 **부호가 반대** [S]).
- R4(assistant 선행 + "Proceed.")는 템플릿상 **학습된 적 없는 슬롯**이다. 예측 = 최저. R4 가 R2 와 같으면 "미학습 슬롯" 서사 사망.

### E5 — 로짓 프로브 (도구-개시 토큰 logprob 격차) ★가장 싸고 가장 민감

**근거** [S]: Qwen2.5 에서 `<tool_call>` = **단일 토큰 151657**, `special=False`, 생성 프롬프트는 `<|im_start|>assistant\n`(토큰 `…151644, 77091, 198`)로 끝난다.
⇒ **채널 결정은 문자 그대로 첫 번째 생성 토큰 하나다.** 사용자가 말한 "사전확률"을 문자 그대로 측정한다. 생성 불필요 · 샘플링 잡음 0 · 이산 통과율보다 훨씬 민감.

**ⓐ 팔**: E3 의 전 셀(정보집합 2 × 형식 5 + C_neg 3) × 32 문항. 생성 없이 `max_tokens=1, logprobs=20`.
**ⓑ 표본**: 13 셀 × 32 문항 = **416 forward** (결정론적이므로 반복 불필요)

**ⓒ 사전 고정 종점**
- **EP4a** = `logP(151657)` at pos 0
- **EP4b** = `logP(151657) − logsumexp(경쟁 상위 채널개시 토큰)`
- **경쟁 질량 분해**: 151657 을 이기는 토큰이 (i) "Sure/네/물론" 류 **예의 prior** 인가 (ii) 도메인 단어 = **응답 prior** 인가 (iii) `{`/```` ```json ```` = **포맷 미스** 인가. 이 3분해가 처방을 가른다.

**ⓓ H 가 죽는 조건 / 계기 조건**
- **래칫**: EP4b 의 팔 순위가 E3 의 EP1 순위와 **불일치하면 계기 불신** → [[55]] 0단계 복귀(어느 쪽 결과도 인용 금지).
- EP4b 가 팔 간에 **flat(범위 ≤ 0.5 nat)한데 EP1 은 크게 갈리면**, 채널은 첫 토큰이 아니라 **후속 디코딩에서 결정**된다 ⇒ "첫 토큰 사전확률" 프레임 사망.
- 경쟁 질량이 (i) 예의 prior 지배면 원인은 FC 코퍼스가 아니라 **RLHF chat prior** → H 약화.
- ⚠ 선행 겹침: `2605.09252`(hidden-state 선형 프로브 AUROC 0.89–0.96, Probe&Prefill 로 호출 48% 감소)와 **계기가 겹친다 — 인용 의무**.

**ⓔ 비용**: **8141 에 이미 떠 있는 32B 재사용 · 추가 GPU 0 · 벽시계 ~10분 · 416 요청.** 사실상 무료.

## 6. 우리 델타 (선행 대비)

선행은 *부를지 말지의 결손*을 **단일턴 고립 프롬프트**에서 쟀고(`2605.09252` — hidden-state 프로브 AUROC 0.89–0.96 인데 생성이 못 옮김, 축자 조건 *"tasks are presented as isolated single-turn prompts"* · `2605.18882` SAE 과호출 편향 · `2607.10059` AgentAbstain act 80.6% ↔ abstain 59.1%), *형식이 출력 모드를 무너뜨린다*를 **도구 없는 label 채널**에서 쟀으며(`2605.04665` — 축자 **"~78% of closed-form variant responses contain no answer-set token at all"**), *코퍼스가 편향돼 있다*를 **다양성 엔트로피 축으로만** 쟀다(`2607.29250` Data Turnstile — xLAM Structure 0.85 / Glaive 0.62, irrelevance 35.7%→77.5%; **인수 축자율도, 정답이 text 인 샘플 비율도, 형식×채널 교차표도 보고하지 않는다**). 극성도 대체로 반대다 — 선행 다수가 **과호출 억제**를 다루고 우리는 산문 문맥에서의 **미호출**을 잰다. 가장 근접한 *문장*은 ToolFlow(`2410.18447`)의 축자 *"Much of the existing research focuses solely on generating single-turn tool-calling instructions, neglecting the coherence between dialogue turns… This creates a gap between Q&A-type training data and its practical application."* 인데, 그건 데이터 생성법의 **동기 문단이고 측정이 0건**이다. **아무도 "동일 질문·동일 도구목록을 유지한 채 전달 형식만 바꿔 tool_call/text 채널 확률이 어디까지 흔들리는지"를 측정하고, 그 기울기를 학습 코퍼스의 형식×채널 교차표(인수 축자율 0.63–0.89 · 산문 2턴 선행 호출 ≈0–2% · 도구결과 뒤 텍스트 마감 0.88–1.00 · `tool_call→결과→tool_call` 연쇄 0.000)에 대조해 귀속하지 않았다** — 이 대조 한 칸이 우리 자리다. 부수로 하나 더 있다: BFCL 의 "부르지 않기" 축은 **도구-불일치 하나뿐**이고 채점은 **파싱 실패 = 정답**이며 대화형 `chatable` 은 리더보드에서 제외된다 ⇒ **학습 코퍼스가 만든 위치 사전확률이 리더보드 밖에 있다.** 이건 [[46]] 의 "결손이 리더보드 밖에 있다" 각도를 데이터 층에서 재확인한다.
