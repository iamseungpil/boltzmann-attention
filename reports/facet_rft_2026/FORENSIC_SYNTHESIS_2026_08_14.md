## §2 기전 — 태스크별 (증거 = sim·메시지 번호)

### A. 우리 층이 **완료된 write 를 되감아 중복 실행**시킨다 — 073 t0 ★신규
`task_073#s626729`(t7285_b): msg 57 에서 gold 3건을 정확히 실행했다 —
`chk_..._1 $9.50` · `_2 $9.00` · `_3 $1.50`, 결과 전부 *"Credit applied successfully"*(58~60).
그 직후 우리 층이 **완료 요약 초안을 폐기**하고 `[DISCOVERY-REQUIRED] … (1) KB_search_bm25 …`
를 주입했고(사이드카 turn 61·67), 모델은 시킨 대로 검색→unlock→**같은 3건을 재실행**했다.
잔액이 `5200 → 5209.50 → 5219.00 → 5228.50` 로 올라간다. gold 인자와 **동일한 성공 호출이 4회**
(msg 57·61·67·73) — 그래서 채점은 3칸 전부 불일치.

기전 위치: `t2_resolve.py:resolve_action_operator` 의 가드가 **턴-국소**다.
```
called = 이번 assistant 메시지의 도구들
if called & action_tools: ok        # ← 과거 턴의 실행은 안 본다
if not _agent_ending(am, ...): ok   # 순수 텍스트 = '회피'로 판정
```
완료 후 손님에게 결과를 말하는 턴은 `도구 0` 이라 **회피로 오판**된다. `transfer` 만
`_transfer_executed(msgs, …)` 로 이력을 보는 예외를 갖고 있다 — 같은 이력-감응이 일반 action 에는 없다.
⇒ **[[64]] 의 거울상**: 이유를 지우는 게 아니라 *이미 이룬 상태를 되감는* 결함. 처방은 새 레버가
아니라 **가드 추가(빼기·[[63]])**.

### B. `account_id` 를 못 얻어 무너진다 — 087 · 085 · 055 · 069 (+081 일부) ★최대 조각
공통 궤적: 신원 검증 통과 → 카드/거래 도구가 **checking account_id** 를 요구 →
`get_all_user_accounts_by_user_id_3847` 를 **부르지 않고** 대체값을 넣는다.
- 087 msg22: `account_id = "mt35a7c9d2"`(= user_id) → env `Account 'mt35a7c9d2' not found`
- 055 msg36: `account_id = "blue_account_jordan_williams"`(**지어낸 슬러그**) → not found
  · msg42 재시도도 user_id → not found → msg44~48 `shell grep` 배회
- 069 msg22~32: 계좌 조회 대신 `shell grep 'Light Blue'` 4연속 → 이관
- 085: 같은 배회가 길어져 **context_window_exceeded**
우리 층은 `[WRITE-GROUNDING] 'YOUR_CHECKING_ACCOUNT_ID' 는 어떤 도구 출력에도 없다`(087 msg28·36)로
**틀렸다는 사실은 정확히** 말하지만, *"계좌 목록 도구를 불러 id 를 얻어라"* 를 **안 말한다** —
[[64]](거부는 고칠 방법을 담아라)의 실패 사례.
