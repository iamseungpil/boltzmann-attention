## 0. 요약 (7줄)

멀티턴의 **무거운 것**(자료 읽기·operand 산출·검증)을 **호출마다 리셋되는 좁은 계약의 기능 에이전트**로
빼고, 멀티턴의 **연속성**(사용자 의도·대화 상태)은 **대화 에이전트 하나**에 남긴다. 둘 사이는 LLM 라우터가
아니라 **결정론 orchestrator**(엔진 + A2 선언 라우팅)가 중개한다 — [[10]]/[[52]] 분담의 명시적 승격이다.
우리는 이미 절반 가 있다: SG_ISOLATE(=formalize 에이전트·라이브 321발화)·wrap(=reader 에이전트)이 그
원형이고, 실측 이득도 이 가족에서 반복 확인됐다(§1). rev2가 더하는 것은 ⑴에이전트·계약의 **1급 명세화**
⑵orchestrator 서비스(버스·거버너·상태 슬라이스 제공)의 일원화 ⑶E-PLAN 컨트롤러의 orchestrator 승격이다.
불변식 둘이 전부를 지배한다: **밖에서는 한 에이전트**(에이전트 간 통신은 공식 히스토리 밖 = replay 위생)
· **라우팅은 닫힌 선언**(A2·열린 라우터 금지). 본체는 에이전트 목록이 아니라 **계약 명세**(§2c)다.

## 2. 설계

### 2a. 에이전트 유형 (5 + 결정론 2)

| 에이전트 | 성격 | 계약 한 줄 | 현 원형 → rev2 |
|---|---|---|---|
| **대화**(dialogue) | LLM·**유일한 user-대면·유일한 히스토리 기록자** | 대화 연속성·행동 방출 | 메인 LLM → 불변 |
| **reader** | LLM·호출마다 리셋 | 질의+getter 결과 소비 → **답 + 무편집 원문 인용** | wrap (W) → 상설화(`KB_search` 포함·이번 수정) |
| **formalize** | LLM·호출마다 리셋 | 문서·행 슬라이스 → **선언된 스키마의 operand만** | SG_ISOLATE → 불변·계약 명세화 |
| **verifier** | **결정론**(LLM 아님) | operand·인용의 닫힌 검사(grounding·핀·범위·멤버십) | 엔진 가드들 → 불변 |
| **plan 컨트롤러** | **결정론** | coverage/사슬 원장·gap 산출·drive 신호 | E-PLAN → **orchestrator 승격**([[14]] 합류) |
| (선택) **judge 서브** | LLM·리셋 | 단일 이지선다/판정 질의([[18]] 프로브형) | 격리 프로브들 → 필요 시 |
| **orchestrator** | **결정론** | 라우팅(A2 선언)·상태 슬라이스 공급·버스/거버너 서비스 | 엔진 실행 루프 → 명시화 |

**빠진 것이 의도**: LLM 라우터·LLM 플래너·에이전트 간 자유 대화. 전부 열린 술어를 아키텍처에
심는 것이라 기각(§2f).

### 2b. 데이터 흐름 (한 장)

```

              ▼
     [orchestrator·결정론] ── A2 선언 라우팅 ──► 실행: env 도구 그대로
              │                                   │
              │ (라우팅 대상이면, 히스토리 밖에서)   │
              ├──► [reader]    : getter 실행·소비 → 답+인용 ─┐
              ├──► [formalize] : 슬라이스 주입 → operand ────┼─► [verifier·결정론]
              └──► [plan 컨트롤러]: 원장 갱신 → gap/drive ───┘        │
              ◄──────────── 반환·노트(표면화 버스 경유·예산 하) ◄──────┘

      대화 에이전트에게는 "도구 반환"의 형태로만 보인다 (밖에서는 한 에이전트)
```

### 2c. ★계약 명세 형식 — 이 설계서의 본체

모든 기능 에이전트는 A2에 다음 **6필드 계약**으로 선언된다(형식은 도메인-일반·내용은 도메인 A2):

1. **input_slice** — orchestrator가 공급하는 입력의 **닫힌 선택자**: 문서(제목-접두)·행(row_fields)·
   원장 슬라이스(ledger/user 발화·기존 `corpus` 선택자 재사용). *"전 대화"는 선택자가 아니다* —
   그걸 원하면 대화 에이전트의 일이다.
2. **return_schema** — 반환의 전 필드 스키마(`operand_schema` 일반화)·**여분 필드는 버려짐을 명시**.
3. **evidence** — 반환 중 검증 대상 필드와 그 검사(verifier 라우팅): 인용=축자 대조·값=grounding·
   이름=레지스트리 멤버십. **근거-우선 formalize 계약**([[22]] 따름정리)의 일반화.
4. **★정보-맞춤 규칙([[18]]·C275의 제도화)** — input_slice는 그 판단에 필요한 정보를 **전부** 담아야
   하고, 계약 리뷰 시 "이 슬라이스만 보고 사람이 옳게 판단할 수 있나"를 통과해야 한다.
   불성립(슬라이스에 없는 것을 요구받음) = **침묵-드롭 금지** → `missing_fields` 분화(§2c C278 방식:
   record-유래=재요청 정당 / slice-밖=이행-가능 재질의 or 정직 abstain 표면화).
5. **budget** — 라운드·getter 호출·반환 문자 상한(기존 max_rounds/max_batch/char_cap 일반화)·초과=폴백.
6. **on_fail** — 폴백 의미: reader=원 실행(현 wrap과 동일·fail-open) / formalize=abstain 표면화 /
   컨트롤러=무개입. **폴백은 항상 "덜 개입"쪽**(fail-open 원칙).

### 2d. orchestrator 불변식 (전부 기존 규율의 승격)

| # | 불변식 | 출처 |
|---|---|---|
| ① | **밖에서는 한 에이전트** — 에이전트 간 통신·중간 산물은 공식 히스토리에 **절대 미기록**. 히스토리에 들어가는 것은 도구 반환 형태의 최종 결과뿐 | replay 사고 3회(C208②·038·026) |
| ② | **라우팅 = 닫힌 선언** — 어떤 호출/조건이 어느 에이전트로 가는지는 A2 멤버십. LLM이 라우팅을 정하지 않는다 | [[10]]·[[52]] |
| ③ | 표면화는 **버스 경유만**(예산·정직·replay 불변식은 버스가 한 번 집행) | CONSOLIDATION §2b |
| ④ | 반복 통제는 **거버너 경유만** | CONSOLIDATION §2a |
| ⑤ | 기능 에이전트는 **무상태**(호출마다 리셋) — 멀티턴 상태는 orchestrator가 원장·슬라이스로 공급 | §1.1 부하 실측 |
| ⑥ | 모든 에이전트 호출은 beat + trace(x44 편입) | 규율 2·3 |

### 2e. 본런 대비 무엇이 달라지나 (비교 arm의 변수)

rev2 arm = 기준선(nt2 스택) 대비 **추가 변수 3개만**: ⓐreader 상설(wrap이 폴백 아닌 기본 경로)
ⓑplan 컨트롤러 e2e 가동(E-PLAN 배선 — [[14]]) ⓒ계약 명세화에 따른 input_slice 정리(현 임시 주입의
선언화). formalize/verifier는 이미 기준선에 있으므로 변수 아님. — 변수를 이 셋으로 묶는 이유:
전부 "부하·경로" 축이라 판정축이 같다(§6).

## 3. [[05]] 결정-시점 3질문 (의무)

1. **도메인-특화 순증?** — scaffold: orchestrator·계약 실행기는 **도메인 리터럴 0**(라우팅·슬라이스
   선택자·문구 전부 A2). A2: 계약 6필드 선언 = **도메인-특화 데이터 순증 있음(정직)** — 단 전부
   기존 선언(isolate·function_agents·corpus·operand_schema)의 **정규화·이관**이고 신규 지식의 출처는
   env 구조·정책 축자([[23]]·엔트리별 `_note_`). 전이 = A2-swap 그대로.
2. **유동적 판단을 동결?** — 아니오. 동결하는 것은 **누가 어떤 입력으로 판단하느냐**(형식)이지
   판단 내용이 아니다. 의미 판단은 전부 LLM 에이전트 안에 남는다.
3. **모델 대신 도메인 행동 수행?** — 아니오. orchestrator는 라우팅·공급·검증만. 행동 방출은 대화
   에이전트, 값 산출은 기능 에이전트(LLM). (plan 컨트롤러의 drive는 기존 E-PLAN 설계의 승계 —
   write 강제 0 불변.)

## 10. 부록 A — 계약 스키마 v1 (결정점-타입별 근거 표준 · 2026-08-02 밤 · 리뷰 대기)

> 사용자 지시: *"모든 선택 결정점에서 근거를 대라고 하는 부분을 기능별 에이전트로 쪼개고, 각 에이전트에서
> 근거 확인하게 루틴을 만드는 건 어떤가."* — §2c 6필드 계약의 **evidence 필드를 타입 시스템으로 구체화**한다.
> 원칙 재확인: 근거 **제출**은 에이전트(LLM·formalize), 근거 **확인**은 경계의 엔진([[10]]·[[22]] — 실재성만·
> 의미 판단 0). 에이전트 내부 자기-확인 루틴은 두지 않는다(soft·[[07]]).

### 10a. A2 스키마 골격 (도메인-일반 형식 · 내용은 도메인 A2)

```json
{"agents": [{
  "name": "…",                       // 도메인-일반 기능명(selection/reader/coverage/…)
  "type": "reader|formalize|selection|coverage|controller",
  "input_slice":  { "docs": ["제목-접두"], "rows": ["row_fields"], "ledger": ["…"], "user_turns": true },
  "return_schema": { "fields": { "…": "type" }, "extra_fields": "dropped" },
  "evidence": [{
     "field": "…",                   // return_schema 내 검증 대상 필드
     "check": "quote_verbatim|grounded_value|registry_member|set_compare|status_field",
     "corpus": "kb_docs|records|user_turns|tool_returns",   // ★에코-제외 규칙 상설(P9-감사B):
                                     //   우리 오류-응답·give-확인 에코는 corpus에서 제외
     "on_fail": "surface_requery|abstain_surface|fallback_less_intervention"
  }],
  "budget": { "rounds": n, "getter_calls": n, "return_chars": n },   // 초과=on_fail·버스 예산 편입(§2d③)
  "on_fail": "…"                     // §2c-6 그대로(fail-open·덜 개입 쪽)
}]}
```

### 10b. ★결정점-타입별 근거 필드 표준 (이번 아크 실증 전량이 원천)

| 결정점 타입 | 근거 필드(evidence.field) | 엔진 검사(check) | 실증 계보 |
|---|---|---|---|
| **선택**(카드·대상 추천) | `eligibility_quote` + `exclusion_check_quote` | quote_verbatim(KB) | P4ⓒ — Apple∈제외·truck∉적격 **둘 다 KB 축자 실재**·QP §8b 확장 |
| **write 인자** | grounded args(기록-값 인자) | grounded_value(records·에코-제외) | §2bs·P9(028 전사·040 placeholder)·C289 |
| **give** | `user_request_quote` | quote_verbatim(user_turns) | P1(010 여분-give 재현 2/2) |
| **이관** | `transfer_trigger_quote`(정책 조항 또는 무득점 신호) | quote_verbatim ∨ 구조 신호(P2 ⑴⑵) | 012(4/4)·014 |
| **완결** | `dispatch_ledger`(지시 대상 집합 vs 제출 집합) | set_compare(구조 필드·A2 패턴 폴백) | P8(020/027 부분-제출) |
| **상태-판독** | `status_field`(도구 응답의 Status: 구조) | status_field 파싱(닫힘) | 026(RESOLVED 신호 미독) |
| **주장-수용**(외부 조건 이행) | `claim_quote`(주장 문구의 KB 대조) | quote_verbatim(KB) | P10(014/015 재현 2/2) |

규약(전 타입 공통): 검사 = **실재성/구조만**·불성립 = 표면화+재질의 1회(fail-open·강제 금지)·
Δspurious 동시 계측·표면화는 버스 경유(§2d③)·개입은 생성-레벨(replay §6-4)·quote 검사는 정규화
토큰-연속(C276)·**도구 인자에 근거 필드 추가 금지**(P1 ☠채널 제약 — 근거는 선언 봉투에만).
