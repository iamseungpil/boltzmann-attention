# 격리 격자 설계 — 어디까지 LLM이 사실을 만들 수 있고, 어디까지 격리해야 하는가

> 2026-08-09 · 사용자 지시. 유료 0(로컬 vllm). 등대 §1.2·§1.4 파생.
> 선행 결과 = 원장 C360~C365 후보(x181~x186). 이 문서는 **다음 격자의 사전 등록**이다.

## §0 왜 — 앞선 프로브가 남긴 것

한 아크에서 다음이 섰다(전부 32B+14B·n=8):

| 사실 | 근거 |
|---|---|
| 궤적 꼬리의 **자기-약속 한 문장**이 답을 8/8 뒤집는다 | x181 절제(`-commit`≡`none`·`-accounts`≡`full`) · x184 |
| **정박이 답을 결정한다** — 지목을 gold로 바꾸면 8셀 중 7셀 8/8 | x184 `+commit→gold` |
| 정박은 **증거로 안 밀린다** — gold 마진 +150도 무효 | x183 |
| 정박 세기에 **형식 사다리**가 있다 (`prose` < `prose+num` < `json`)·모델마다 붕괴 칸이 다르다 | x185 |
| **과잉 격리는 타입 제약을 잃는다** — 사실 문장을 빼면 두 태스크·두 모델 카드(`Business Platinum`) | x182 `bare` |
| **우리 사실 문구가 정박을 나르고 있었다** — 후보 이름 부르는 문장 제거로 32B/099 4/4셀 8/8 | x186 |

⇒ 남은 질문 둘, 둘 다 사용자가 지시한 형태:
**⒜ 격리를 어디까지 해야 하는가**(무엇을 지우고 무엇은 반드시 실어야 하는가)
**⒝ 사실을 LLM이 어디까지 정확히 만들 수 있는가**(형식화의 실제 정확도)

그리고 **난이도**가 그 답을 바꾸는지 — *쉬운 질문은 작은 모델도 맞고 어려운 질문은 큰 모델도 틀린다* — 를
같은 격자 안에서 잰다.

## §1 축 정의

**격리 사다리(무엇이 프롬프트에 남는가)**

| 층 | 내용 | 뜻 |
|---|---|---|
| `L0 full` | 실제 대화 전체 + 표 + 사실 + 질문 | 현행 라이브(오염 포함) |
| `L2 facts_full` | 표 + 우리 사실 문구 + 질문 | 대화 제거 |
| `L3 facts_operand` | 표 + **피연산자 문장만** + 질문 | 후보 이름 부르는 문장까지 제거 |
| `L4 bare` | 표 + 질문 | 사실까지 제거(과잉 격리) |

**후보 목록**: `all`(표의 모든 주어) · `chk`(계좌 축이 있는 행만 = 질문의 타입)

**질문 난이도**

| | 문장 | 요구 |
|---|---|---|
| `Q1` | *"Which ONE ... has the highest `referrer_bonus_usd`?"* (타입어 제거) | 축 명시 · 타입 없음 = **순수 argmax** |
| `Q2` | *"Which ONE business checking account ... has the highest `referrer_bonus_usd`?"* | 축 명시 · **타입 제약** |
| `Q3` | 현행 — *"...maximise the bonus THEY receive?"* | **축 해석** + 타입 제약 |

Q1→Q2 = 타입 제약 한 단계 · Q2→Q3 = 축 해석 한 단계. 정답은 각각 엔진이 계산한다(Q1은 동점 집합 허용).

**정렬**: `name_asc` · `name_desc` (기지의 레버) **태스크**: 099 · 100 **모델**: 32B(Int8) · 14B(bf16)

## §2 E-A 선택 격자 (`x187_isolation_grid.py`)

4 격리 × {Q1×all, Q2×(all,chk), Q3×(all,chk)} × 2 정렬 × 2 태스크 = **80셀** × n=8 · 모델당.

## §3 E-B 사실 생성 정확도 (`x188_fact_accuracy.py`)

`formalize_case_facts` 가 실제로 무엇을 내는지를 **A2 템플릿 그대로** 재현해 잰다.
요청 항목 = `criteria` 중 `operand=="stated"` 인 축 + `policy_ontology.axes` 설명(엔진에 도메인 어휘 0).

**문맥 사다리**: `full`(전 궤적) · `last10`(마지막 10 메시지) · `user_only`(손님 발화만)

**채점은 gold를 안 본다** — 셋 다 엔진이 검증 가능한 닫힌 술어다([[22]]):
1. **키 준수** — 요청한 축 이름만 왔는가 (지어낸 키 0)
2. **인용 실재** — `quote` 가 대화에 축자로 있는가
3. **값 정합** — `value` 가 그 인용 안의 수와 맞는가

## §4 사전 등록 판정 규칙

| 관측 | 결론 |
|---|---|
| `L3` 가 모든 난이도·모델에서 `L2` ≥ 이면 | **처방: 사실은 피연산자만 싣는다** |
| `L4` 가 `Q1` 에서만 붙고 `Q2`/`Q3` 에서 지면 | **사실 문장이 붙잡는 것은 타입 제약**(x182 해석 확증) |
| `chk` 가 `Q2`/`Q3` 를 고치면 | **처방: 후보를 질문 타입으로 제한** (⚠[[05]] Q2 결정 필요) |
| 난이도↑에서 14B는 무너지고 32B는 버티면 | **결손 = 스케일-의존** → 격리 불필요·scale 이 산다 |
| 난이도↑에서 **둘 다** 무너지면 | **결손 = scale-invariant** → 격리/결정론이 유일 레버([[45]]) |
| E-B 의 (1)(2)(3) 중 하나라도 낮으면 | 파이프라인 상류가 이미 새고 있다 — 선택 격자 결론보다 **먼저** 고친다 |

## §5 교락·한계 (결론 전 반드시 읽을 것)

1. **★양자화 교락**: 32B는 **GPTQ-Int8**, 14B는 **bf16**. *"큰 모델이 더/덜 진다"* 는 전부 양자화 효과일 수 있다.
   bf16 32B(CPU 오프로드·C349에서 사용)로 재보기 전까지 스케일 진술은 **[M] 이하**.
2. **모델 2점**. 3B·7B는 초안 §6.1에 데이터가 있으나 현재 GPU 여유가 없다(GPU0 47/49GB·GPU1 45/49GB·GPU1은 다른 세션 소유).
3. **태스크 2개·도메인 1개**. C359가 이미 한 번 "일반화 실패"를 냈다 — 2태스크 일치도 일반 진술이 아니다.
4. **후보 제한(`chk`)은 프로브에서만 무해하다.** 출하하려면 A2/엔진 변경이고 [[05]] Q2·§1.3 제1원리(Δspurious≤0 반대편 계측)를 통과해야 한다.
5. `guided_choice` full-string 사용 — 첫 토큰 판독의 접두 그룹 왜곡을 피한다(핸드오프 §7).
