# 레버-원인 전도(全圖): 원인별 분류와 레버 할당 (2026-08-02)

> 사용자 지시: *"레버 말고 **레버의 원인별로** 분류하고, 각 원인별 대책 레버들을 할당해서 전체 그림을
> 설명해 달라. 지금까지 나온 문제들이 계속 반복되고 레버도 정리가 안 되는 것 같다."*
> 명명 규율 = [[48]](서술형 이름만·새 실패코드 금지) · 프레임 = 등대 §1.1/§1.2(LOCK·재론 아님).
> 레버 전수 회계는 x20(117 플래그·기계 산출)이 정본이고, 이 문서는 **가족 단위**로 원인에 붙인다.

## 0. 왜 반복되는가 — 문제는 레버 부족이 아니라 4개의 메타 결함이다

| 메타 결함 | 실증 |
|---|---|
| ① **진단→처방 등재→미구현→재발** | 터미널-턴: C208 ③ [S] 확정·처방 3순위 등재 → 미구현 → **035가 같은 기전으로 재발**. 채널 오분류: C208 ②서 판정 완료("env 도출 opex 0") → 미구현 → 019·028·040·041 재발 |
| ② **dark 레버** (구현됐는데 안 돎) | wrap 격리: 설계·리뷰·구현 완료인데 **발화 0회**(플래그 미설정 + `wraps` 이름 불일치 + `getter_tools` 불일치 — 세 겹) |
| ③ **레버끼리 상쇄** (합성 미계측) | 뷰-압축 ↔ dedup: 압축이 캐시를 비워 **23k 테이블 3부 재유입** — 두 레버가 없을 때보다 나쁨 |
| ④ **레버가 실패의 새 원인이 됨** | 우리 문구 결함 6종(D1~D5·C275 ⑤) · dedup 스텁이 replay를 깨서 sim 무효(026 R1) |

⇒ 대책은 §4의 규율이다(구현 순서 원칙·x44 커버리지 감사·beat 규약·설계서 소유 경계).
**레버를 더 만드는 것이 답이 아닐 때가 많다** — ①~④는 전부 이미 있는 것을 관리하지 못한 비용이다.

## 1. 원인 분류 체계

두 겹이다: **A. 모델-측 원인**(에이전트 행동이 이탈하는 이유 6개) + **B. 스캐폴드-측 원인**(우리가
만든 실패 4개). A5(부하)는 독립 실패가 아니라 **증폭기**이고, A6(의미 선택)은 레버가 없는 **경계**다.

```
A. 모델-측                          B. 스캐폴드-측(자기 결함)
├─ A1 접지 실패    (없는 값을 씀)     ├─ B1 지시 결함   (모순·이행불가·부재)
├─ A2 경로 실패    (맞는 목표·틀린 수단) ├─ B2 레버 상쇄   (합성 부작용)
├─ A3 행동 부족    (under-action)     ├─ B3 dark 레버   (배선·이름 불일치)
├─ A4 행동 과잉    (over-action)      └─ B4 측정 정합성 (replay·파서·user-sim)
├─ A5 부하        (증폭기 — 위 넷을 악화)
└─ A6 의미 선택    (열린 술어 = 경계·레버 없음)
```

등대 §1.1과의 대응(참고·재론 아님): A1≈symbolic/semantic operand 표면 · A3≈coverage/persistence ·
A5≈load([[45]]) · A6≈semantic reference 경계. over/under는 §1.3 상쇄 법칙의 두 방향이다 —
**거의 모든 레버는 under를 사면 over를 팔고, 그 역도 같다.** 그래서 짝으로 배치해야 한다.

## 2. 원인 → 레버 할당표

### A1. 접지 실패 — 값·인용·이름이 실재하지 않음 (날조·오독·정박 치환 C43)

| 하위 원인 | 레버 | 상태 | 파는 것(상쇄) |
|---|---|---|---|
| 도구 인자에 없는 값 | `ground`(scalar/array/**intent**·D4′) + GROUNDING WARNING | 배포 | **판별력**(023: 제약 4개 드롭→fit 무력화) · false-drop |
| 강등 근거 인용 날조 | quote-ground(C197) → **quote-pin+식별표**(C278/C279) | QP arm 검증 중 | 구가드=false-abstain 9종(ba8b) · 표=회수축만 순이득 |
| 제출 전 주장 비접지 | CLAIMPROV / WRITEPROV / NLNUM_PROV | 배포 | 강제 regen이 날조 유인(C212서 계측) |

| 발명 txn id | FAB_STRIP·grounded_params(C211 F6) | 배포 | — |

## 3. 전체 그림 — 한 장

모든 레버는 결국 **다섯 질문**에 대한 답이고, 각 질문에 짝(상쇄)이 있다:

```
              ┌─ 값이 실재하는가?      → A1 접지 (ground·prov·quote-pin)   ── 팔면: 판별력·false-drop
              ├─ 수단이 맞는가?        → A2 경로 (TOOL_CHANNEL·redirect)   ── 팔면: over-action
 모델 행동 ───┼─ 다 했는가?           → A3 under (coverage·EPLAN·terminal) ─┐
              ├─ 너무 했는가?          → A4 over  (게이트·REPEAT_CAP)      ─┴─ 서로가 서로의 비용
              └─ 문맥이 감당되는가?     → A5 부하 (wrap격리·SG_ISOLATE·재유입 차단) — 증폭기 억제
                        (A6 의미 선택 = 레버 없음 · learn/scale로 이관 [[13]])

 스캐폴드 자신 ─ B1 우리 문구가 틀렸다 / B2 레버끼리 싸운다 / B3 죽어 있다 / B4 측정이 거짓말한다
                → 문구 수정 · 합성 계측 · x44+beat 상설 · replay 위생
```

**반복의 정체**: qp32p1 실패 24건을 이 틀로 다시 세면 — A2(경로) 9 · A3(under) 11 · A6(선택) 5 ·
A5(부하) 3 · B4(측정) 1 — **새 원인은 하나도 없다.** 전부 위 표의 기지 칸이고, 반복된 이유는
§0의 메타 결함(①미구현 ②dark ③상쇄 ④자기결함)이지 분류가 부족해서가 아니다.

## 4. 반복을 끊는 규율 (상설)

1. **기지-미구현 우선**: 새 발견을 좇기 전에, [S]로 끝난 처방의 미구현 목록을 먼저 소진한다
   (FAILURE_AXES §0.2 — 035 재발이 비용의 실증).
2. **모든 런에 x44**: env 덤프(켜짐 증명) × 태그/beat(동작 증명) → `ON·무발화`가 0이 아니면 발사 전 감사.
3. **beat 규약**: 신규 레버는 효과 지점에 `beat()` 필수 — 무태그 dark 원천 차단.
4. **소유 경계**: 한 트리거는 한 설계서만 규정(R-A) · 같은 이름 다른 뜻 금지(`lookup_missing` 사고).
5. **합성-우선**([[19]]) + **Δspurious 의무**(등대 §1.3): 레버는 단독이 아니라 스택으로 계측 —
   상쇄(B2)는 합성 런만이 드러낸다.
6. **표적 실재 선행**(C263): 레버를 만들기 전에 전수 계수 — WRITE_CAP(∅)·케이스 3b(도달 불가)가 선례.
7. **A6은 밀지 않는다**: 열린 술어에 scaffold를 더 얹는 것은 [[13]] 역순 — learn/scale 몫으로 기록만.
