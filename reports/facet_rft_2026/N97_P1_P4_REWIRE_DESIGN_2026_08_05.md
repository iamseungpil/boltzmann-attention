## §1 P1-ⓐ — 표적의 출처를 "우리 층이 방금 선언한 결손"으로 옮긴다

### 1.1 무엇을 바꾸나

지금: `pin_for(orch, am, a2, messages)`가 `am.tool_calls`를 순회하며 A2 `require_tool_before`를 조회한다.

바꿈: **sim-범위 상태**를 표적으로 삼는다 — A2가 선언한 선행 read 중 **이 sim에서 아직 실행되지 않은 것**.

```
M(sim) = { r | r ∈ A2 선언 선행 read } − { 이 sim에서 실행된 도구 }
```

두 A2 키를 모두 흡수한다(`require_tool_before` 4건 + `scaffold_get_tools[].requires_reads` 2건 = 선언 6건).
초판이 쓰던 **턴-범위**(거부가 산출한 결손)는 폐기한다 — 그 출처는 `t2_scaffold_get.py:1450~`의
**호출 순회 안**에 있어서 무호출 턴에는 ∅이고, 무호출 턴이 바로 표적이었다(리뷰 ★1).
실행 집합은 이미 `_effc`(:1462)가 계산한다.

| 출처 | A2 키 | 초판(턴-범위) | rev2(sim-범위) |
|---|---|---|---|
| `SG_REQREADS` 거부 | `scaffold_get_tools[].requires_reads` | 15/15 발화인데 P1 사정거리 밖 | **흡수** |
| `require_before` 사후점검 | `require_tool_before` | 1 발화·재생성 트리거 아님 | **흡수** |

### 1.2 술어 (전부 닫힘·[[22]])

```
pin ⟸ ⑴ M(sim) ≠ ∅                                        ← sim-범위 상태(§1.1)
      ∧ ⑵ **수요 신호**가 이 sim에서 이미 관측됐다            ← §1.7이 정한다(무차별 발화 방지)
      ∧ ⑶ m ∈ M 중 **피의존 ≥2**이고 env 레지스트리에서 **유일하게** 접미사 해소되는 항목이 있다
      ∧ ⑷ 그 이름이 read 접두(get_/list_/check_/…)를 가진다   ← write 고정 금지([[14]])
      ∧ ⑸ 이 sim에서 아직 고정한 적이 없다                     ← 1회/sim
      (호출 유무는 조건이 아니다 — 무호출 재생성에서도 성립한다)
```

⑴은 A2 선언집합 − 실행집합이라 새 판정이 아니다. ⑶은 env 기계도출([[23]]·opex 0). ⑷⑸는 상수.
**A2 저작 순증 0 · gold 미참조**([[03b]]).

### 1.3 왜 이것이 "강제"가 아닌가

고정은 **생성-측 스키마 제약 1회**다. tool 출력을 만들지 않으므로 replay가 비교할 것이 없고
(C210이 `require_tool_before`를 권고로 강등시킨 사유가 닿지 않는다), 다음 턴부터는 모델이 자유롭다.
거부·deny·차단이 아니라 **한 번의 재생성에서 고를 수 있는 이름을 하나로 줄이는 것**이다.

### 1.4 이 레버가 파는 것 (제1원리·등대 §1.3)

| 산다 | 판다 | 계측 |
|---|---|---|
| 관문 진입(미도달 53 sim) | 그 턴의 **다른 정당한 행동**(이관·질문·다른 read) 1회 | `transfer_to_human_agents` 호출률 Δ · 첫 이관 시점 Δ(`x67`) |
| 접미사 날조 차단(x72 T2 재현) | 불필요한 unlock 1건 = **over-action** | Δspurious: gold 밖 unlock/read 수 · `x44` 발화×결과 |

**중단 규칙(리뷰 ★2 교체·pass를 술어에서 뺀다)**:

```
되돌린다 ⟸ 이관률 하락 ∧ 관문 미도달 53이 줄지 않았다
```

초판 문안("이관률 하락 ∧ pass 불변")은 **레버가 설계대로 작동할 때 반드시 발동한다** — 이관 감소가
의도된 1차 효과이고 pass 불변은 §5가 이미 사전등록한 결과이며, 194 sim·pass 0.10에서는 pass 상승을
검출할 분해능도 없다. 즉 성공을 실패로 읽는 술어였다. 교체본은 **"이관은 줄었는데 진입도 못 늘렸다"**
= 탈출구만 판 것일 때만 되돌린다. "이관 줄고 진입 늘고 pass 그대로"는 **예상된 성공**이므로 유지한다.

## §2 P4 — 거부-호출 반복을 계수에 넣는다 (**P1-ⓐ 이후로 미룸**)

> ★리뷰 ★3 반영: **052는 P4의 표적이 아니라 P1-ⓐ의 표적이다.** 12회 반복된 `check_cli_eligibility`는
> *선행 read 결손*으로 거부된 호출이고, 그것이 바로 P1-ⓐ가 창을 여는 조건이다. P1-ⓐ가 그 read를
> 고정하면 첫 고정에서 루프가 끝난다. ⇒ **순서를 P1-ⓐ → 재계량 → P4로 바꾼다**(P6의 GO를 P3 이후로
> 건 것과 동형). 선결 ⑴(K_deny 곡선)도 그 재계량 뒤로 함께 미룬다 — 표적이 정해지기 전에 K를 재는 것은
> 무의미하다.
>
> **조건부 폐기**: 재계량에서 잔여 표적이 유의하지 않으면 P4-거부계수는 **세우지 않는다.** §2.2가
> 자인하듯 처방은 문구뿐이고, 같은 문서의 실측(`[DUPLICATE-READ]` 경고 68 ↔ 반복 71)이 그 예후다([[07]]·[[42]]).

### 2.1 무엇이 문제인가

`seen[k]`는 **실행되는 read만** 계수한다(설계 의도 그대로 — 실행 비용을 재는 계수기다).
그런데 폭주의 한 축은 실행되지 않는다: 052는 `check_cli_eligibility`를 12회 반복했고
매번 `[READ-FIRST]`로 거부됐다. 실행이 아니므로 계수 0, K=8 미도달, 캡 무발화.
084/t1의 71회(실행된 read)는 잡지만 **이 축은 원천 무맹**이다.

### 2.2 처방 (계수기 확장 · 새 강제 아님)

거부된 호출도 `(name, args)` 키로 **별도 계수기**에 센다. K회째부터 거부 문구에 기존
`[REPEAT-CAP]` 전환 지시를 덧붙인다 — **거부는 이미 일어나고 있으므로 실행 억제가 추가되지 않는다.**
바뀌는 것은 **문구뿐**이고, 그래서 replay 표면도 변하지 않는다(거부 스텁은 이미 우리 것).

**K는 실행-캡과 같은 8을 쓰지 않는다.** 거부는 실행보다 싸므로 과차단 위험이 낮지만, 반대로
거부 루프는 더 빨리 치명적이다(052는 12회에서 ctx로 죽었다). ⇒ **K_deny는 x35로 재계량한 뒤 정한다**
(무료 선결·§4).

## §5 판정

1차 지표는 pass가 아니라 **레버 발화 로그 × 원인별 이동**(C294)이다.

| 레버 | 성공 신호 | 실패/중단 신호 |
|---|---|---|
| P1-ⓐ | pinned > 0 · **관문 미도달 53 → 감소** · 발화 sim ≈ 49(§1.7 사전등록) | **이관률 하락 ∧ 관문 미도달 불변**(=탈출구만 매도·§1.4) · 발화가 49를 크게 넘음(=수요 게이트 무력) |
| P1-ⓐ 부작용 | 오조준 sim에서 gold 밖 read 순증 ≤ +1 · 밀린 행동 0 | 근접-성공 sim(잔여 ≤2) 오조준 = **단독 되돌림 사유** |
| P4-거부계수 | (P1 이후 재계량에서 잔여 표적이 남을 때만 판정) | 과차단(정당한 재시도 차단) 발생 |

**사전등록(rev2)**:
- P1 단독 기대 pass 증가 = **0**(관문 도달 26 sim도 전부 실패했다). 이 레버의 값은 실패 지점을
  *진입*에서 *회복*으로 옮겨 P3·P5의 사정거리 안에 두는 것이다.
- 기대 발화 = **36 sim**(§1.7 `demand2h` 전수). out-of-sample 기준선은 **trial당 16~20 발화·적중 69~75%**다.
  크게 많으면 수요 게이트가 무력한 것이고, 크게 적으면 재생성 자체가 안 일어난 것이다 — 다른 진단이므로
  발화 로그로 구분한다.
- 기대 조준 = **관문 36 / 36**(rev3안은 관문만 겨눈다). gold 적중 26은 *상한*이지 pass 예측이 아니다.
- **오조준 10건**(§1.8)은 사전등록된 비용이다. 밀린 행동·gold 밖 read 순증·근접성공 sim 오조준을 계량한다.
