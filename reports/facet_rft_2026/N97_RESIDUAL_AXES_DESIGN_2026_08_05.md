### 1.3 [[16]] P2-b 금지선 판정 (이 설계의 최대 쟁점)

폐기된 P2-b는 **모델의 자유 산문을 해석해 의미를 뽑는 것**이다. 여기서 하는 것은 다르다:

| 판정 주체 | 파서가 의미를 결정 | 파서는 **후보만** 만들고 판정은 기존 원장-대조가 한다 |

### 1.3b 보수 추출 규칙 (리뷰 지적 — "못 뽑으면 무동작"은 **오추출**을 안 덮는다)

`card_type: Silver Rewards Card (다만 Platinum을 권합니다)` 같은 문장에서 값이 절 전체로 잡히면
정당한 안내가 접지에 걸린다. 그래서 추출은 **부재뿐 아니라 애매함에서도 무동작**이어야 한다.

```
값 = 키 뒤 구분자까지만        (줄바꿈 · 마침표 · 쉼표 · 여는 괄호 · 백틱 · 별표)
```

그 확인용이 된다(경계 사례 = 값에 괄호·수식어가 붙은 안내문).

⇒ **키 매칭은 열린 해석이 아니다.** 다만 이 논거가 리뷰에서 기각되면 N1은 폐기한다 —
그 경우 대안은 "give 호출에 `grounded_args`를 **요구**"인데, 이미 P9 `_note`가
*"인자를 요구하지 않는다(요구=스키마 사고 재발)"* 로 금지해 둔 길이라 되살리지 않는다.

## §2 N2 — 모르는 불리언·범주를 값으로 채우지 않는다

### 2.1 관측

### 2.2 술어 — **권위 소재**로 가른다 (리뷰 ★2 반영·초판 폐기)

초판은 *"(원장 ∪ 손님 발화)에 근거가 없으면"* 이라고 썼는데 **불리언에는 성립하지 않는다.**
`invited: false`의 근거는 문자열 `"false"`가 아니라 **그 주제가 대화에 나왔는가**이고, 그것을 재려면
의미 판정(=열린 술어)이 필요하다 — N3를 기각한 바로 그 사유에 걸린다.

**권위 소재로 가르면 닫힌다**([[52]]):

```
인자명이 회수된 레코드의 **필드로 실재** → 그 필드값이 근거      (기계 대조·통과)
실재하지 않음 → 권위자는 손님뿐 → 명시적 손님 발화 없으면 **채우지 말고 ASK/미기입**
```

술어는 "**필드명 멤버십**"이라 완전히 닫혀 있고 A2 순증도 0이다(필드명은 회수된 레코드에서 온다).

**전수 실측(194 sim)** — 이 분기가 실제로 가르는가:

| 인자 | 레코드 필드로 실재 | 레코드에 없음 |
|---|---|---|
| `invited` | 3 | **26** |
| `premium_subscriber` | 0 | **33** |
| `needs_purchase_protection` | 0 | **36** |
| `business` | 0 | **38** |

⇒ 레코드에서 오는 것은 통과하고 **손님 속성인 것만** 걸린다. 001의 `rho_bank_subscription`
(레코드 필드 아님·손님만 앎)이 정확히 이 분기로 잡힌다. 영향 sim = **36**.

### 2.4b ★미기입은 안전한 폴백이 아니다 (재리뷰 지적 → 픽스처로 확인 → 처방 교체)

rev2는 *"예산 소진 → 미기입"* 으로 해소했다. **픽스처가 그것을 무효화했다** — 두 하류가 모두
빈 값을 **false로 되돌린다**:

| 하류 | 축자 | 미기입의 실제 효과 |
|---|---|---|
| env `apply_for_credit_card` | `rho_bank_subscription: bool = **False**` (tools.py:4409) | 빼면 **False로 실행**된다 — 001의 gold(`true`)와 정확히 반대 |
| **우리** `catalog_filter` | `if row.get("invite_only") and **not ctx.get("invited")**` (t2_compute.py) | `None`도 `not` 참 → **invite-only 카드가 배제**된다(Diamond Elite) |

⇒ **미기입 = false 단정과 같은 결과다.** 폴백을 다시 쓴다:

```
값의 권위자가 손님(레코드 필드 아님)이고 값이 미지일 때
  ⒜ 우리 도구  → **미지를 unverified 버킷으로**(배제 아님) — 코드 수정 · A2 순증 0
                  (A2 `_note`가 이미 "미지=판정이 갈리면 unverified"라고 적어 둔 규약이다)
  ⒝ env 도구   → **ASK**. 예산 소진이면 **그 행동을 실행하지 않는다(보류)** —
                  기본값이 조용히 값을 만들므로 "빼고 실행"은 선택지가 아니다
```

**우리 층이 같은 결함을 갖고 있었다**는 것이 이 항목의 핵심이다 — 모델의 "모르면 false"를 지적하면서
엔진의 `not ctx.get("invited")`가 똑같이 미지를 false로 접고 있었다. ⒜는 그 교정이고, N2의 표적
(`invited` 26건·`premium_subscriber` 33건)이 대부분 이 경로다.

⒝ 때문에 ASK 예산 충돌은 **남는다**. 보류는 gold 행동을 못 하게 하므로 pass 비용이 실재한다 ⇒
`IDENTITY_GATE_DESIGN` §4-2의 B는 **측정 대상 파라미터**로 이미 선언돼 있으니, N2 도입 런에서
`ASK 발생률 × 답변 품질`을 같이 재서 B를 조정한다(그 문서의 조정 근거 그대로).

계측 = ASK 턴 수 Δ · 미기입 호출 수 · 손님 이탈(`###STOP###` 조기 종료) Δ.

### 2.5 사전등록

기대 발화 = **35건 상한**(대화에 주제 없는 false 단정). 실제로는 A2가 write로 선언한 도구에 한정되므로 더 작다.
**pass 기대 증가는 001형 1~2건**으로 잡는다.

## §4 복구 — `T2_MATCH_COUNT`가 스택에서 빠져 있다

구현은 `t2_gate_patch.py:707`, 라이브 검증은 B4. 그런데 A·N97·현재 런은 **0**이고 `go_stack.sh`에
등재된 적이 없다. `SEARCH_TOOLING_TRANSFER_MAP_2026_08_03.md` §5의 순서 ①("T3 완주 판정")이 중단된 상태다.

**값 분포 계량(리뷰 ★3 선결·`x75_match_count_dist.py`)** — B4 궤적 전수:

| 부착 문구 | 건수 |
|---|---|
| **전부 표시**(`…; all N shown`) = 경계 인증 | **126 (62%)** |
| 0건(`no document contains …; K shown by ranking`) | 53 (26%) |
| 부분 표시(`…; K shown (M not shown)`) = 좁히라는 신호 | 23 (11%) |
| 합계 | **202건 / 50 sim** |

⚠**초판(rev2)의 149는 내 분류 오류였다.** 세 문구가 **전부** `all of these words`를 담고 있어서
`"all" 포함`으로 가르면 **부분표시가 인증으로 접힌다**(149 = 126 + 23). 재리뷰가 지적한 126이 옳다.
`x75` 도크스트링에 **분기별 고유 표지**를 축자로 박았다(0건=`no document` · 인증=`; all ` ·
부분=`not shown)`). 총계 202는 궤적(role=tool 본문) 기준이고 드라이버 로그는 제외한다 —
로그에는 모델이 본 적 없는 줄이 섞이므로 판정 대상이 아니다.

⇒ **등재 판정 = GO**(인증 62% = 과반). 남는 26%는 다중어 자연어 질의에서 분모가 0이 되는
경우이고, 이것은 문구 문제가 아니라 **질의가 구(phrase)라서** 생긴다 — `SEARCH_TOOLING_TRANSFER_MAP`
T5(부분문자열 AND)가 그 자리다. 등재는 지금, 0건 문구 개선은 T5와 함께.
단 **이번 런 중에는 금지**(드라이버가 블록마다 pull한다).
