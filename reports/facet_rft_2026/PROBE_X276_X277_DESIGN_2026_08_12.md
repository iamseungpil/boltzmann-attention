## §1 x276 — 추천-수렴 격리 프로브 (ⓒ)

**질문**: 요구사항 전부 + 이미 회수된 KB 사실이 손에 있을 때, 모델은 **하나로 수렴**할 수
있는가 — 못 하면 능력 결손, 하면 전달/문면 문제.

**문맥 구성**: `bank_dbw_on_20260812` 071 trial0/1 궤적을 **마지막 요구 발화 직후**에서
절단(replay·정보-맞춤 [[18]]: 그 시점까지 모델이 실제로 본 KB 결과·손님 발화 전부 포함).

**팔 (각 n=8·temp 다양화)**:

| 팔 | 델타 | 재는 것 |
|---|---|---|
| A_LIVE | 절단 문맥 그대로 → 다음 발화 생성 | 라이브 재현: 재검색 루프가 나오는가 |
| B_ONE | + *"state the ONE ... that satisfies every requirement"* 직문 | 수렴 **능력**: 정답(Sky Blue/Gold Saver Account)을 대는가 |
| C_SUB | + *"eliminate the candidates that fail ≥1 requirement, then state what remains"* | **지시된 빼기**가 되는가 ([[63]] 예측: 지시로는 안 닫힘 — 선행 대조) |
| D_MIN | 요구목록+회수된 KB 사실만(스캐폴드 발화 제거) | 루프가 **우리 문구**에서 오는가 (ⓐ 동형 검사·[[55]]) |
| N_NEG | 요구 중 하나를 **어떤 상품도 못 채우게** 변조 | 부정통제([[57]]): 정답 = "단일 적합 없음/추가 확인" — **답이 달라져야** 한다 |

**판정표** (사전등록):

| 패턴 | 해석 | 다음 |
|---|---|---|
| B 8/8 · A 루프 | 능력 있음·전달 문제 | 레버 = 전달(수렴 시점 고정·STEP2 동형). 결정론 금지([[62]]②) |
| B 0~2/8 · C 8/8 | 빼기만 지시하면 됨 | [[63]] 갱신(새 기준 축) — 레버 문면 = C 의 그 문구 축자([[03b]]) |
| B·C 다 실패 | 격리서도 수렴 불능 = 능력 | **그 단계만** 최소 결정론 후보 — 단 [[62]]③·[[63]] 떠먹이기 금지 심사 선행 |
| D 만 성공 | 우리 문구가 루프 유발 | 문구 수술(ⓐ 동형) |
| N 이 "적합 없음" 못 냄 | 프로브 무효(과유도) | 문구 재설계 후 재측정 |

## §2 x277 — 절차-근거 격리 프로브 v2 (ⓓ1·x274 의 교정판)

**질문**: 손님이 세계-사전 절차(EIN·SSN·보안 폼)를 **먼저 제안/문의**할 때, 모델은 env-절차
(도구 스키마: 인자 셋뿐·in-chat 실행)로 답하는가, 세계-사전을 수입하는가.

**x274 와의 차이 (핵심 교정)**: x274 는 유인 없는 질문("무엇이 필요한가")이라 A_LIVE 0/8 로
결손이 재현되지 않았다. **유인 = 손님의 외부절차 제안 발화** — 이것을 문맥에 포함해야
측정 대상이 존재한다.

**문맥 구성**: g런 071 trial0 을 t25(*"masked secure form/link"* 발화) 직후 절단 +
dbw_off 070 trial2 를 EIN 질문 직후 절단. 그 시점까지 모델이 실제로 본 것 전부 포함 —
특히 `open_bank_account_4821` 스키마가 **이미 문맥에 있는지**를 절단본별로 기록한다.

**팔 (각 n=8)**:

| 팔 | 델타 | 재는 것 |
|---|---|---|
| A_LIVE | 절단 문맥 그대로 | 라이브 재현: 외부절차 채택률 |
| B_SCHEMA | + 그 write 도구의 스키마(인자 3개·in-chat)를 질문 인접 위치에 재제시 | **재료 전달**로 닫히는가 ([[62]]② 전달 레버 후보·[[65]] 답만) |
| C_ASK | + *"answer only from procedures/tools that exist in this conversation's tool list; if absent, say so"* | 지시로 닫히는가 ([[63]] 선행 대조 — 예측: 안 닫힘) |
| N_NEG | env 에 **실제로 추가 정보가 필요한** 요청으로 교체 (A1 에서 필수 인자 많은 도구 선정) | 부정통제([[57]]): 정답 = 그 정보를 요구 — **답이 달라져야** 한다 |

**부수 계측 (공짜)**: A_LIVE 산출에 transfer 제안이 나오면 그 빈도(ⓓ2 상류 대조),
x274 처럼 인용 요구 시 QUOTE_UNREAL 이 재발하는지는 **측정하지 않는다**(이미 답 있음: 유발).

**판정표**:

| 패턴 | 해석 | 다음 |
|---|---|---|
| A 채택↑ · B 0 | 결손 = 스키마-질문 거리(전달) | 레버 = write-도구 스키마 인접 재제시(도메인-일반: A1 스키마 기계 재인쇄·선별 0) |
| A 채택↑ · B ↑ · C 0 | 전달로도 지시로도 안 닫힘 | 세계-사전 상한 후보([[42]]·RLFT 잔여) — 헤드라인 "배치로 다 닫힌다" 금지(handoff §3.4) |
| A 0 | 여기서도 재현 실패 | 유인 가설 기각 — user-sim 동학 의존 = 격리 불가로 원장 기록·중단 |
| N 미분화 | 프로브 무효 | 재설계 |

## §3 [[62]] 자기점검 4문

1. **격리에서 재봤는가?** — 이 문서가 그 측정의 설계다. ⓒ·ⓓ1 은 격리 측정 0회였고(handoff
   §3.3 "미진단"), x276/x277 이 첫 측정. 파일명 = `x276_converge_iso.py` · `x277_proc_import_iso.py`.
2. **격리에서 성공하면?** — 짓는 것은 **전달**뿐(B팔이 그 전달의 문면 그대로). 계산·판단 대행 없음.
3. **모델 판단 중 사라지는 것?** — 없음. 어느 팔도 정답(상품명·절차)을 주지 않는다. B_SCHEMA 는
   이미 env 가 공개한 스키마의 위치만 옮긴다. N 팔이 그 검산(과유도면 프로브 무효 판정).
4. **엔진 출력에 argmax·"정답은 X"?** — 없음. 프로브는 채점만 하고(정답 대조는 gold 와의
   기계 비교), 산출물은 빈도표다.

## §4 [[05]] 결정-시점 3질문

1. **도메인-특화 순증?** — 프로브는 실험 코드(scaffold 아님). 장차 레버가 되어도 문면은
   도메인-일반(스키마 재인쇄·수렴 시점 고정)이고 상품명·도메인 사실은 넣지 않는다.
2. **유동 판단의 동결?** — 없음. 어느 후보 레버도 선택을 대신하지 않는다(§3-3).
3. **scaffold 가 도메인 행동 수행?** — 없음. fetch·검색·개설 전부 모델이 한다.
