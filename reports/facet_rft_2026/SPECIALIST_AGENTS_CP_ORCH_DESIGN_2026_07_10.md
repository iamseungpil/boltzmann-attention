## 0. 한 줄
결정유형마다 **(전문 에이전트, 전용 검증기, 전용 A2 슬라이스)** 3중쌍을 독립시키고, 이들의 협력을
**결정론 오케스트레이터(pin 상태기계)** 가 조립한다. 오류는 (a) 각 전문가의 전용 검증기에서 조기 차단되고
(b) pin 규칙으로 단계 간 재개방·전파가 구조적으로 불가능해진다. **= thesis([[00]] boundary-translator)의 완전형.**

## 1. 원칙 (불변 준수)
1. **분담**([[10]]): LLM=생성·formalize·의미 판단만 / 선택기·검증기·상태유지·조립=결정론.
2. **관할 서로소**: 전문가 1 = 결정유형 1 = 검증기 1 = A2 슬라이스 1. 같은 결정을 두 주체가 열지 않는다.
3. **pin**: 검증-통과 결정은 오케스트레이터 ledger에 고정 — 이후 어떤 전문가·재생성도 재개방 불가(수정=미통과 부분만).
4. **짧은 문맥**: 전문가는 ledger의 관련 슬라이스만 받는다(전체 대화 아님) — 부하 절감(E1 계보)·오염 차단(오염된 표면 합의가 아니라 형식층 요청스펙을 받음).
5. **[[05]]**: 전문가 역할·검증기 로직 = 도메인-일반. 도메인 사실 = A2 슬라이스만. 전이 = A2 스왑.
6. **좌석은 질량으로**([[13]] 최소 scaffold): E-ISO/census 질량이 정당화하는 전문가만 둔다. 질량 없는 전문화 금지.

## 3. 결정론 오케스트레이터 (context-유지 = 코드)
- **pin ledger** (sim당 단일 상태): `{요청스펙[], plan[], 선택값{arg→val,verified_by}, 동의{제안id→user-yes}, 실행기록[], 잔여[]}`.
- **라우팅** = CP 지점: user 턴 도착→① 호출 / 스펙 신규→② / write 인자 필요→③(후보는 오케스트레이터가 결정론 열거) / tool 선택→④ / 실행 후→기록(retry 규칙) / 보고 필요→⑤ / 종결 시도→잔여 검사(walk).
- **동의 바인딩(CP2)**: user "yes"는 직전 pin된 제안 id에만 결합 — 검증 안 된 제안은 프론트가 발화 자체를 못 하므로(2행 참조) **오염-세탁 경로 소멸**.
- **조립**: 최종 tool call = pin된 값들의 결정론 조립(전문가 출력 그대로·재생성 없음) → CP3 게이트(정책)만 통과.
- 오케스트레이터는 **판단하지 않는다** — 열거·기록·조립·라우팅만. 의미 판단은 전부 전문가(LLM) 몫(동결 금지·[[05]] Q2).

## 5. 단계적 검증 계획 (비용 규율·전면 재작성 금지)
- **Phase A (무료·게이트)**: E-ISO full 질량으로 전문가별 좌석 판정(질량<5sims 좌석은 기각) + ①③의 격리 정확도 프로브(기존 c51/E-ISO 인프라 재사용).
- **Phase B (프로토타입·최소쌍)**: **오케스트레이터 pin ledger + ③ Operand-선택기**만 먼저(최대 질량·T5-B 합류) — 기존 unified regen 위에 얹는 증분(대체 아님). arm: COMP+D vs COMP+D+pin③. 판정 = t61형 flip 0 ∧ **p4 회복**(pin이 분산 차단) ∧ Δspurious≤0.
- **Phase C (확장)**: Phase B GO 시 ①(intent-파서)·⑤(reporter) 추가 — 각각 단독 귀속 arm.
- **Phase D**: ②④는 E-PLAN·feasibility(ENDGAME L3/L4)가 이미 커버 — 그 결과를 이 프레임에 흡수(재구축 금지).
- **리스크(정직)**: 서브콜 수↑=턴당 토큰↑(측정) · 전문가 인터페이스 오류(스펙 스키마 검증으로) · **over-engineering**([[13]]) — Phase 게이트가 방어. 실패 시 후퇴선 = CP+pin만 유지(§1b)·전문가 없이.
