## 6-2. ★더 큰 위험 — **범주 오매핑이 값으로 증폭된다**

024 가 실제로 낸 인자는 `spend_category=operations` 였다(작업용 트럭 구매를 *operations* 로 매핑).
그 인자 그대로 엔진을 돌리면:
```
Business Gold Rewards Card       **800.00** = 2.5% (category rate) x 40000 minus annual_fee 200
Business Bronze Rewards Card       400.00 = 1.0% (base rate) x 40000            ← gold
```
⇒ **값 주석이 gold 에서 멀어지는 쪽을 가리킨다.** 벤치의 gold 가 Bronze 라는 것은 트럭 구매가
   *operations* 가 **아니라는** 뜻인데, 우리 주석은 그 잘못된 범주 위에서 **자신 있게 곱셈을 해 준다**.

이것은 **닫을 수 없는 자리**다 — 범주 소속은 **열린 술어**이고 판정 주체는 LLM 이다([[22]]·[[66]]).
엔진이 *"트럭은 operations 가 아니다"* 를 알게 하면 그 순간 도메인 입법이고 [[23]] 위반이다.

남는 선택지(전부 **미측정**):
```
⒜ 그대로 두고 라이브 A/B 에서 재기 — 범주가 맞는 사례에서 얻고 틀린 사례에서 잃는 순합을 본다
⒝ 범주 요율과 기본 요율의 값을 **둘 다** 붙이기 — 조건부(C187(c) unverified)와 같은 모양.
   *"범주가 맞으면 800 · 아니면 400"* 을 보이면 판단은 모델에 남고 산술만 우리가 한다
⒞ 범주가 **한 행에만** 존재할 때는 주석을 보류 — 과잉 일반화 위험(다른 태스크를 죽인다)
```
⇒ **⒝ 가 이 프로젝트의 선례(조건부 값 3-값 처리)와 같은 모양**이지만, 고르기 전에 [[70]] 양방향을 재야
   한다. 이 문서는 그 선택을 **열어 둔 채** 끝낸다.

# §7 ⒝안(두 값 병기) 측정 — **판정선 미달** (`x444` · 48 문항)

> 사용자 지시 *"B안으로 가라"* · 배선은 했고(`t2_compute` 두 값 병기) **측정은 통과하지 못했다**.

## 7-1. 설계

일부러 **틀린 범주**로 주석을 만들고(손님이 말한 것은 `cat_true`, 주석이 계산한 것은 `cat_wrong`),
두 argmax 가 **갈리는 문항만** 채택했다(48). 팔 = `E_one`(값 하나) ↔ `F_two`(값 둘 · 엔진 문면 그대로).
사전 고정 판정: **`따라감(F_two) < 따라감(E_one)`, 차 8/48 이상만 읽는다.**

## 7-2. 결과

```
E_one   따라감 28 (0.58) · 정직  9 (0.19) · 기타 11
F_two   따라감 26 (0.54) · 정직 13 (0.27) · 기타  9
Δ따라감 **−2** · Δ정직 **+4**        (판정선 8/48)
뒤집힘: E 따라감 → F 안 따라감 **8** ↔ 반대 방향 **6**  (거의 상쇄)
```
⇒ **병기는 오매핑을 막지 못한다.** 두 값을 나란히 보여줘도 모델은 **큰 쪽 수를 따라간다**(0.58 → 0.54).
   조건문을 읽고 판단을 되찾는 일은 일어나지 않았다.

## 7-3. 그래서 남은 선택지 (⒝ 는 탈락)

```
⒜ 그대로 두고 라이브 A/B 순합       위험이 이제 정량화됐다 — 범주가 틀린 상황에서 **~55%** 가 부풀린 값을 따라간다
⒞ 범주가 얇을 때 보류               미측정
⒟ ★**범주 분기를 아예 안 쓴다**     기본 요율 값만 계산해 붙이고, 범주 보너스는 지금처럼 **요율 조회로만** 둔다
                                    — C562 가 특정한 결손(곱셈·뺄셈)은 그대로 메우고, C565 가 잰 위험
                                      (오매핑 증폭)은 **구조적으로 못 생긴다**. 대신 범주가 맞는 사례의
                                      이득을 얼마나 잃는지는 **미측정**(x441 격자에 `G_base` 팔 하나면 잰다)
```
★현재 코드 상태: 두 값 병기가 **들어가 있다**. 그러나 위 측정이 **채택 근거를 주지 못했으므로**,
  이것을 *"검증된 개선"* 으로 인용하면 안 된다. 라이브 A/B 를 돌린다면 이 부분은 **미채택 상태의 배선**으로
  기록하고, ⒟ 를 먼저 재는 편이 순서에 맞다([[62]]).

# §8 ⒟안(범주 분기 없음) 측정 — 위험을 **구조적으로** 없애고 이득의 **60%** 를 지킨다

```
C_nopat    5/48 (0.10)   패턴 없음(부정통제)

## 8-2. 어디서 얻고 어디서 잃나 (분해)

```

⚠**값만 읽는 모델의 구조적 상한은 34/48 = 0.71** 이다(기본 요율 argmax 가 참 정답과 일치하는 문항 수).
G_base 는 **35/48** — 즉 모델은 사실상 **값을 읽을 뿐**이고, 행 텍스트에 남아 있는 범주 요율을 스스로
써서 되찾은 것은 **14 중 2** 뿐이다.

## 8-3. 그래서 선택은 이렇게 정량화된다 ([[70]] 양방향)

| 안 | 이득(격자) | 위험 |

| **⒟ 기본 요율만** | **+17/48**(0.38 → 0.73) | **구조적으로 0** — 범주 요율로 곱하지 않으므로 증폭될 수가 없다 |

## 9-1. 그래서 무엇이 틀렸나

§6-2·§7 은 이 자리를 *"열린 술어라 닫을 수 없다"* 로 적었다. **틀렸다.** 그것은 **KB 를 안 뒤지고**
내린 판정이었다. 정확한 진술은 이렇다:

```
범주 소속은 **KB 산문에 근거가 있는 판정**이다 — 열린 술어가 아니라 **근거를 안 읽은 것**이다.
024 의 실패는 "판단 불가"가 아니라 **`spend_category=operations` 를 근거 없이 낸 것**이다.
```
그리고 [[23]] 은 **정책·KB 산문에서 나온 것을 금지하지 않는다** — 금지되는 것은 **gold 를 보고 쓰는 것**이다.

## 9-2. ⒠안 — 근거 없는 범주는 곱하지 않는다 (신규·미측정)

이 프로젝트에 **이미 있는 모양**을 그대로 쓴다(C45 동형·[[22]] 근거-우선 formalize·[[59]]ⓐ):

```
모델이 `spend_category` 를 낼 때 **그 근거 인용**(KB 축자 한 줄)을 같이 낸다
엔진은 그 인용이 **원문에 실재하는지만** 확인한다 — 뜻은 해석하지 않는다
실재하면 범주 요율로 곱하고, 못 대면 **기본 요율로만** 계산한다(⒟로 자동 강등)
```
⇒ 범주가 진짜일 때의 이득(⒜ 0.98)을 지키면서 오매핑 증폭(C566 ~55%)의 **경로를 막는다**.
⚠**아직 아무것도 측정되지 않았다.** ⒠는 지금 **설계뿐**이고, ⒜/⒟처럼 격자에서 먼저 재야 한다([[62]]).

# §11 사용자 물음 — *"범주 선택할 때 KB 검색 내용이 전달되고 있나?"* ⇒ **아니다**

전수(326 sim·오프라인·LLM 0):
```
fit 호출 **이전**의 KB 검색 횟수 = **0 회가 251/326 (77%)**

```
⇒ 모델은 **문서를 한 편도 안 받은 상태**에서 `spend_category` 를 고른다. x445 의 *"95% 무근거"* 는
   이것의 따름결과다.

**세 가지가 즉시 따라온다.**
1. ⒠(인용 요구)는 그 시점에 **구조적으로 만족 불가능**하다 — 인용할 문서가 문맥에 없다.
   (요구 자체가 **검색을 유발**하는지는 별개이고 **미측정**이다.)

3. ⒟(기본 요율만)는 **범주를 안 쓰므로** 이 문제를 통째로 우회한다 — 오늘 A/B 의 treat 팔이 ⒟인 이유다.
