## §1 문제 (C543ⓐⓑ)

`T2_VERDICT_CARRY`(VC)는 **결정점에 도달하면 무조건** 발화한다. 073(수수료 정정)처럼 **고를 것이
없는 태스크**에서도 축이 열리고, `후보 10 · OK 10 · VIOLATES 0` 의 **무정보 판정**을 낸다(C535 와
같은 가족 = 범위 밖 발화). 그 발화가 결정 경로를 한 번 돌며 **쓰기를 밀어낸다**.

| 런 | VC | EL | 073 결과 |
|---|---|---|---|
| t7314 ctl | 0 | 0 | **1.0** |
| t7316 vconly | **1** | 0 | 0.0 |
| t7314 treat | 1 | 1 | 0.0 |

`WRITE_SUB` ctl **31** ↔ treat **19**. **회귀가 아니라 레버가 이 태스크에서 음수**다.

## §2 왜 조건으로 못 잘랐나 — 세 갈래의 사망 진단 (C543ⓒ)

| 시도 | 결과 | 사인 |
|---|---|---|
| ①LLM 라벨(선택/비선택) | CHOOSE 6/12 · NOT_CHOOSE 15/20 | **국면 자기평가는 LLM 이 못 하는 부류**([[66]]) — 인용검산 32/32 로 기구는 멀쩡한데 라벨이 흔들린다 |
| ②스키마 술어(인자 이름) | 추출 0건(항상 끔) | 계기 실패 |
| ③선언 술어 `applies_when` + pending | v2 77% · v3 43/43 항상 켬 | **pending 은 "부를 뻔한 것"이 아니라 "부를 수 있는 것"** 이라 전 도구가 들어온다 |

**★구조적 결론**: A3 의 `applies_to`/`applies_when` 관용구는 **호출-트리거**다 — 모델이 그 도구를
*부르려 할 때* 검사한다. VC 는 **호출 이전에 밀어넣는 push 레버**라 그 관용구로 조건을 만들 수 없다.
조건을 만들려면 **레버를 관용구가 사는 자리로 옮기는 수밖에 없다.**

## §3 설계 — `T2_VERDICT_GATE` (호출-트리거 VC)

### 3.1 트리거 = 이미 있는 선언 (새 A2 키 0)

`banking_knowledge.specific.json` `write_arg_enum[0]` 이 **후보를 먹는 호출**을 이미 선언해 두었다:

```
applies_to    call_discoverable_agent_tool
applies_when  {arg: agent_tool_name, prefix: open_bank_account}
arg           account_class            ← 후보를 먹는 인자
group_arg     account_type             ← 축
group_map     {checking: checking_accounts, ...}  ← 축 → 문서군(닫힌 사상)
```

⇒ **비-선택 태스크에는 트리거가 존재하지 않는다.** 073 은 이 호출을 내지 않으므로 VC 는 한 번도
발화하지 않고 궤적은 ctl 과 **바이트 동일**이다. 조건이 기계적이고([[22]] 닫힌 술어) 모든 경우에
같은 방식으로 적용된다(사용자 지시). **케이스 열거 0 · 태스크 이름 0**([[66]]).

### 3.2 자리 = `T2_WRITE_ARG_ENUM` 소속 검사 **직후**

현행 코드는 제출값이 공식 명칭 집합 안이면 `continue` 하며 *"선택이 옳은지는 우리가 판정하지
않는다"* 고 적어 놓았다. 판정하는 것은 여전히 **LLM** 이고, 엔진은 그 판정을 **맞대기만** 한다:

```
집합 밖  → 현행 ENUM deny (이름이 없다 · 후보 명단)          [불변]
집합 안  → ★VG: verdict_lines(군) 중 제출값의 판정을 읽는다
           VIOLATES  → deny + 그 줄(이유 + 문서 인용) + OK 후보 명단
           OK/UNCLEAR/근거 미검산/판정 없음 → 통과(침묵)
```

### 3.3 계약 (엔진이 하는 일 전부)

1. `group_arg` 값 → `group_map` → 문서군 `_g` — **닫힌 사상 조회**(해석 0)
2. 요구 인용 확보: `sub_requirements`(LLM) → `quote_in`(존재확인만·C45 동형)
3. `verdict_lines(_g)`(LLM) → 후보별 `OK|VIOLATES|UNCLEAR` + 인용
4. 제출값 = 그 후보의 표시명인지 **문자열 동치**(`_slug_disp` 규약·기존 함수 재사용)
5. `VIOLATES` 면 deny 문면 = **LLM 이 쓴 줄 축자** + 남은 `OK` 후보 명단

엔진은 어느 것이 옳은지 **고르지 않는다**. 후보를 **제거하지도 않는다**.

### 3.4 fail-safe (모르면 막지 않는다 · [[25]])

- 요구 인용 0건 → 침묵 (판별자가 없으면 판정도 없다)
- `verdict_lines` 빈 목록 / 후보 상한 초과 / 코퍼스 부재 → 침묵
- 제출값이 판정 줄에 없음 · `UNCLEAR` · **근거 인용 미검산** → 침묵
- sim 당 상한 `T2_VERDICT_GATE_CAP`(기본 **1**) — 같은 거부를 반복하는 livelock 금지(052 전례)
- 예외는 전부 삼키고 침묵 → OFF 와 **바이트 동일**

### 3.5 문면 ([[64]] 거부는 무엇이 틀렸나 + 무엇을 하면 풀리나)

```
Error: [VERDICT] '{val}' conflicts with the customer's stated requirement.
{verdict_line}                      ← LLM 판정 + 문서 인용 축자
Candidates on file that do NOT conflict: {ok_names}
Pick one of those verbatim (or explain to the customer why none fits) and call the tool again.
```
문면은 A2 오버라이드 가능(`verdict_gate_feedback`) — 미선언이면 위 도메인-어휘 0 기본문.

## §5 부작용 계측 (§1.3 — 부작용 없는 레버는 없다)

| 부작용 | 계측 | 사전 기준 |
|---|---|---|
| **over-block**(옳은 write 를 막는다) | 거부된 값이 gold 인자와 일치하는 건수 | **Δspurious ≤ 0** — gold 값 오차단 **1건이라도 나오면 GO 없음** |
| 지연 | 후보 8~10 × 서브 1회 = 그 턴 1회, sim 당 상한 1 | steps·wall-clock 증가 t7314 대비 보고 |
| livelock | 같은 거부 반복 | 상한 1 로 구조적 불가 |
| 침묵(죽은 레버) | `[T2_VERDICT_GATE]` 발화·skip 사유 stderr 인쇄 | 트리거 자리에서 skip 사유가 **항상 같은 값**이면 계기 무효 선언([[C543ⓕ]] 규칙) |

## §6 사전 고정 판정 (런 전에 못 박는다)

1. **073**: `vgate` 팔(VC0·VG1·EL0)이 **1.0** 이어야 한다 — 트리거 부재 ⇒ ctl 동치. 아니면 설계 실패.
2. **트리거 자리**(`open_bank_account` 호출이 있는 태스크): `[T2_VERDICT_GATE]` 가 **발화 또는 명시적
   skip 사유**를 남겨야 한다. 침묵 0줄이면 死배선([[67]] `t2_liveness` 0단계).
3. **pass 로 레버를 판정하지 않는다**(n 작음). 판정은 짝비교 + 원인 지표.
4. push VC(`T2_VERDICT_CARRY`)와 **동시에 켜지 않는다** — 같은 판정을 두 번 사는 것이고 귀속이 섞인다.
   ⇒ `run_one.sh` 에 팔 `vgate` 신설(VC0 VG1 EL0) · `vgate_el`(VC0 VG1 EL1).
