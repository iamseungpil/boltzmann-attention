## §0. 한 줄 — 목표의 정확한 정의

**"검증 없는 단정 = 0"은 "단정 = 0"이 아니다.** 에이전트의 모든 단정(assertion)을

$$A \;=\; \underbrace{A_{\text{verified}}}_{\text{결정론 검증 통과}} \;\cup\; \underbrace{A_{\text{INFER}}}_{\text{명시-추론 표시(가시화)}} \;\cup\; \underbrace{A_{\text{ASK}}}_{\text{질문으로 전환}} \;\cup\; \underbrace{A_{\text{unmarked}}}_{\text{무표시 단정}}$$

로 분할하고, **집행-가능한 추출 범위 안에서 $A_{\text{unmarked}} = 0$** 을 만드는 것이 목표다. 이것은 C45가 tool-call 인자
하나의 표면에서 이미 실증한 것(출처 선언 강제 + 갈래별 결정론 검증 → 날조 67→0%·over-block 0·Δspurious 0 [M])의
**전-채널 일반화**다. 제1원리(등대 §1.3)가 이 아키텍처 자신에게도 적용된다: 검증기마다 반대편 계측(Δspurious≤0·
over-block·Δtme)을 달지 않은 "0-단정" 주장은 그 자체가 검증 없는 단정이다.

세 정리 구조:
- **§1 완전성**: 단정이 들어오는 표면은 4개로 유한하고, 10-케이스는 그 4표면의 분할이다.
- **§2 건전성**: 각 표면×케이스에 결정론 검증 술어가 배정되고, 검증-불가 단정은 INFER-표시 또는 ASK-전환으로 *선언 강제*된다.
- **§3 불완전성**: 이 아키텍처가 원리적으로 못 닫는 것(추출기 recall·성향-층·검증기 역효과·간섭 비용)을 정직하게 계상한다.

## §1. 완전성(Completeness) 정리 — 단정 표면은 4개로 유한하다

### §1.1 논거: 에이전트-환경 인터페이스의 형식적 열거

tau2형 에이전트 루프에서 에이전트의 턴-출력은 메시지 스키마상 정확히 3성분이다:
`AssistantMessage = (tool_calls[], content, stop?)`. 에이전트가 세계에 영향을 주는 경로는 이 스키마를 벗어날 수 없다
(환경 상태 변경 = tool_call 실행 · 사용자 신념 변경 = content 발화 · 태스크 상태 확정 = 종결). 입력 방향으로는
에이전트 내부 상태에 명제가 들어오는 유일한 통로가 메시지 히스토리(user 발화·tool 출력)다. "단정"을 **세계-상태
명제를 참으로 커밋하는 행위**로 정의하면, 커밋 지점은 출력 3 + 수용 1 = 4로 전수 열거된다:

| 표면 | 정의 | 커밋 형식 | C45 기존 커버 |
|---|---|---|---|
| **S1 tool_call(name, args)** | 기계-해석 채널. name = "이 도구가 존재하고 이 목적의 producer다", args = "이 값이 옳은 operand다" | 구조화(스키마 有) | ✅ **args만**(C45의 한정판) |
| **S2 발화의 추출-가능 주장** | NL 채널. 수치·정책·DB-상태·자기-능력·완료-보고 | 비구조(추출 필요) | ✗ |
| **S3 종결 결정** | 암묵 채널. 더 행동하지 않음 = "잔여 항목 = ∅" 단정 | **행동의 부재**(추출 대상조차 없음) | ✗ |
| **S4 타자-단정의 수용** | 입력 채널. user/tool의 오류 명제를 무검증 채택 → 이후 자기 단정으로 세탁 | 후속 행동/발화에 잠복 | ✗ |

- S3이 표면인 이유: 종결은 발화가 없어도 커밋이다. telecom "exhausted all steps"(완료 오판정·UNIFIED_TAXONOMY
  완결-자기검증)와 coverage 미완(C64 A클래스 ≈8 task)은 둘 다 "잔여 없음"이라는 **무표시 단정의 실측 사례**다.
- S4가 표면인 이유: 수용은 출력이 아니지만, 수용된 오류는 반드시 S1~S3 중 하나로 재출력된다. 그때 검증하면
  되지 않느냐는 반론에 대한 답: **고착(t61형·C56 user-sim 오확인 고착)은 제안→동의 시점에 일어나며, 하류 검증기가
  개입해도 이미 대화-경로가 오염돼 있다**(C61 E-ISO ①: 오염/경로 몫 ≈20% [M]). 수용 시점 검증(CP1/CP2)이 구조적으로
  필요하다 — 표면으로 세는 것이 맞다.
- **완전성의 범위 한정(정직)**: 이 열거는 *커밋 지점*의 완전성이다. S2/S4 내부에서 "어떤 명제가 주장되었는가"의
  추출은 NL 의미론이며 완전하지 않다 — §3.1로 넘긴다. 즉 정리는 "표면 4개 밖의 단정은 없다"이지
  "4표면 위의 모든 단정을 검출한다"가 아니다.

### §1.2 10-케이스는 4표면의 분할이다

| 케이스 | 내용 | 주 표면 | 실측 앵커(등급) |
|---|---|---|---|
| (a) 인자-id | 없는/틀린 id를 args에 | **S1** | C43 정박치환·C45 67→0% [M] |
| (b) 인자-free-text | 주소 등 자유텍스트 날조 (환경이 타입상 못 잡음) | **S1** | C24 ours 5/o4 0 [M]·C65 rescue 입도 구멍 [M] |
| (c) 도구명 | 없는 도구 호출 | **S1** | banking 도구명 날조 61 sims(`BANKING_FLOOR_LEVER_FIT`) [M] |
| (d) DB-state 단정 | "취소됐습니다"류 상태 주장 (write 없이/모순되게) | **S2** | t57형 허위 발화(C64·CENSUS §3b) [M] |
| (e) 자기-능력 | "수동으로 조정해 드리겠다" — 도구집합 밖 행위 주장 | **S2** | C63 impasse-시 발명형 escape [M·정독 3/3] |
| (f) 발화-수치 | count/총액 NL 보고 오류 | **S2** | C64 G클래스 NL_ONLY 13 [M] |
| (g) 발화-정책 | 정책 사실을 틀리게 발화 ("gift card로 환불됩니다") | **S2** | t57(부록 W NL-POLICY-PROV 표적) [M] |
| (h) 커버리지/완료 | "다 했다" 보고·조용한 종결 | **S3**(보고형은 S2 겸) | telecom 완료-오판정·C64 A클래스 [M] |
| (i) 시간 | "가장 최근" 등 시간-명제 — 재료(날짜 필드) 부재인데 판단 | **S1**(시간-파생 인자)·S2 겸 | t71 argmax(date) unresolvable·4/4 오적용 (C56) [M] |
| (j) confabulation-수용 | user-sim 오확인/허위 프레임·tool 오류의 무검증 채택 | **S4** | C56 t71 오확인 고착·C28 gold-모순 user·APRIME 허위 프레임 [M] |

- **분할성**: 각 케이스의 *주* 표면은 유일하다(커밋 형식이 다름 — 구조화 args / NL 발화 / 행동 부재 / 입력 채택).
  (h)·(i)의 겸-표기는 같은 명제가 두 표면에서 *각각* 커밋될 수 있음을 뜻하며(완료를 보고하고 종결·시간 판단을
  발화하고 인자화), 그 경우 **두 커밋 각각이 자기 표면의 검증기를 거친다** — 이중귀속이 아니라 이중커밋이다.
- **피복성**: S1 = (a)(b)(c)(i-인자) · S2 = (d)(e)(f)(g)(+h-보고·i-발화) · S3 = (h) · S4 = (j) — 4표면 전부가
  케이스로 점유되고, 케이스 밖 표면은 없다. 역방향(표면에 있는데 10-케이스 밖인 단정)은 존재한다 — 예: S2의
  일반 사실 주장("이 상품은 방수입니다"). 10-케이스는 **실측된 실패 질량이 있는 부분집합**이지 S2의 전부가 아니다.
  이 잔여는 §2.4의 일반 규칙(무-앵커 주장 = INFER-표시 대상)으로 흡수되고, 추출 한계는 §3.1로 간다.

## §2. 건전성(Soundness) 정리 — 표면별 검증기 배정

### §2.0 개입 채널 축 (약어 정의·로컬)

정본 채널 좌표는 `NEXT_LEVER_GEN §0a`(+특허 taxonomy 부록 X·로컬 전용 [[32]] — 본 문서는 repo 문서로만 재구성).
본 문서에서 쓰는 채널 6종(서술형 이름이 정본·문자표기는 본 문서 로컬):

| 채널 | 서술형 이름 | 성질 · 실측 근거 |
|---|---|---|
| ch-R | **deny-regen**(생성-레벨 deny→피드백 재생성) | 비커밋 버퍼·복구절 제시. C45/C53 GO — 단 턴-파기가 p4 매도(C53 −5.3pp)·대화-교란(C62 ②) |
| ch-S | **silent 제자리 치환** | 인자만 교체·대화 완전 불변·replay-clean. C62 ③("정보는 무해·전달 기전이 유해")의 처방 |
| ch-A | **read-증강 주석** | tool 출력에 결정론 주석(calc/nested). 창-오염 리스크(C43 재료화) |
| ch-G | **read강제**(gather 유도) | §1.5 Q5: **읽기만 강제 가능·쓰기 강제 절대 금지**. C31: 주입보다 강제 조회가 학습-정합적 |
| ch-M | **비커밋 리마인더**(작업버퍼·CP5 walk형) | 결정점 직전 1회·히스토리 미오염. C61 CP 재주입 오염 소폭 잔존 |
| ch-D | **decode제약**(guided decoding) | 생성-시점 유한집합 제약. 현 스택 미점유(E-XGRAMMAR [D]) — abstain 봉쇄 위험 시 ASK/null 분기 필수 |

부작용-최소 선택의 일반 원리(실측 유도): **판정이 같아도 채널이 다르면 부작용이 다르다**(C60/C62). 우선순위 =
결정 재개방을 안 하는 것(ch-S·ch-A·ch-M) ≻ 재개방하되 flagged 부분만(ch-R+pin) ≻ 생성 자체 제약(ch-D·유한집합일 때만).
프롬프트/정책 텍스트 채널은 죽었다([[42]]·C30·C41 — 여기 열거에서 제외).

### §2.1 핵심 일반화 — 커밋-시점 출처선언 슬롯 (C45의 전-채널판)

C45의 기전을 표면-불변으로 재기술하면: **커밋마다 출처 슬롯을 강제하고, 슬롯 값별로 결정론 검증기를 단다.**

| 슬롯 | 의미 | 검증 술어 (전부 decidable·DB 주입 0) |
|---|---|---|
| GET | 도구가 산출할/산출한 값 | 지목 도구가 그 인자·주장의 producer (A2 `{인자→producer}` 매핑) |
| FIND | 문맥에 실재하는 값 | 값 ∈ {사용자 발화 ∪ 도구 출력} (문자열/정규화 대조) |
| INFER | 문맥 값에서 유도 | 유도식이 형식화되면 결정론 재계산 일치 / 형식화 불가면 **표시만(가시화)** — 통과시키되 계측·마킹 |
| ASK | 사용자만 아는 값 | producer가 **없어야** 함 (C48 위계: FIND→GET→DISAMBIGUATE→ASK — ASK는 금지가 아니라 최후위) |

**"0으로 만든다"의 조작적 정의**: 검증기가 참을 확인 못 하는 단정은 (i) INFER-표시로 강등돼 사용자·계측에 가시화되거나
(ii) ASK로 전환된다. 어느 쪽도 아닌 커밋(무표시 단정)은 deny-regen 대상. C45 실측이 이 분할의 실행 가능성을
tool-인자에서 증명했다: D″ arm에서 전 커밋이 {검증통과, GET폴백, 재발화}로 소진되고 무표시 날조 0.

| **(b) 인자-free-text (S1)** | 문맥-실재(정규화 대조·빈값-제외) | ✅ (경계: 패러프레이즈 잔여 — C58 variant .667) | ch-R per-arg (C65: per-call `break`가 구멍 — **PROV-RESCUE-PERARG**) | ◑ 부분구현·**입도 구멍 봉합 설계됨**(C65·무료) |

### §2.3 건전성 조건 (GO 조건의 일반형)

각 검증기 V에 대해 (RESEARCH_MASTER §4 공통 GO의 일반화):
1. **무-오차단**: over-block = 0 (정당 커밋을 막지 않음 — C45는 전수 2,650으로 증명·신규 검증기도 V0 census 필수)
2. **무-개악**: Δspurious ≤ 0 (원본이 맞던 결정을 뒤집지 않음 — pin이 구조적으로 보장(§3.4))
3. **예산 보존**: Δtme ≤ 0 (재발화 예산이 pass를 깎지 않음 — C53 tme 1/456으로 선례)
4. **위반 0 유지**: 기존 게이트(compliance)와의 합성에서 위반 재유입 0
이 4조건 미충족 검증기는 **개별 제거**(ENDGAME 죽은-레버 규율) — "0-단정"이라는 목표가 검증기 증식의 면죄부가 되지 않는다.

### §2.4 잔여 흡수 규칙 (10-케이스 밖 S2 단정)

케이스-특화 검증기가 없는 S2 주장(일반 사실 등)은: 추출기가 잡으면 → 출처 슬롯 강제(§2.1) → FIND/GET 검증 or
INFER-표시. 추출기가 못 잡으면 → §3.1 한계로 정직 계상. **어떤 경우에도 "검증기가 없으니 통과"가 아니라
"추출되면 표시 없이는 통과 불가"가 규칙**이다.

## §3. 불완전성의 정직 계상 (한계 정리)

### §3.1 주장-추출기의 recall 한계 — NL 의미 전체는 추출 불가

S2/S4의 검증은 "주장 추출 → 대조" 2단이고, 추출기는 패턴-사전(A2 어휘 트리거)이다. 이것은 원리적으로 불완전하다:
- **C58 트릭 경계와 동일 이유**: slot-대조기의 variant 축 .667(무증거 구간 28% [M]) — 패러프레이즈·간접 화법은
  사전 밖이다. 사전을 벤치-분포로 살찌우면 **통계-디폴트와 동형인 전이불가 트릭**이 된다(C58: 통계 디폴트 =
  벤치-분포의 숨은 일·rand .065 vs LOTO .185). ⇒ **추출 어휘는 정책-도출·스키마-도출만 허용**(A2 규약) —
  분포-학습된 트리거는 ablation 분리 없이 금지.
- 귀결: $A_{\text{unmarked}} = 0$의 보장 범위는 **"추출기가 잡는 단정"에 한정**된다. 정리의 정확한 형태:
  *검출-가능 단정에 대해 무표시 통과 0* + *검출-불가 질량의 상한을 계측으로 보고*(예: NL judge와 추출기의
  불일치율을 상시 카운터로 — 닫는 게 아니라 재는 것).

### §3.2 표시-준수 자체가 모델 성향이다 — 집행 가능성의 경계

INFER-표시·ASK-전환·deny-복구절 준수는 결국 모델이 따라야 성립하고, **불응은 실측된 현상**이다:
- deny 피드백 불응: `APRIME_REGRESSION_FORENSIC` E7(deny 4회 불응·기아) · `T27_T103_PERSTEP`(L2가 3회 정확히
  gold read를 지목해도 기지-주문 재조회로 **오해독 불응** — cap은 한도만 바꾸지 행동판을 못 바꿈) [M]
- 검증-우회 escape: C63 — env/게이트 반복-거부 후 "수동 조정" 발명형 escape-write(t93·t95형) [M·정독 3/3]
- 일반 법칙: [[42]]·C30(정책 명문 "do not make up"에도 ours 91 vs frontier 1·3) — **prompt-수준 규범은 성향을 못 닫는다**.
⇒ 집행 가능한 것 = **검출-가능한 위반의 결정론 처리**(deny·치환·라우팅)까지. 표시 규범의 *내면화*(불응 감소·
INFER 남용 억제)는 성향-층 = learn 몫(E6′·[[42]] SFT설치+penalty)이다. 아키텍처는 성향을 **관측 가능하게**
만들 뿐(마커·카운터), 성향을 소거한다고 주장하지 않는다.

### §3.4 간섭 비용과 CP/pin 통합 — 검증기 수는 공짜가 아니다

검증기 n개의 간섭은 쌍으로 늘고(O(n²)·실측: prov⊕DISAMB 미완 상쇄 C60·이중발화 관할 문제 NEXT_LEVER_GEN §0c),
"레버가 결정 전체를 재개방"하는 것이 주 기전이다(ENDGAME §1b (a)). 처방은 규율이 아니라 구조:

**본 아키텍처의 전 검증기는 CP1~CP5 좌석에 배정되고 pin 규칙을 공유한다** (`SCAFFOLD_ENDGAME §1b` 승계):

| CP 좌석 | 배정되는 본 문서 검증기 |
|---|---|
| CP1 제안-발화 전 | (d)(e)(g) 발화-provenance·(j)의 제안-수준 검증 |
| CP2 동의-해석 | (j) 동의=CP1-통과 제안에만 유효 |
| CP3 도구호출 전 | (a)(b)(c)(i) — 기존 unified regen 체인(게이트·prov·DISAMB)에 합류·**레버당 결정유형 1 서로소 관할** |
| CP4 결과 수신 후 | (j)의 tool-오류 수용 차단·retry 기록 |
| CP5 종결 전 | (h) walk ledger-diff·잔여 가시화 |

- **pin**: CP 통과 커밋은 결정론 상태로 고정 — 이후 어떤 검증기의 재발화도 flagged 부분만 수정 가능(통과분 변경 시
  결정론 복원 = arg-머지 일반화). 간섭의 지배 경로(재개방)를 구조로 차단.
- **단일 fire 규약**: 한 결정점 = 검증 체인 1회 통과(관할이 서로소이므로 체인은 합성이지 경쟁이 아님) —
  이중발화·이중예산 금지(NEXT_LEVER_GEN §2.4 승계).
- 그래도 남는 비용(정직): CP 체인 자체의 지연·마커 부피, pin의 경직성(pin된 오답은 pin이 보호한다 — pin은
  Δspurious를 *검증기 간섭*으로부터만 지키며, 최초 통과가 오판이면 고착. 완화 = pin 해제 조건을 "새 read가
  대조원을 갱신했을 때"로 한정하는 재검 규칙 — [D]·V0 대상).
