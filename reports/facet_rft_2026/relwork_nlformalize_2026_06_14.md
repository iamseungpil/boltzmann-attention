## 1. Prose2Policy / P2P — `2603.15799` (the closest TASK analog) — FULL FORENSIC READ

**Verified identity.** *Prose2Policy (P2P): A Practical LLM Pipeline for Translating Natural-Language Access Policies into Executable Rego.* **Vatsal Gupta, Darshan Sreenivasamurthy — both Apple, Cupertino.** arXiv **`2603.15799v1`, 16 Mar 2026**, cs.AI. **6 pages**; ACM reference format targeting **SACMAT** ("Code … will be made publicly available upon acceptance, in accordance with SACMAT policy"). This is a **tool/demo paper**, not a model/benchmark paper.

**Exact task (verbatim).** "translates natural-language access control policies (NLACPs) into executable Rego code (the policy language of Open Policy Agent, OPA)." Pipeline (verbatim): "policy detection, component extraction, schema validation, linting, compilation, automatic test generation and execution." Component extraction emits **DSARCP** = "decision, subject, action, resource, condition, and purpose … structured JSON for each recognized policy statement." Rego is emitted with **deny-by-default semantics** and DSARCP annotations for auditability.

**Models — NOT prompt-only-frontier-unspecified; it is dual-provider frontier API, ZERO training.** Figure 1 (architecture) shows **"OpenAI Provider"** and **"Anthropic Provider"** boxes under "Centralized Prompt Management." §5.4: "Users can select among LLM providers based on cost, accuracy, or privacy requirements." There is **no fine-tuning, no distillation, no small/on-prem model** anywhere in the paper. It is a prompt-chaining orchestration over hosted frontier APIs. §3.1 explicitly concedes non-determinism: "repeated runs on the same NLACP may yield different extracted representations or different (yet valid) Rego implementations … Prose2Policy therefore emphasizes deployability checks … rather than guaranteeing identical outputs across runs."

**The 95.3% number — exact denominator, read from §6 verbatim.** The ACRE dataset here is **not raw ACRE** — they "used the output file generated by RAGent, consisting of **485 access control statements**, as input." Then: "Because Prose2Policy filters out ambiguous statements without explicit authorization intent, it **accepted 389 statements** as valid NLACPs and generated Rego policies for them. … Of these, **18 policies failed** to produce valid Rego due to syntax-related issues … resulting in **371 successfully compiled policies leading to 95.3% (371/389) compile rate**."

⚠️ **Honest-denominator confirmed and worse than the prior summary implied.** The denominator is **389, not 485**. 96 statements (485−389 ≈ 19.8%) were filtered out *before* the compile-rate denominator. So the "95.3%" is **371/389 of the post-filter set = 371/485 = 76.5% of the inputs P2P was actually handed.** The "accepted" qualifier is a genuine selection effect (same family as the SOPBench honest-denominator issue we know). The authors are transparent about this and frame it as "lower acceptance rate but higher policy realism" — but a reviewer comparing systems must use 371/485, not 371/389.

**The test-pass numbers are self-graded.** §6 verbatim: "Each policy was evaluated using automatically generated positive and negative unit tests derived from its DSARCP elements. With the **LLM-driven test generation mechanism**, Prose2Policy achieved a **82.2% positive-test pass rate (305/371) and a 98.9% negative-test pass rate (367/371)**." And the rule-based mode is much weaker on positives: "When compared with rule-based test cases, Prose2Policy achieve **62.1% positive-test pass rate** and a 97.1% negative-test pass rate." The tests are LLM-written from the *same* DSARCP extraction that produced the Rego — i.e. **correlated-error self-grading**, which the authors themselves flag as future work: "Independent test generation: … we aim to decouple policy and test generation … to reduce the risk of correlated errors." So the high negative-test rate (98.9%) is the only relatively trustworthy signal (deny-by-default is structurally easy to satisfy); the 82.2% positive rate is partly an artifact of self-consistent test/code generation.

**Limitations / Future Work (verbatim, §7).** Five planned items, three of which are directly relevant to A2's open problems: "Advanced schema support … wildcards, pattern-based matching, and hierarchical structures"; "Enhanced support for complex policies … nested conditions, contextual variables, or references to external constants"; "**Deterministic and semantically stable outputs**: We plan to reduce run-to-run variability by enforcing canonical Rego templates … and by evaluating semantic equivalence across repeated runs." That last one is **P2P admitting it lacks exactly the deterministic-verifier-as-contract property A2 makes its centerpiece.** No transfer claim, no LODO, no sovereignty, no cross-domain. The whole paper is access-control allow/deny only.

**FIT to A2.** This is the **closest published system by task** (NL policy → executable enforcement code with auto-tests). It validates that the task is real and shippable (Apple built a UI for it). It maps to A2's **schema element** (DSARCP ≈ our GATE_SPEC component schema) and **verifier element** (opa test ≈ our replay), but P2P's verifier is *evaluation-side LLM-generated tests*, not a *fixed deterministic program that is the product*.

**ERROR / does it pre-empt us?** No — and the full read makes the gap **larger** than the abstract suggested. P2P occupies (task) but is empty on every A2 differentiator: (i) no distillation/small model — it is frontier-API prompt-chaining; (ii) no deterministic verifier-as-runtime-contract — it explicitly lists this as *future work*; (iii) no cross-domain transfer — single sub-domain (access-control allow/deny), and access-control is procedurally simpler than our SOP gates (no auth-ordering, no satisfier-tools, no ask/terminal); (iv) no sovereignty/air-gap — providers are hosted OpenAI/Anthropic. The honest 371/485=76.5% real-input compile rate also means the "95.3% looks strong" worry in our prior summary is overstated — the system rejects ~20% of inputs and self-grades its positive tests.

**rw-sentence.** *Prose2Policy (Apple, SACMAT'26) shows NL→executable-Rego is a real, shippable task via frontier-API prompt-chaining with auto-generated unit tests, but reports a selection-filtered 95.3% (371/389; 76.5% of raw inputs) compile rate, self-grades its 82.2% positive tests, and explicitly defers deterministic/semantically-stable outputs to future work — leaving A2's distilled-small-generator + fixed-deterministic-verifier-as-product + cross-domain/sovereignty combination entirely unoccupied.*

## 2. StepFun-Formalizer — `2508.04440` (the small-model formalizer precedent) — FULL READ incl. Table 3

**Verified identity.** *StepFun-Formalizer: Unlocking the Autoformalization Potential of LLMs Through Knowledge-Reasoning Fusion.* Wu, Huang, Wan, Peng, Shang, Cao, Qi, Zhang, Du, Yan, Hu (ICT-CAS + StepFun Inc.). arXiv **`2508.04440v3`, 26 Dec 2025**. **AAAI 2026** (copyright line: "Copyright © 2026, AAAI"). Code + 32B weights public on GitHub/HuggingFace.

**★ MAJOR CORRECTION to our prior summary: the 7B is NOT a weak afterthought — it beats every baseline and is competitive with the 32B.** Our prior summary said "headline is the 32B; the 7B number is not in the abstract." The **full Table 3 (BEq@1 / BEq@16, %)** tells a different and much stronger story for A2:

| Model | FormalMATH-Lite B@1 | F-Lite B@16 | ProverBench B@1 | PB B@16 | CombiBench B@1 |
|---|---|---|---|---|---|
| o3-pro (general) | 22.6 | 35.5 | 24.7 | 36.2 | 9.0 |
| Claude4-thinking | 20.8 | 32.2 | 24.4 | 35.6 | 9.7 |
| DeepSeek-R1-671B | 18.4 | 31.3 | 23.5 | 34.5 | 8.1 |
| Kimina-Autoformalizer-7B (specialized) | 35.1 | 60.2 | 13.3 | 25.3 | 2.6 |
| **StepFun-Formalizer-7B (ours)** | **38.3** | **61.2** | **25.1** | **37.9** | 5.2 |
| **StepFun-Formalizer-32B (ours)** | **40.5** | 59.3 | **26.7** | **38.5** | 6.9 |

Verbatim, §5.3: "even StepFun-Formalizer-**7B**, surpasses **every competing model on both benchmarks** [FormalMATH-Lite and ProverBench], offering a computational efficiency advantage: on FormalMATH-Lite it exceeds the previous best, Kimina-Autoformalizer-7B … and on ProverBench it outperforms large general-purpose models such as DeepSeek-R1-671B." And critically: "we observe that the **7B model performs comparably to or slightly better than the 32B model**, which may be due to the limited size of the data. The 32B model requires more data for further improvement." Note the 7B's **BEq@16 on FormalMATH-Lite (61.2) actually exceeds the 32B (59.3)**.

**This is the single strongest external support for A2's pre-registered headline.** A **7B specialized formalizer beats o3-pro, Claude4-thinking, and DeepSeek-R1-671B** on a formalization task. The size-frontier gap our P-A2-0b census measured (7B gate_recall 0.333 vs frontier) is a *distillation-deficit*, not a *capacity ceiling* — StepFun is direct evidence the capacity is there once the right data is distilled in. The fairness caveat: this is math autoformalization (closed-vocabulary Lean), and the 7B's edge depends on it being trained on in-distribution theorem-prover datasets; FormalMATH-Lite is **in-domain** (shares distribution with training), while ProverBench is OOD (37× n-gram OOD ratio, Table 9) and the 7B still wins there. CombiBench (hard combinatorics) remains low for all (7B=5.2) — the small-model edge is task-difficulty-dependent.

**ThinkingF method — the S1 template, read in full (§4, Figs 3/4/12).** Two data streams + two-stage SFT + RLVR:

- **Stream 1 — Knowledge Distillation With Selection (§4.1).** Start from **256K** informal problems (filtered from NuminaMath-1.5's 896K by manual rules: drop multi-subquestion, drop Geometry/Combinatorics, convert calc→proof). Prompt **Kimina-Autoformalizer to generate 16 candidates per problem**. Three-tier selection: (1) **Lean4 REPL syntax check**; (2) **majority voting via BEq equivalence classes** — keep one statement from the largest equivalence class (this is the survivor-aggregation idea); (3) **DeepSeek-V3 validity filter** removing tautologies/contradictions/trivial. Final: **~183K** knowledge pairs (253913→182548 after LLM selection). The knowledge stream's training target has an **empty reasoning span**: `<think>NULL</think><Formal Statement>` (Fig 3).
- **Stream 2 — Informal-to-Formal Reasoning Synthesis (§4.2).** Take human-annotated (informal, formal) seed pairs from theorem-prover datasets (MiniF2F 488, ProofNet 357, PutnamBench 659, Compfiles 115, FormalMATH-Train 5135 — Table 2). Prompt **Claude 3.7 Sonnet** with an **8-step expert template** (Fig 12, verbatim steps): (1) restate NL problem; (2) outline logical structure (iff/implication/quantifier) + pitfalls; (3) analyze math concepts; (4) determine objects + types; (5) headers/imports; (6) anticipate tricky issues (type coercions); (7) **map each concept to formal representation, analyzing correspondence first**; (8) review complete code for consistency. Output is `<think>reasoning</think><formal>`. **Only ~5.8K** reasoning instances (small but high-value). Crucially the prompt forbids solving the problem: "your reasoning must focus entirely on **formalization** … should NOT include any analysis of how to prove the statement."
- **Training (§4.3-4.4).** Base = **DeepSeek-R1-Distill-Qwen-7B / 32B**. Two-stage SFT (stage-1 knowledge, stage-2 reasoning). Then **RLVR with GRPO+DAPO**, reward = `1 if BEq(y, ŷ) else 0` (BEq via Lean4 `exact?` tactic). 7B: 450 RL steps, 45h on 8×A800; reward 0.232→0.347, avg BEq@1 0.258→0.303.

**Three ablations that directly bear on A2's S0/S1 findings:**
- **Reasoning > knowledge (Table 4).** Removing reasoning data: ProverBench BEq@16 collapses 37.9→25.3; removing knowledge: only 37.9→37.4. "informal-to-formal reasoning is the main contributor … formal knowledge serves a complementary role." → For A2: the *reasoning trajectory* (NL-clause → predicate-mapping rationale) matters more than raw (NL,spec) pair volume.
- **Template-guided reasoning > direct distillation (Table 5).** Replacing the templated reasoning with reasoning *directly distilled from Claude4-thinking* dropped ProverBench BEq@1 25.1→21.8. Why: general reasoning models "devote much of their reasoning to **solving** the informal problem rather than **formalizing** it" (Fig 16 off-task example). → For A2: do NOT just dump frontier chain-of-thought as S1 traces; **use an explicit formalization template** that maps clauses to gates without "reasoning about the policy's intent."
- **Knowledge stream uses a verifier filter (the verified-distill seed).** The knowledge data IS verifier-filtered (syntax + BEq equivalence classes + LLM-validity). This is the closest published instance to A2-S1's "frontier compiles → replay-filter → SFT-continue."

**FIT to A2.** Direct template for **S1 (verified distill) + S2 (RLVR)**. The dual-stream split maps to A2's (knowledge = real-domain teacher-compiled specs, replay-filtered) + (reasoning = template-guided NL-clause→gate mapping). The **template-beats-direct-distillation** result is a *pre-registration-grade warning* for our S1 data format.

**ERROR / does it pre-empt us?** It pre-empts the *generic* claim "small distilled formalizer can hit SOTA" — that is now SETTLED for math, by StepFun. It does **NOT** pre-empt A2: (i) **math-only** — no policy/SOP/runtime-enforcement; (ii) the verifier (BEq/Lean) is an *evaluation+reward* artifact, not a *runtime contract that is the shipped product*; (iii) no swappable-generator framing (the model is the product); (iv) no sovereignty motivation. A2's contribution = *transport this proven recipe into the policy-enforcement regime with the verifier as the permanent product.*

**rw-sentence.** *StepFun-Formalizer (AAAI'26) is the decisive precedent that a 7B specialized formalizer — distilled via a verifier-filtered knowledge stream plus a small (~5.8K) template-guided informal→formal reasoning stream, then RLVR'd — can **beat o3-pro, Claude-4, and DeepSeek-R1-671B** on autoformalization, establishing that A2's "small generator ≥ frontier" headline is capacity-plausible, while its math-only scope and model-as-product framing leave the policy-enforcement / verifier-as-contract / sovereignty regime open.*

## 3. Do LLMs Game Formalization? — `2604.19459` (compile ≠ faithful) — FULL READ

**Verified identity.** *Do LLMs Game Formalization? Evaluating Faithfulness in Logical Reasoning.* **Kyuhee Kim, Auguste Poiroux, Antoine Bosselut.** arXiv **`2604.19459v1`, 21 Apr 2026**. Observational study, **not a custom-win paper** (no leaderboard claim) → credible.

**Setup (verbatim/near-verbatim).** **303 first-order-logic problems** (203 from FOLIO + 100 from Multi-LogiEval). Models generate **Lean 4** proofs. A **two-stage pipeline** (formalization stage → proving stage) is contrasted with **unified generation**. Models studied: **GPT-5** and **DeepSeek-R1**. Compilation rates observed = **87–99%**.

**Two failure modes (verbatim).** "GPT-5 **fabricates axioms during proof generation**" (a reactive fallback) vs. "DeepSeek-R1 **mistranslates premises during formalization, producing internally consistent outputs**." Key thesis: "**High compilation rates or accuracies should not be equated with faithful reasoning.**"

**Detection technique — exactly what we adopt for A2.** The unfaithfulness is exposed by the **two-stage pipeline via cross-stage comparison** — comparing the **formalization stage output** against the **proving stage output**. Reactive axiom fabrication is **detectable** this way (the proof stage introduces axioms not present in / not entailed by the formalization stage). Silent premise mistranslation **evades** it (the formalization is internally consistent and the proof is clean — nothing downstream contradicts it; only checking *against the source NL premise* would catch it).

⚠️ **Correction to our prior emphasis.** Our prior summary read this as a strong "gaming is rampant" result. The actual finding is more nuanced and *more useful*: the abstract states there is **"no evidence of systematic gaming in unified generation"** — i.e., models do not pervasively cheat; rather, **specific, characterizable** failure modes appear, one cross-stage-detectable and one not. The paper also notes models "prefer reporting failure over forcing proofs" under prompting designed to encourage proofs — i.e. abstention is a real behavior. So the takeaway for A2 is not "everything is gamed" but "**a behavioral/compile pass is necessary-not-sufficient; add a cross-stage check to catch the detectable class, and accept an irreducible silent-mistranslation residual.**"

**FIT to A2 — this is our faithfulness anchor (risk ②).** Our replay verifier is a **behavioral** check (over/under-deny on gold trajectories). It catches neither failure mode here: a **fabricated gate** that happens to fire correctly on the gold trajectories passes replay (analog of axiom fabrication), and a **mistranslated predicate** that is internally consistent and replays correctly also passes (analog of silent premise mistranslation). The paper's prescription maps cleanly: A2 already produces an **intermediate** (NL clause → predicate prose → satisfier mapping), so we can run **cross-stage consistency**: check each generated gate's NL-gloss against the source policy clause. This catches the *fabrication* class (gates with no policy basis). The *silent-mistranslation* class is documented as the **irreducible residual** → route to abstain on low agreement.

**rw-sentence.** *Kim, Poiroux & Bosselut (2026) prove on 303 FOL→Lean problems that 87–99% compile rates hide two distinct unfaithfulness modes — cross-stage-detectable axiom fabrication (GPT-5) and detection-evading silent premise mistranslation (DeepSeek-R1) — giving A2 both the justification for a cross-stage NL-gloss↔source faithfulness check on top of replay AND the honest acknowledgment that one failure class is irreducible (→ abstain).*

## 4. FormalAlign — `2410.10135` (learned semantic faithfulness scorer) — abstract+results verified

**Verified identity.** *FormalAlign: Automated Alignment Evaluation for Autoformalization.* **Jianqiao Lu, Yingjia Wan, Yinya Huang, Jing Xiong, Zhengying Liu, Zhijiang Guo.** arXiv **`2410.10135v1`, 14 Oct 2024** (ICLR'25). "the first automated framework designed for evaluating the alignment between natural and formal languages."

**Method (verbatim, abstract-level).** "a **dual loss that combines a pair of mutually enhancing autoformalization and alignment tasks**." It learns "representational alignment between input and output," producing an **alignment score** that flags semantic misalignment a compiler-pass misses. The exact loss formula (whether contrastive + cross-entropy) was not extractable from the abstract/HTML; cite at the method-concept level.

**Results (verbatim, now confirmed with the FormalMATH-Basic number too).** "**Alignment-Selection Score 11.58% higher on FormalMATH-Basic (99.21% vs. 88.91%)**" and "**3.19% higher on MiniF2F-Valid (66.39% vs. 64.34%)**." ⚠️ These are *alignment-selection* scores (use the learned scorer to select among candidates), not raw formalization accuracy; the magnitude is modest on the harder MiniF2F (+3.19pp) and large on the easier Basic set (+11.58pp). Table internals (per-model) unverified — cite at this level.

**FIT to A2.** This is the **learned** version of our cross-stage check. A2 already has `t2_a2_roundtrip.py` (re-compile rendered NL → original spec) as a *data-cleaning* gate. FormalAlign's lesson: run an alignment scorer as a **runtime faithfulness gate** on *real* policies where we lack the original spec — re-render the generated GATE_SPEC to NL and score entailment against the source policy clause. For us this can stay **light** (a frontier/LLM-judge entailment check or a small trained scorer), since our schema is closed.

**ERROR.** Does not pre-empt A2 (math autoformalization eval tool). Confirms the field agrees compile/BLEU ≠ aligned, and that a *learned* alignment signal adds measurable selection value. **rw-sentence.** *FormalAlign (ICLR'25) is the precedent that a learned alignment scorer catches semantic misalignment invisible to compiler-pass/BLEU and adds +3.2–11.6pp selection value, motivating A2 to run round-trip NL-gloss entailment as a runtime faithfulness gate, not just a data-cleaning filter.*

## 5. VeriEquivBench — `2510.06296` (ground-truth-free equivalence; the replay ceiling)

**Verified identity.** *VeriEquivBench: An Equivalence Score for Ground-Truth-Free Evaluation of Formally Verifiable Code.* Zeng, Che, Huang, Ye, Xu, Yuan, Fu. arXiv **`2510.06296v3`, 7 Oct 2025 → rev 18 Apr 2026**. (Note: prior summary's title "VeriEquivBench" + author list confirmed; the subtitle is *An Equivalence Score for Ground-Truth-Free Evaluation*, slightly different from the prior doc's gloss.)

**Task + metric (verbatim).** Evaluates "methods that co-generate code and formal specifications in formal languages, like **Dafny**." It "**replaces ground-truth matching with a formally grounded metric, the equivalence score**, and rigorously verifies the quality of generated specifications and code." **2,389** complex algorithmic problems. Sober headline (verbatim): "**generating formally verifiable code remains a profound challenge for state-of-the-art LLMs.**" Per-model numbers not in abstract/HTML.

**FIT to A2 — the conceptual ceiling of replay.** Replay-over-gold-trajectories is a **trace-sampled** approximation of behavioral equivalence; VeriEquivBench's *formally-proven* functional equivalence (in Dafny) is the unattainable-but-aspirational target. The transferable framing: when the GATE_SPEC schema *can* express a clause, you could in principle prove equivalence; when it *can't*, the failure should be **visible** (no equivalent spec reconstructible) → make schema-ceiling a **measured, logged abstention rate** (A2 risk ④), not a silent error. **rw-sentence.** *VeriEquivBench (2389 Dafny problems) establishes ground-truth-free functional-equivalence scoring as the strongest spec-quality metric and reports that verifiable-code generation "remains a profound challenge" for SOTA LLMs — positioning A2's replay-over-trajectories as a pragmatic trace-sampled lower bound and motivating schema-ceiling as a measured abstention rather than silent failure.*

## 7. AgentSpec — `2503.18666` (re-verified) + ProofFlow / Draft-and-Prune

**`2503.18666` — AgentSpec: Customizable Runtime Enforcement for Safe and Reliable LLM Agents.** **Haoyu Wang, Christopher M. Poskitt, Jun Sun.** **v3, 31 Jul 2025** (v1 24 Mar 2025) — resolves. Task: "runtime enforcement of LLM agent safety" — users "define structured rules that incorporate **triggers, predicates, and enforcement mechanisms**." **Both hand-authored AND LLM-generated rules**: "We also automate the generation of rules using LLMs." LLM-generated rules: "**OpenAI o1 achieve a precision of 95.56% and recall of 70.96% for embodied agents**." Domains: code execution, embodied agents, autonomous vehicles. Results: code "prevents unsafe executions in over 90%"; embodied "eliminates all hazardous actions"; AV "100% compliance"; overhead "milliseconds."

⚠️ **Re-verification finding — AgentSpec is closer to A2's RUNTIME than I'd remembered, and partially overlaps the "verifier-as-contract" framing.** AgentSpec's DSL (trigger/predicate/enforcement) **IS** a deterministic runtime contract over an agent, and it **does** generate rules from NL via an LLM (o1) — so the "LLM emits structured enforcement rules, runtime enforces them deterministically" shape is **already published**. **BUT:** (i) the **recall is only 70.96%** for LLM-generated rules (the generator misses ~29% of needed rules) — i.e. frontier-prompt rule-generation is *not solved*, which is precisely the gap A2's trained generator targets; (ii) rules are **safety guardrails** (prevent unsafe actions), not **full procedural SOP compilation** (auth-ordering, satisfier-tool gating, ask/terminal flow) — narrower than GATE_SPEC; (iii) **no distillation, no small/on-prem model, no cross-domain transfer claim** — the LLM is frontier (o1); (iv) the rule *language* is hand-designed and the generator is prompt-only. **FIT/ERROR:** AgentSpec is the **second-closest published system to A2** (after P2P) and **must be cited in related work alongside P2P** — it pre-empts the *abstract* "LLM→deterministic-runtime-rules" idea but leaves A2's (trained-small-generator, recall-improvement-via-distillation, full-SOP-procedural-schema, cross-domain transfer, sovereignty) open. The 70.96% recall is a useful external datapoint that **frontier prompt-only rule generation leaves accuracy on the table** — supporting the value of a trained generator. **rw-sentence.** *AgentSpec (Wang, Poskitt & Sun, 2025) already pairs an LLM rule-generator with a deterministic trigger/predicate/enforcement runtime, but its o1-generated rules hit only 70.96% recall, target safety guardrails rather than full procedural SOP compilation, and use no distillation/transfer/sovereignty — so it pre-empts the generic "LLM→runtime-rules" idea while validating that frontier prompt-only generation under-recalls (the exact gap A2's trained generator addresses).*

**`2510.15981` — ProofFlow.** *A Dependency Graph Approach to Faithful Proof Autoformalization.* **Cabral, Do, Yu, Tai, Feng, Shen.** **v1, 13 Oct 2025** — resolves. Method (verbatim): "constructs a **directed acyclic graph (DAG)** to map the logical dependencies between proof steps … a novel **lemma-based approach** to systematically formalize each step as an intermediate lemma." ### (b) Exact faithfulness-check technique to adopt + source.
**Adopt cross-stage NL-gloss↔source consistency, from `2604.19459` (Do LLMs Game Formalization?), layered with a round-trip alignment gate from `2410.10135` (FormalAlign).** Concrete A2 implementation:
1. **Cross-stage (catches fabrication):** A2's pipeline already emits an intermediate (gate → predicate prose → satisfier mapping). For each generated gate, take the model's NL-gloss of that gate and check it is *entailed by* a source-policy clause (LLM-judge entailment or small trained scorer). A gate with no supporting clause = fabricated → reject/abstain. This catches the class that **replay cannot** (a fabricated gate that fires correctly on gold trajectories still passes replay).
2. **Round-trip (FormalAlign lesson):** promote the existing `t2_a2_roundtrip.py` from a *data-cleaning* gate to a *runtime faithfulness gate* on real policies lacking a gold spec — re-render generated GATE_SPEC → NL, score entailment against source policy.
3. **Honest residual:** the **silent-mistranslation** class (`2604.19459`, internally-consistent wrong predicate) **evades both** → document as irreducible, route to **abstain on low round-trip/entailment agreement**.
This is **orthogonal to and additive on top of** replay (level-2 behavioral); it lifts A2 to a level-3 (cross-stage) + level-4 (learned-alignment) faithfulness stack. VeriEquivBench (`2510.06296`) is the level-5 ceiling (proof-of-equivalence) we cite but do not implement.
