   현 deny 는 문구는 옳으나 재생성이 도구 0으로 접혔다. 격리 프로브로 ⑴현행 deny ⑵deny + 대화 텍스트에 실재하는 접미사-후보 나열(레지스트리 ∩ 이미 받은 텍스트 — 새 정보 0) ⑶무개입(env 까지 통과) 3셀을 재라. ⑶이 이기면 우리 pre-exec deny 자체가 이 부류에서 손해라는 뜻이다.
   ⛔현 시점에서 수리 금지 — §4ⓓ 는 PLAUSIBLE 이고 [[57]] 부정통제가 없다.

5. **[잉여 write] "손님 요청 1건에 같은 종류의 write 를 N회" 를 표면화하는 도메인-일반 술어 검토.**
   trial 1 은 한 요청에 체킹 계좌를 3개 열었다(t7328 도 동형: 18/23 blocked + 1 wrongarg). 술어는 닫혀 있다 — **직전 손님 발화 이후 같은 도구·같은 `account_type` 으로 성공한 write 가 이미 있는데 또 쓴다**. 도메인 어휘 0·태스크 id 0([[05]]·[[70]] 조건은 도메인 일반 닫힌 술어).
   ⚠이것은 [[62]] 경계선이다 — 먼저 **격리로 결손을 재라**: 같은 문맥에서 *"이미 연 계좌가 있다"* 만 알려주면 모델이 스스로 멈추는가.

6. **[측정 대상 밖 · 기록만] `get_checking_atm_fee_totals` 반환문의 완결-인상 문구.**
   *"These totals already cover every personal checking class's documented Rho-Bank ATM fees"* 가 t7335→t7336 사이에 바뀌지 않았다(P5 는 `get_atm_fee_discrepancies` 만 손봤다). 057 의 결정 기준은 ATM 이 아니었으므로 **이번 실패와 무관**하나, P5 와 같은 계열의 잔존 문면이라 기록해 둔다.
