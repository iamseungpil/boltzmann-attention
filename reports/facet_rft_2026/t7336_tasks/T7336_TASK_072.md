> [18] `get_current_time{}` → [19] `The current time is 2025-11-14 03:40:00 EST.`

엔진 로그가 [18] 직전의 실제 사건을 기록한다:
```
[T2_PHASE_PRECEDE] substitute (was: silent) target=call_discoverable_agent_tool → rw_fb(pure-advice)
[T2_LEVER] T2_WRITE_EVIDENCE sim=task_072#s626729
[T2_WRITE_ARG_GROUND] deny tool=log_verification inner=
[T2_MATERIAL_GATE] stop=other_lever(wev) turn=18
```
⇒ 모델의 turn 18 원본은 `log_verification` 이었고, 시계가 아직 없어 우리 `write_arg_grounding`(`applies_to: log_verification`·`grounded_args: [time_verified]`)이 **정당하게** 거부했다. 재생성 결과가 `get_current_time` 이다. **여기까지는 우리 층이 옳다.**

**결정 지점 ★ — [20] 이후: 시계를 손에 쥐고도 `log_verification` 을 다시 내지 않고 손님에게 되묻는다.**
> [20] assistant: `"I apologize for the confusion. Let's proceed with verifying your identity again … Could you please confirm your full name, user ID, address, email, phone number, and date of birth?"`
> [21] user: 전부 재확인
> [22] assistant: **같은 문구·같은 필드 순서로 재요구**
> [24] `"It looks like there was an issue with verifying your identity. Let's go through the verification process again …"`
> [25] user: `"Can you tell me what specifically is failing on your end (e.g., user ID mismatch vs. contact info mismatch)?"`
> [26] `verify_identity{…}` → [27] 다시 `VERIFIED — 4 identity values match …`
> [28][30][32] **또 같은 재요구 3회** → [29] user: `"I'm getting concerned because we've repeated this several times."` / [31] `"we're going in circles"` → 종료 `too_many_errors`

**이 문구의 출처는 우리 층이다.** `gate_interpreter.py::render_recovery` 가 auth 게이트 거부문을 만들 때 satisfier 의 인자 목록을 그대로 "손님에게 물어라"로 렌더한다:
```python
asks = " OR ".join(", ".join(v) for v in gate["satisfiers"].values())
steps += [f"(2) ask the user for: {asks}", ...]
```
GB1 의 satisfiers(`a2/banking_knowledge.gate.json` `GB1_VERIFY_BEFORE_ACCOUNT_ACCESS`)는
`log_verification: [name, user_id, address, email, phone_number, date_of_birth, time_verified]`
⇒ 실제 발화문 = **`(2) ask the user for: name, user_id, address, email, phone_number, date_of_birth, time_verified`**

모델의 [12]/[20]/[22]/[24]/[28]/[30]/[32] 재요구는 **이 목록의 순서를 그대로**(name → user_id → address → email → phone → dob, `time_verified` 만 탈락) 복창한다. 우연 일치가 아니다. 그리고 같은 게이트의 `note` 는 정반대를 말한다 — *"confirm 2 of {date of birth, email, phone number, address} **against the record** (use the get_user_information_by_\* read tools), then call log_verification with the verified values **and get_current_time()**"*. 한 메시지 안에서 **"레코드와 대조하라"와 "손님에게 물어라"가 충돌**하고, 모델은 뒤에 오는 명령형 Recovery 목록을 집었다([[64]]·[[55]] 문구-모순 계열).

손해는 이중이다: (a) `user_id` 는 손님이 가질 수 없는 값이고 손님이 [13] 에서 이미 없다고 말했다 — **이행 불가능한 요구**. (b) `time_verified` 는 `get_current_time` 산출물인데 "손님에게 물어라" 목록에 들어 있다 — 같은 파일의 `write_arg_grounding` 이 *"do not ask the customer for the time"* 이라고 명시적으로 금지한 그 행위다.

루프가 자기를 재생산한 기전: GB1 미충족 → 계좌 접근 deny → 같은 Recovery 재발화 → 재요구 → 손님 재확인 → GB1 여전히 미충족(satisfier 인 `log_verification` 은 끝내 호출 안 됨) → 반복. `T2_PHASE_PRECEDE` 는 20회 중 19회를 `suppressed (same fingerprint)` 로 접었지만 **접힘은 원인을 지우지 못했다**(C413/C414 동형).

## 7. 우리-층 결손 (코드 경로 지목 · 수리 실행 없음)

**① `gate_interpreter.py::render_recovery` — auth 게이트 Recovery 가 "레코드에서 읽을 값"을 손님에게 물으라고 지시** *[CONFIRMED]*
`asks = " OR ".join(", ".join(v) for v in gate["satisfiers"].values())` → `(2) ask the user for: …`. satisfier 인자 중 어떤 것이 **손님-제공**이고 어떤 것이 **레코드-파생**(`user_id`)·**도구-파생**(`time_verified`)인지 구분하지 않는다. `arg_source_reads`(같은 A2 파일)가 이미 `user_id → get_user_information_by_name/by_email` 를 선언하고 있으므로 **판정에 필요한 사실은 이미 우리 손에 있다**.
처방 후보: (a) `asks` 에서 `arg_source_reads` 에 원천-read 가 선언된 인자를 빼고 그 인자는 "(2') read it with `<producer>`" 로 분리, (b) 이미 원장에 있는 선행(예: `verify_identity` 통과)을 문면에 반영해 *"identity is already verified — the only missing step is `log_verification(...)`"* 로 **잔여만** 말하기([[64]] fix-naming).

**② `a2/banking_knowledge.gate.json` — `get_atm_fee_discrepancies.requires_reads` 가 계좌목록 read 를 빠뜨림** *[CONFIRMED]*
현재 `["get_bank_account_transactions"]` 뿐. **형제 선언인 `get_interest_correction.requires_reads` 는 `["get_all_user_accounts_by_user_id", "get_bank_account_transactions"]` 로 둘 다 적고 있다**(같은 파일 `relations` 블록). `apply_checking_account_credit.requires_reads` 도 같은 결손(`["get_bank_account_transactions"]`). 그래서 P3 거부문이 *"the checking account's id copied from **the accounts listing**"* 이라는 **이름 없는 산문**으로 나갔다.
처방 후보: 두 선언에 `get_all_user_accounts_by_user_id` 추가 — 그러면 기존 `{missing}` 치환이 이름을 자동으로 싣는다(레버 신설 0). 출처는 gold 아닌 KB/env 축자로 확인할 것([[23]]).

**③ `t2_gate_patch.py` PROV 경로가 `arg_source_reads` 를 안 본다 — P4 死배선** *[CONFIRMED]*
- `_fab_fix_note`(`t2_gate_patch.py:1834`)가 `arg_source_reads` 의 **유일 소비자**이고, 호출처는 `T2_FAB_STRIP` 블록(`t2_gate_patch.py:9961`) 하나뿐. FAB_STRIP 은 이 런 **전체 0회**.
- PROV regen(`t2_gate_patch.py:9298~9377`)은 `_resolver_directive`(`:1714`)를 쓰는데, 이는 `a2["default_specs"] + a2["regen_resolver_specs"]` 를 읽는다. **banking 은 둘 다 0건** → 항상 `None` → 폴백이 `REGEN_FEEDBACK`(`:1067`).
- 그래서 8회 전부 나간 문면: *"call a lookup/getter tool that produces this value (e.g. a getter to retrieve the user's records, payment methods, or addresses)"* — **생산자 이름 0**, 게다가 예시 3종이 모델이 이미 소진한 `get_user_information_by_*` 쪽을 가리켜 `[DUPLICATE-READ]` 6연발을 유도했다([[42]] priming 계열).
처방 후보: `_resolver_directive` 실패 시 `arg_source_reads` 를 2차 폴백으로 조회(선언 재사용·신규 저작 0).

**④ `t2_gate_patch.py:9355` `_tok_overlap`(정의 `:127`)이 정답 도구를 목록에서 배제** *[CONFIRMED]*
`T2_OWNERSHIP_FIX` 가 `navigate_to_account_details` 에 대해 surface 한 10개 목록에 `get_all_user_accounts_by_user_id_3847` 이 없다. 재현 확인:

## 8. 처방 우선순위

1. **[P-A · A2 선언 1회 저작]** ②: `get_atm_fee_discrepancies` / `apply_checking_account_credit` 의 `requires_reads` 에 `get_all_user_accounts_by_user_id` 추가. 기존 `{missing}` 치환이 이름을 싣는다. **레버 신설 0**. — 이 태스크의 두 MISSING 을 직접 겨눔.
2. **[P-B · 엔진 폴백 1줄 계열]** ③: PROV 폴백 순서를 `_resolver_directive → arg_source_reads → REGEN_FEEDBACK` 로. 8회 무명 거부가 8회 유명 거부가 된다. ④/⑤ 도 부분 흡수.
3. **[P-C · 문면 분리]** ①: `render_recovery` 의 `(2) ask the user for` 에서 원천-read 가 선언된 인자를 분리. **부작용 계측 필수** — auth 게이트는 전 태스크 공유 상류 노드라 폭발 반경이 크다([[66]]·[[70]]: 태스크별 부호표 동반).
4. **[P-D]** ⑤ dispatcher 내포 인자 PROV 전개.
5. **[측정]** 이번 런에서 `FAB_STRIP` · `T2_ARG_PRODUCERS` 가 **런 전체 0회**다. P4/F8 은 배선 생존부터 재검할 것([[67]] `t2_liveness` 0단계).

> ⚠ 위 처방은 전부 **제안**이다. gold(`reward_info`)는 진단 목적으로만 읽었고 A2 내용 저작 근거로 쓰지 않았다([[23]]). ②를 실제로 넣을 때는 KB/env 축자 출처를 `_note_` 에 지참할 것.
