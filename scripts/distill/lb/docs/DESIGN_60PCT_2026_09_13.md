## 1. 레버 센서스 — 무엇이 동작하고 무엇이 아닌가 (2026-09-13 · `lb_lever_census.py`)

**방법.** 리모트 `x768/out_lb` 의 결과 gz 427건 + 사이드카 `fb_*.jsonl.gz` 408건(모든 팔, `infra_void`·`run1`·`partial`·`x818cloud`·smoke/probe 제외) → **1,642 sim / 63 팔**, 사이드카 행이 붙은 sim 1,218. 레버 = 사이드카 `kind`(`advice/deny/block/tool/inject/fold/regen`) × `source`. 판정은 세 층:
1. **팔 수준**: 같은 태스크 4-sim 셀에서 ours − base.
2. **레버 수준(공정한 것)**: **같은 팔·같은 태스크 안**에서 레버가 운 sim 과 조용한 sim 의 승률 차(`dpp`)와, 그런 셀에서 운 쪽이 나은/못한 셀 수(`bet/wor`) → 부호검정(양측).
3. **태스크 수준**: 모든 팔 합산 ours(n≥8) vs base 4 sim, Fisher 한쪽꼬리, |Δ|≥25pp.
pooled(운 sim 전체 vs 조용한 sim 전체) 승률은 **선택 효과**가 섞여 참고만 한다(regen·fold 는 어려운 sim 에서 더 운다).
⚠ 다중비교: 53 레버에서 p<.05 를 기대 2~3개 우연으로 얻는다(메모리 85). 유의 0 은 그 기대보다도 적다.
⚠ 상존 레버(도구 주입 `tools` 1,128 sim · `ask` 1,118 · `verify_identity` 666)는 짝이 거의 없어 **이 방법으로는 검정 불가** — 팔 A/B(nc17 `inject_after`, nc9/15 선택 주입)만이 근거다.

## 5. 설계

### 5.1 M-A′ — A3 인자 규칙은 **재료를 돌려주고 값은 돌려주지 않는다**

v1 의 `fact: "… the amount is {want}"` 는 호출을 막고 **정답을 돌려준다** — 모델 입장에서 인자에 값을 써 주는 것과 같다. 이것은 구 스택 `T2_RESOLVE`(`flags_inventory`: **HARMFUL** · `LEVER_ROSTER:110,429`) 의 재현이고 `specific.json` 축자가 금지선을 적어 두었다: *"The policy tables themselves stay legal as DELIVERED TEXT … what is forbidden is the engine writing the value into the call."* 그래서:

- `source` 네 종류는 유지하되 **`fact` 에 `{want}` 가 없다.**
  - `computed` → `fact` = 정책 표의 해당 행 **축자** + 엔진이 본 입력(`discovery_date={got}`, `today={t}`, `card_type={c}`). 판단은 모델.
  - `enum` → 문서에 있는 이름 목록(재료). 유효-오선택은 못 고친다고 적는다.
  - `grounded` → 「손님 말·조회 결과 어디에도 `{got}` 이 없다」 사실만(기존 `_match_verdict_grounded`·`FREE-TEXT-DEFAULT` 와 같은 검사).
  - `default` → 기존 `FREE-TEXT-DEFAULT`.
- **계산은 기존 op 를 참조한다**: `"compute": "tool:get_debit_dispute_liability_cap"` / `"tool:check_credit_dispute_provisional_credit"` / `"tool:get_interest_correction"`. 새 Python 함수(`liability_schedule` 등) **금지**(메모리 91 — 코드에 도메인 없음).
- 자리: **LB3 의 kind**(`grounding` 옆). 새 파일 없음. 엔진 ≤ 40줄. 경로는 nc26 `_lb_blocked`(in-place, 형제 실행, regen 없음).
- **사전검증은 gold 전사가 아니라 격리다**(메모리 62·76): 238 실패 sim 의 실제 호출에 **재료를 붙인 프롬프트**를 격리 서브에 주고 모델이 값을 맞히는지 잰다. 100% 라야 배선. 못 맞히는 규칙은 **결손으로 기록·보류**(메모리 92). 그와 별도로 `computed` 가 gold 와 안 맞는 **잔여 칸을 보고서에 적는다**(§4 표의 도달 불가 칸이 그대로 나올 것) — 임계를 만져 맞추지 않는다.
- 우선순위(재료형이 닿는 것만): ① `default` reason 잔여 7 태스크 + 083 liability 생략(55) ② `enum` account_class(비정규 36) ③ `grounded` discovery_date/pin/amount(46) ④ LB2 `get_debit_dispute_liability_cap` 수리(clamp + KB 축자 임계) → 잔여 칸 보고 ⑤ LB2 `get_interest_correction` 기권 수리(§2). `computed` 재료행은 없다. provisional 은 결손.

### 5.2 M-B — LB1 절차 3 + deny 대상 정리
1. 도난 카드 `freeze ×N → 조회 → unfreeze → close_debit(reason=stolen)` (078 079 081 087) 2. 리워드 정정은 손님 `submit_cash_back_dispute` 뒤 심사에서만 (026 027 029) 3. 한도 증액이 분쟁·교체보다 먼저 (051 054). 전부 정책 문서 **축자 인용 + 문서 id** 를 A2 에 박는다(`freeze_debit_card` 는 A2 specific 9곳, tenure 14일은 1곳).
