# `mn_` 팔 판정 — 세 뺄셈은 산 것이 없고 운 자리에서만 잃었다 (2026-09-11)

> `mn_` = `ub_`(a11ebd48) **− 명령 3개**(acquire 조언 · 폐쇄 `enforce` · `open_request`).
> 근거: `out_lb/{ub,mn,cb}_task_*.results.json.gz` + 같은 이름의 `fb_*.jsonl.gz`, base 정본과 짝.

## 표 — 점수와, 뺀 것이 **실제로 어디서 울었는가**

```
task  base   cb_    ub_    mn_    mn−ub   ub 에서 운 것 → mn 에서
007   4/4    2/4    3/4    4/4     +1     셋 다 0
016   4/4    2/4    1/4    3/4     +2     셋 다 0
036   2/4    0/4    1/4    0/4     −1     acquire 2→0 · open_request 1→0
043   4/4    4/4    4/4    4/4      0     폐쇄 deny 4→4(안 빠졌다) · open_request 4→0
049   3/4    0/4    2/4    0/4     −2     폐쇄 deny 11→6 · open_request 5→0
048   3/4    1/4    0/4     ?       ?     폐쇄 deny 16→0 · open_request 5→0   (진행 중)
                        순효과 +0 sim / 5 태스크
```

## 이 표가 말하는 것

**1. `+3` 은 뺄셈이 번 것이 아니다.** 007 과 016 에서 **세 뺄셈 중 어느 것도 `ub_` 에서 울지 않았다**
(`[VALUE-ACQUIRE]`·`[PROCEDURE]`·`[LEDGER]` 전부 0). 두 트리는 그 태스크에서 **우리 층이 한 일이 같다.**
그런데 점수는 +1 과 +2 로 움직였다. ⇒ 이 둘은 **잡음**이다.

> 부수적으로 이것이 **잡음의 실측**이다. 우리 층이 동일하게 행동한 두 태스크가 nt=4 에서 각각
> +1·+2 로 움직였다 — 추정치 18.8% 가 아니라 **현물**이다. 한 태스크의 ±2 는 근거가 못 된다.

**2. 잃은 둘은 뺀 것이 운 자리다.** 036(−1)은 acquire 조언이 빠진 자리, 049(−2)는 폐쇄 거부가
11→6 으로 준 자리다. 즉 **뺄셈이 닿은 곳에서만 내려갔다.**

**3. `open_request` 제거는 효과가 안 보인다.** 043 에서 4→0 으로 완전히 뺐는데 점수는 4/4 그대로다.
048·049 에서는 폐쇄 변경과 겹쳐 분리되지 않는다. ⇒ **폐기 우세라던 판단의 근거는 아직 없다.**

**4. ARM 커밋의 두 진술이 재현되지 않았다.**
- *"acquire 조언을 빼면 036 이 0/4 → 2/4, 즉 base"* → 팔 전체에서는 **0/4**.
- *"`open_request` 가 task_016 에서 두 번 울었다"* → `ub_` 의 016 사이드카에서는 **0회**.
  (그 수는 다른 팔·다른 런에서 온 것으로 보인다. 격리 프로브의 수를 팔 전체에 옮겨 적은 셈이다.)

## 036 은 왜 안 고쳐졌나 — 조언이 원인이 아니었다

```
give_discoverable_user_tool 을 부른 sim  →  16 sim 중 13 실패 / 0 통과
안 부른 sim                              →   3 sim 전부 통과
(base·cb·ub·mn 네 팔 전부에서 같은 분리)
```
`mn_` 은 우리 문장에서 그 도구를 **완전히 지웠는데도 네 sim 전부 넘겼다.** 조언은 원인이 아니다.
base 의 이기는 궤적은 `unlock_discoverable_agent_tool → call_discoverable_agent_tool`(에이전트가 직접),
지는 궤적은 거기에 `give_discoverable_user_tool → call_discoverable_user_tool`(손님에게 넘김)이 붙는다.

⚠ 일반 규칙으로 만들면 **틀린다**: 이 도구는 base 97 중 **22 태스크**에서 쓰이고 그중 **21개는 네 sim
전부** 쓴다 — 정상 경로다. 태스크 안에서 갈리는 것은 **036 하나**뿐이다(give 0/2 : nogive 2/2).
⇒ 고칠 거리는 *"손님에게 넘기지 마라"* 가 아니라 **누가 그 값을 가져오는 쪽인가**라는 사실이다.

## 판정

**`mn_` 은 답이 아니다.** 세 뺄셈은 귀속 가능한 이득을 하나도 만들지 못했고(007·016 의 +3 은 잡음),
뺀 것이 운 자리에서 −3 을 잃었다. 048 이 남았지만 그것 하나로 뒤집히지 않는다.
⇒ **세 뺄셈은 되돌린다.** 팔은 `lb-v5`(e1c9b33e) 자체, 즉 뺄셈 없는 전체 스택으로 간다.
